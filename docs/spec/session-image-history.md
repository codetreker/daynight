# Session 图片显示与归档规格

本文定义图片显示、预览、历史与归档要求。共享浏览器显示与预览消费已保存资源；来源采集、输入和归档的完整链路是否可用须按各自验收结果判断。[输入与草稿规格](session-image-input.md)拥有 R1–R3/R7，[验收规格](session-image-acceptance.md)拥有容量与全部验收追溯。本页拥有 R4–R6/R8；显示内容必须是可授权读取的真实图片，不能只显示路径、文件名或 JSON 占位。

## 入口与权限

| 入口 | 图片显示与操作边界 |
| --- | --- |
| Task 详情弹窗与独立 Task 页 | 当前 Session、历史及全屏图片采用相同身份与显示语义；仅当前可操作 Session 允许图片输入。 |
| Test Session | 当前 Session、可读取归档及全屏支持图片；新 Session 的显式原生恢复与原记录读取分别核验权限。 |
| Bot Session | 当前实际选中 Session 及已有历史支持图片；快速切换、隐藏、冷恢复、删除和父凭据撤销不得串用图片。 |
| 各 live 入口的 Session 全屏、Task 全屏及两层组合 | 保持同一客户端、草稿、预览与读取范围，进入全屏不额外上传或发送。 |
| Task Session 历史选择器、附件中的原生记录 | 只读展示和原件下载；无 Composer、上传、命令和来源重新采集，不依赖 live snapshot 或原 Controller。 |

所有入口沿所属 Session 或记录的当前权限读取。图片资源标识、内容摘要、缓存命中或已知下载地址不授予权限。Herdr 终端与录像、Thread、普通任务附件管理、通用文件上传及任意文件浏览保持原有边界，不因共享显示组件获得图片来源读取权限。

## 图片显示

### R4 用户、Agent 与工具的原生图片

- 已发送的用户图片在对应消息中可见；Agent 原生返回的图片和工具结果中的图片在各自的内容位置可见。保持文本、图片及工具所属关系，不把图片结果仅串行化为 JSON 文本。
- 实时内容、原生历史恢复、分页历史和已归档内容采用一致的图片身份与显示语义。能取得的原生图片应显示实际内容；原生端仅提供失效定位符或没有图片字节时，展示明确不可用状态。
- 工具详情折叠和现有时间线显示模式保持原有筛选规则。被模式隐藏的工具不强制展示，但其内容被展开或显示后必须能够正确呈现图片。
- 展示至少保留现有 PNG、JPEG、GIF、WebP、AVIF 支持。SVG、HTML 和其他可执行文档不作为图片执行；不支持的格式有明确结果。输入格式与展示格式分别定义，不能因输入只支持三种格式而删除现有图片显示能力。

### R5 Markdown 本地与外部图片

- 支持实际 Markdown 图片节点，包括行内图片和引用式图片。代码块、行内代码和普通文本中的类似路径不能触发图片读取。
- 本地图片支持相对路径、绝对路径、`file://` 路径和已登记的会话资源引用。相对路径按该消息的来源上下文解析；没有单独文档上下文时按该 Session 的工作目录解析。
- 本地读取限定在会话已有权限允许的文件范围，跟随符号链接后仍须满足范围要求。不存在、越界、权限不足或不可读取的文件产生对应失败结果，不拼成网站根路径，也不要求用户手工上传才能显示 Agent 引用的合法本地图片。
- 外部 HTTP(S) 图片直接支持图片显示和预览。读取不能携带 Daynight 认证信息或用户其他站点的登录凭据；网址跳转仍需符合相同访问规则。失败、格式不支持或源站限制应可见并可重试。
- 外部网址读取不获得任意本机、局域网或云元数据服务访问权限；原生会话内本地图片仍通过前述本地范围读取。需要登录的图源不新增登录或凭据转发流程，无法读取时明确显示不可用。
- 图片加载成功后记录当前消息所对应的实际内容，不因同一路径或 URL 后来指向其他字节而悄悄改写已保存的历史图片。重新取得内容的操作须明确区分于读取已有历史。
- 可点击图片的 Markdown 链接保持其链接语义，不产生嵌套按钮或链接。图片预览与原链接均有可访问入口。

### R6 加载、预览与下载

- 读取或解码中的图片显示加载状态；取得尺寸后预留对应空间。解码失败与读取失败均显示可理解的错误，提供适用的重试操作。
- 图片显示后可在当前页面放大预览，支持适应窗口、原始比例和大图滚动查看；提供图片下载。发送前缩略图、消息图片、Markdown 图片和工具图片使用一致的预览交互。
- 预览通过关闭按钮或 Escape 关闭，焦点回到仍存在的触发位置。Escape 先关闭图片预览，不能同时关闭任务弹窗或 Session 全屏。预览期间的滚动不滚动背景时间线。
- 加载状态更新、流式文字更新、后台权限复核不能重复挂载已显示图片或反复下载同一内容；保留阅读位置、已展开工具、焦点与当前预览。用户在阅读较早消息时，图片加载不能强制滚到底部。
- 桌面与至少 390px 窄屏均可添加、预览、移除、重试和发送；长图片名、多图和大图不产生页面级横向溢出。图标具备文字可访问名称，状态变化能被辅助技术读取，遵守减少动态效果设置。

## 历史与权限

### R8 历史与归档

- 对已成功采集并关联消息的图片，刷新、重连、加载更早记录、原生 Session 恢复和归档后回看均可读取原有图片；已归档图片不依赖原 Controller 在线，也不依赖原本地路径或外部网站仍可访问。
- 没有成功采集的历史图片应保留所属消息及可解释的不可用状态。归档明确记录缺失或失败，不把空白或占位误报为完整图片归档。
- 已存在的文本历史和旧归档保持可读；旧记录确实没有保存图片字节时，不制造图片已存在的假象。
- 历史图片的数据读取、缓存使用与下载执行与所属 Session 或记录相同的权限。账户变化、项目访问撤销、Session/记录删除后，不继续使用旧授权取图或展示仍由页面持有的敏感预览。
- Controller 当前正文、Markdown、原生图片关联与传输事实必须原子可见，分页、完整历史和归档读取同一权威；迟到结果不能覆盖较新的正文或原图位置。同步和归档在网络等待前冻结完整正文、资源引用与来源截止点，不跨网络保留 SQL 快照，也不继续使用已关闭的 SQL 连接。
- 上传、暂存、未发送草稿、已发送内容和归档分别具有明确保留与清理条件。保留要求跟随所属会话与记录；不得为实现临时上传而删除仍被消息或归档引用的图片。

## 图片出现与原内容

同一图片在不同消息或位置出现时，各自保留出现身份与所属关系；不同资源即使摘要相同，也不能据此合并消息、接受回执或访问权限。历史分页、重复原生事件和普通权限复核保持原出现与原件身份，不产生重复图片或重新读取来源。

Markdown 正文、reasoning 及工具中明确的 Markdown 片段都按真实图片节点处理，保留原消息、片段和工具 callId。普通工具日志、原始 JSON、HTML、代码和类似路径文本不因此触发来源读取；来源上下文只能决定解析基点，不能扩展允许的文件范围。

已采集图片不随正文修订、part/entry 撤回或工具折叠消失。旧出现保留在原所属位置的只读历史图片容器中，不重复当前图片；迟到的成功采集仍归原出现。切换显示模式或离开视口不改变采集和保存事实，也不强制展示本应隐藏的工具或 reasoning。

已保存原件必须保持不可变。预览与下载均使用同一原件及完整性事实；读取失败后的重试只重读该原件，解码重试不意味着重新访问来源。已验证且仍有权限的原件，即使当前浏览器解码失败，仍可提供适用下载；未完成字节完整性校验的内容不得显示或下载。

## 来源失败与重试

从未成功保存的合法本地或 HTTP(S) 来源，只有确定前次采集失败、旧 staging 已清理且当前用户仍有操作权限时，才提供重新准备来源的入口。该操作只针对已登记的原出现，不接受任意新路径、URL、认证头或用户身份。权限拒绝不能靠重试绕过。

正在采集或结果 unknown 时仅查询原采集操作，不能另建身份或抓取第二份内容。已 committed 的图片只能读取保存原件；若用户确需取得变化后的源内容，必须明确成为新的出现或记录，不能悄悄替换历史。只读归档永远不提供来源重试。错误类型不能单独决定重试资格，应按权威返回的适用动作呈现。

外部源读取不得借用浏览器登录、Daynight token、环境代理凭据或跨站 Cookie；每次跳转仍须满足地址和访问规则。网络环境不能保证阻断内网、loopback、云元数据等目标时，不得开放外部采集。合法本地图片继续按原生会话的允许文件范围处理，不以外部网络限制替代本地授权规则。

## 阅读、预览与可访问性

所有图片入口使用一致的适应窗口、原始比例、大图滚动、关闭和下载行为；适应窗口不无故放大小图，原始比例下可滚动到四边。带链接的 Markdown 图片保留原导航与并列的预览、下载入口，不产生嵌套链接或按钮。

图片预览模态与 Task 弹窗、Task 全屏、Session 全屏及认证/删除确认正确分层。一次 Escape 只关闭最内层；预览期间背景时间线停止滚动和自动跟随。用户主动关闭时才恢复仍有效的同范围触发点；触发点消失使用适当后备位置，隐藏或撤权不抢回焦点。上层认证或删除确认出现时先挂起图片模态；权威撤权销毁敏感预览。

稳定布局下媒体阅读锚点偏差不得超过 2 CSS px；既有文字 prepend 的 1 CSS px 要求不放宽。流式更新、无变化权限复核及资源状态变化不应重建已显示图片、反复下载或夺走阅读位置、工具展开状态和焦点。

添加、移除、重试、预览关闭和发送等主要图片操作触控目标至少 44 CSS px。桌面与 390px 窄屏均须保留可达操作、完整名称、可访问名称、可见焦点和状态公告；软键盘、visualViewport、旋转及浏览器缩放不能使退出或发送入口不可达。状态公告应避免高频噪声，尊重 reduced-motion。已有 Bot 对 320px 等更窄容器的要求仍有效。

## 归档真实性与清理

完整归档包含全部已保存原件与其消息、工具、Markdown、reasoning、旧版本及撤回容器的关联。`complete` 不能含未采集图片；`partial` 仅表示确定从未采集的缺图，并逐项保留原因。已知 available 原件丢失、摘要损坏、正文缺口或提交 unknown 均不得改为 partial 凑成成功；已发布归档损坏应报告读取失败，不能改写原封存内容或重新取源伪造历史。

归档封存需要原生停止、完整历史同步、来源结算及实际写入停止证据；停止超时不等于写入已终止，不等于提交未发生。图片归档不能因当前视口、分页截短或隐藏工具遗漏正文与引用。服务仍可访问时，原 Controller 离线、源文件删除和网站变化后，已采集图片继续读到原字节；此保证不等于浏览器断网后的离线图库。

同 Session 原生恢复保留原资源归属。显式恢复到新 Test Session 时，必须同时验证源读取、目标写入及可信同 owner/provider/native 来源关系，按目标完整预算导入独立资源；仅 native ID 相同不够。导入不能复用旧上传资格、生成原生输入或偷偷部分成功；已确认保存项复制失败不能冒充从未采集。成功后删除源记录不删除目标副本；无可信映射则明确 `context_unavailable`。

删除 Session、记录或 Bot 后不得继续使用旧授权、缓存、排队下载或页面持有的敏感预览。清理先阻止新读写，再确认在途写入和读取实际结束，最终清理后才报告完成；租约到期不能代替物理停止。删除一个引用不能损坏仍被其他有效消息、记录或原生恢复引用的原件，失败清理保持真实失败和可恢复状态。已交给用户的下载文件不承诺召回。

备份恢复必须覆盖消息账本、完整历史、归档文件及原件的关联整体；缺少原件时显示损坏，不通过重抓 URL 补成历史。回滚可以停止新图片写入，但须保留已有图片读取、原操作查询及 unknown 恢复能力，不能用仅支持旧文本归档的版本覆盖存量图片记录。
