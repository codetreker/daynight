# Task 调度优先级

## 状态与归属

本文是**待实现的功能提案**，不是当前服务能力说明。四级字段、协议、
Worker 选择规则与 UI 必须作为可协作的版本组合交付后才能宣称生效。
[设计](../design/task-priority.md)拥有数据结构、协议、并发机制及实施切片；
[决策记录](../../.agents/notes/proposed/feature/2026-11-18-task-scheduling-priority.md)
保存替代方案与范围代价。现行行为仍由
[Worker 规格](daynight-worker.md)及其相关合同拥有。

## 目标与非目标

让普通 Task 的业务重要程度影响 Worker **后续领取**，覆盖 Standalone、
Task Chain 成员和 Goal 子任务，不改变执行资格与已领取工作的责任。
Task Chain 是依赖组织，不是可领取资源。Goal 不参与调度。

首期不提供 Goal/Chain 整体等级、继承、自动提升前置、抢占、自动老化或全局
原子调度。紧急的验收任务仍须等待实现任务完成；提高等级不会让其前置自动
提高等级。连续更高等级流量可使较低等级无限等待；不得宣传最大排队时间或
无饥饿保证。创建年龄不是进入可执行队列后的等待时长。

## 产品合同

### 等级与写入

| API 值 | 中文 | 英文 | 比较顺序 |
| --- | --- | --- | --- |
| `urgent` | 紧急 | Urgent | 最高 |
| `high` | 高 | High | 次高 |
| `normal` | 普通 | Normal | 默认 |
| `low` | 低 | Low | 最低 |

1. 普通 Task 创建省略 `priority` 时为 `normal`；历史普通 Task 为 `normal`。
   修改省略该字段必须保留原值，显式 `normal` 才恢复默认等级。
2. `proposed`、`todo`、`in_progress` 可修改；`done`、`cancelled` 只读。
   进行中修改只保存元数据，不改变当前 claim、Session、进程、平台、容量、
   恢复、清理或停止责任。以后合法重新进入待办时使用保存的新等级。
3. Goal 显式设置任意等级（包括 `normal`）均拒绝；对外表达为
   `priority: null`，不能让内部默认值产生 Goal 可执行的含义。
4. 仅复用现有项目 Task 写权限，不新增优先级专用角色。依赖与 Goal 归属变更
   不复制、不重置等级。复制字段、状态迁移和 claim 释放也不得丢失等级。
5. 优先检查当前权限与精确 Task 版本，再判断同值。当前版本同值不递增
   `version`，不改时间；旧版本同值仍为冲突。真实修改使 Task 版本递增一次、
   更新 `updatedAt`，不改 `createdAt`。与其他字段原子修改时总共只递增一次。
6. `null`、未知枚举、错误大小写、数字、布尔、数组、对象及重复 JSON 字段
   均拒绝；不得把非法或未知数据静默转成 `normal`。

### 领取资格与顺序

只比较满足当前领取合同的普通 Task：待办、依赖完成、负责人匹配、项目访问
有效、允许自动执行、父 Goal 条件满足、未暂停、无冲突 claim、平台兼容，
且通过本地项目准备、容量、资源和执行器门禁。优先级不能绕过任何门禁。

新 Worker 在已完整观察的项目候选中按以下顺序选取：

1. 业务等级降序。
2. 同等级中，`preferPlatformSpecificTasks=true` 时，当前实际平台专用任务
   优先于通用任务；关闭时两者同类。
3. 同等级同平台类别按项目轮转。
4. 项目内按 `createdAt`、`id` 升序。

因此 B 项目的紧急通用任务先于 A 项目的普通 Windows 任务；同级平台偏好
是对现行跨项目平台优先规则的拟议调整，不是当前实现事实。
同级平台专用任务持续到达也可能延迟该级通用任务。

已有 pending claim、原执行恢复和清理先按现行所有权规则处理；不能为了
新紧急任务释放、跳过或重建原执行。一个协调轮次至多新增一个 claim。
同级轮转按等级和平台类别独立维护，扫描或跳过不推进其他分组的位置。

### 观察与并发边界

排序必须在服务端过滤与分页之前完成；不能只对旧接口第一页本地排序。
本地拒绝某个候选后必须继续该项目的有序流，不能使后页永久不可见。
查询并发、每轮页数、候选数和超时必须有明确上界。

候选读取必须有自己的、绑定查询身份的一致性标识；影响排序或资格的变化
使旧遍历失效。失效后有界重读，不得把失效、拒绝、权限撤销、扫描未完成、
网络错误或不支持协议当作空队列。

当某健康项目扫描未完成且仍可能藏有更高候选时，本轮不得拿其已见低等级
候选冒充最高候选；下一轮继续扫描。真实失败项目可以暂时排除，让已完整
观察的健康项目推进，但必须报告观察不完整及具体项目错误。
该降级不提供失败项目之间的优先顺序保证。

领取使用所选 Task 的精确版本，并在原子事务内重验现行领取资格。
候选自身变化或竞争失败后重新选择，不复用旧排序决定。其他项目在读取后
新到达紧急任务不撤销已提交的合法 claim。多 Worker 的启动、完成顺序不受
全局排序保证；同级轮转仅约束单个连续运行的 Worker。

## 用户入口与读取一致性

HTTP 创建/更新、MCP `task_create`/`task_update`、CLI create/update 和 Web
普通 Task 创建/详情编辑使用相同枚举及省略语义。详情、写入回执、列表、
搜索、图、Goal 子任务、同步快照/增量、个人进行中列表以及 MCP summary/full
中实际呈现 Task 的投影必须一致。版本保持各现有协议的精确表示，不借新增
字段改变旧版本编码。

普通展示列表仍保留现有状态/readiness 分组与分页，搜索仍保留现有相关性
排序；不以 Worker 调度顺序替代它们。首期不增加列表优先级筛选、排序、
拖拽重排或批量编辑。未来增加时必须在服务端分页前执行。

### Web 交互

遵循 [UI 原则](../ui-design.md)与
[公共选择控件](../design/native-select.md)：

| 入口 | 要求 |
| --- | --- |
| 普通 Task 创建 | 选择器默认普通；草稿按现有账号/项目作用域保留；Goal 创建不出现 |
| Task 卡片、行、图节点 | 文字等级配合可区分图标；普通可弱化但可访问名称保留完整等级 |
| Task 详情 | 普通 Task 显示已确认等级和独立草稿，显式保存；进行中可编辑并说明当前执行不变 |
| Chain/Goal 展开成员 | 每个成员显示自己的等级；容器标题不显示“整体优先级” |
| 个人列表、搜索结果 | 显示真实等级，不改变现有排序 |
| 无写权限、终态 | 等级可读，控件禁用；原因可由键盘和触摸访问 |
| 服务能力未确认 | 不提供编辑；明确未知/不支持，不猜测普通 |
| 混合 Worker | 说明元数据支持与实际调度支持不同；不显示虚假的“全队列已生效” |

等级使用中性文字与图形，不占用生命周期、attention 或 error 语义色。
紧急且依赖阻塞同时显示两个独立事实；紧急不表示故障或正在运行。
图节点选择和键盘焦点同时保留，等级徽标不成为多余 Tab 停靠点。

每 Task 复用现有写入串行化与账号/项目/Task 身份栅栏。提交后禁用重复保存，
其他字段写入不相互覆盖；仅确认回执才发布新值。失败保留旧确认值和草稿；
冲突要求读回并重新核对，不自动合并或重放。结果未知时先读回；同值读回
只证明当前状态，不能证明原操作已成功。读回失败继续保持未知，提供重试。
切换 Task 或账号后，迟到响应不得污染新作用域。后台同步保留焦点、草稿、
滚动、展开和图视口，不能整页刷新。

两种语言、320px 与桌面、长标题、键盘/触摸、加载/空/失败/未知/权限撤销
都必须验证。正常文字对比度至少 4.5:1，必要非文字提示至少 3:1。
交互原型仅证明提案的交互，不代替生产组件与真实服务验收。

## 兼容与生效

新字段投影与新候选排序分别显式协商。未协商的旧响应保持原形状；严格
消费者不得因无条件新增字段而失效。新客户端遇旧服务禁用该能力，不写入
后再误报成功。能力已确认却缺字段、枚举非法或响应协议不匹配必须报错。

兼容服务先部署，随后升级领取 Worker，最后开放编辑。新 Worker 报告其
实际采用的调度协议与观测时间；仅版本号、安装完成或配置目标不证明已应用。
旧 Worker 仍可能按旧规则领取，不能假装其遵从新等级。首期不新增旧 Worker
领取封禁或项目级强制准入；强制统一调度属于另需确认的产品变更。
离线或无报告的 Worker 为未知，不据此推断其已停止或已升级。

回退保留数据库等级和迁移记录。回退到理解新迁移前缀的兼容版本，必要时
关闭编辑并明确调度降级；不删除记录绕过迁移校验，不把已保存等级清为普通。
