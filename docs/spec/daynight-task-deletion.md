# Task 软删除需求

## 范围与数据保留

用户可通过 CLI 或 Web 删除 Task。删除使用独立于 `todo`、`in_progress`、`done` 的持久化标记；保留任务数据库行、完整资料、状态、执行起止、附件元数据及文件字节。默认保留依赖记录；显式选择解除引用时，只删除其他任务指向目标任务的直接依赖，目标自己的前置依赖继续保留。公共 Task JSON 不增加删除时间字段。已删除任务退出正常业务视图，不提供恢复、回收站、批量删除任务、级联删除任务或传递重连入口。

## 删除规则

普通项目成员和管理员均可删除。删除必须在同一项目写事务中重新核对成员权限、任务身份和精确版本，先判断版本，再判断业务限制。合法版本范围为正 int64，沿用既有严格 JSON 和 CLI 十进制规则。

- `removeDepends` 省略或为 false 时采用严格删除：存在任意未删除源任务引用目标任务，返回 `409 dependency_unsatisfied` 和稳定排序的引用者 ID，不修改任何记录；没有这类引用时可以删除，已删除源任务的历史引用保持原样。
- `removeDepends=true` 明确授权解除全部传入引用并删除目标。清除执行时所有源任务指向目标的直接普通和外部依赖，包括已删除源任务的历史引用，不按确认时的引用数量或某份固定 ID 清单裁剪。
- 目标存在 active worker 执行归属时，返回 `409 invalid_transition`；必须先完成对应 release 流程。解除引用的源任务允许仍由 active worker 持有，其状态与 claim 保持不变。
- 目标没有 active worker 归属且满足所选删除模式时，无论处于哪种业务状态，都可以删除。人工 `in_progress` 本身不构成禁止条件。
- 目标版本陈旧返回 `409 version_conflict`。成员、版本和目标 worker 保护均在解除引用之前完成；拒绝不修改任务、依赖、附件或项目缓存 epoch。

成功删除只递增目标任务版本一次，更新其 `updatedAt` 与内部删除时间；目标自己的前置依赖、其他业务字段与附件保持不变。显式解除引用时，每个实际失去引用的源任务只递增一次 version 并更新 updatedAt，其他依赖、外部分类、状态、计时、worker 归属和删除标记保持不变。解除前置可能让未完成源任务变为 ready；它不停止执行、改写 claim 或自动完成源任务，后续写入继续使用其新版本。

所有依赖移除、源任务版本更新、目标软删除与项目缓存 epoch 的一次轮换在同一事务原子提交；SQL、取消或事务失败完整回滚。业务准备阶段只校验并生成计划，不执行解除引用；真实修改属于已通过全部保护的删除执行阶段。未移除的历史依赖继续保留，已删除源任务不计入活动图、边数、可达性及直接后继保护。

## HTTP API

`DELETE /api/v1/projects/{projectId}/tasks/{taskId}` 接受 JSON 正文 `{"version":123,"removeDepends":true}`，成功返回 `204`，无正文。version 必填；removeDepends 可省略或为严格布尔值，省略/false 保持严格删除，true 才解除引用。拒绝 null、字符串、数字等非法 removeDepends、query、重复或未知字段、缺失版本、非整数及越界值；认证、Cookie 写入的 Origin 校验与 no-store 沿用其他任务写入。

项目成员对已删除任务的定点读取、更新、状态、worker 或附件操作返回 `410 task_deleted`；不存在的任务、错误项目以及无项目访问权仍为 `404 not_found`。删除后重复 DELETE 返回 `410 task_deleted`，不再次变更版本或 epoch。不能用任务已删除响应撤回整个项目访问。

列表、ready、完整图、任务同步、统计、自动执行候选和新依赖引用只包含未删除任务。`--all` 只扩大业务状态范围，不包含已删除任务。附件地址访问遵循任务可见性，即使底层文件仍存在也不能通过正常附件 API 读取。

## CLI

`daynight task delete <task-id> [--remove-depends] [--if-version <version>] [--project <project-id>]` 与 `dn` 等价。`--remove-depends` 是可选开关；不传时严格删除，无未删除引用者即可成功，有引用者返回 409。传入时发送明确的 `removeDepends:true`，原子解除全部传入引用再软删除。省略版本时仅先 GET 一次任务并提交读取到的版本；显式版本直接提交，不能以新版本替换冲突版本。成功输出明确的软删除结果；失败保留服务错误和不确定写入诊断。CLI 不另加交互确认，不自动重试写入。

```bash
daynight task delete <task-id> --if-version 3
daynight task delete <task-id> --remove-depends --if-version 3
```

## Web

居中详情和独立详情共享删除入口。操作前弹出明确说明“解除其他任务对本任务的依赖并删除”的组合确认窗，展示任务标题、数据保留及可能改变 ready 状态的后果，初始聚焦取消。授权范围是执行时所有直接引用这一类别，不是当前看到的数量或固定引用者清单。确认同时绑定任务、精确版本、明确的 `removeDepends:true` 意图和已准入的项目缓存 generation；传输层不得自行推断或补上解除引用选项。只有明确确认且提交准备后仍属于该操作所有者与历史，才发送一次 DELETE。每次异步准备结束及请求发送前都重新检查；准备期间切换数据历史时零写入，只 GET 刷新当前详情，并要求 fresh GET 后重新确认，即使恢复后的任务 ID 和版本相同也不能沿用旧确认。取消、Escape、遮罩关闭及失效确认不发送写请求。仅关闭详情不取消已经接受、且历史与所有权仍有效的操作意图。同用户身份核验暂停时，提交准备和普通结果处理等待既有身份 gate，恢复后重新检查原审阅历史、操作所有者与身份生命周期，再读取当前准入或改变操作阶段；再次暂停继续等待，身份结束使旧操作失效。未发送的失效准备以本地冲突或拒绝结束并只读刷新；已发送但属于旧历史的结果进入未知结果与 GET 核对，不得永久占住 pending 或产生未处理异常。确认窗沿用焦点约束、背景 inert、焦点恢复、双语和 320px 窄屏要求。

删除与状态、自动执行许可、平台操作共享同一任务操作所有者。pending、unknown 或 reconciling 时禁止并发写；关闭详情不会取消已提交操作的核对义务。请求超时或响应丢失只允许 GET 核对，不自动重放 DELETE。当前数据历史中的可信 `410 task_deleted` 确认任务已删除，清除该任务内容并请求项目同步；权限撤回继续沿用项目级撤回规则。已发送操作的可信同用户 `404 not_found` 在普通暂停等待前立即按原 ticket 撤回项目准入并清除私有正文，不等待身份核验恢复；持久清理继续等待 gate，旧历史 ticket 不能撤回新历史。删除终态绑定确认该事实的项目缓存 generation，不能永久绑定 task ID。

成功后图和列表不再展示任务，选中任务消失时详情弹窗关闭并恢复到仍存在的入口。独立详情显示已删除状态并保留返回项目入口。其他标签页通过新的项目 epoch 接收完整快照，原子移除旧摘要与详情缓存；本任务删除不能让整个项目进入无权限状态。

既有[配套数据库与文件恢复流程](../../deployment/localhost/README.md#persistence-and-backup)可以恢复删除前的数据历史，并在重新开放服务前轮换 epoch。后续已获授权的新 generation 快照同时包含该 task ID 的活动节点和摘要时，页面解除旧删除终态并重新 GET 完整详情；只有当前历史的 live GET 成功后才可写入。相同 ID、业务版本或时间不允许复用旧详情或操作权限。状态、自动执行许可、平台和删除的所有迟到结果都须同时匹配操作所有者与数据历史；旧历史结果不能修改恢复后的详情、覆盖较新操作反馈或解除较新操作的共享写锁。旧 DELETE 的 `204` 或 `410` 也不能重新设置删除终态，任何旧操作均不因此重放。既有身份隔离和按捕获项目 generation 处理的撤权规则继续有效。

## 验证

验证无引用时不传开关成功、存在未删除引用者时省略/false 拒绝且零变更、true 原子解除普通/外部/已删除源任务历史引用；每个受影响源任务版本只增加一次，其 active claim、状态与其他资料保留；目标自己的前置、数据库记录和附件保留，epoch 只轮换一次。验证三状态、陈旧版本、目标 active worker、权限隐藏、重复删除、严格布尔、准备阶段拒绝零写入和删除执行中 SQL 失败完整回滚。并发新增引用先提交时，显式解除删除可随后成功并移除该新引用；删除先提交时新增引用失败；严格删除仍保持引用保护。验证所有读取、图计数、自动候选和附件入口的一致可见性及旧 epoch 的完整快照替换。Web 验证确认与取消、共享写锁、GET 核对、独立页、跨标签同步、身份隔离与删除后焦点；在异步提交准备的每个等待点替换为相同 ID/版本的新历史，确认旧决定零写入且新历史必须 fresh GET 后重新确认；组合身份核验暂停与历史替换，验证恢复后没有未处理异常或永久 pending，且已发送操作的可信 404 在 gate 暂停时立即隐藏私有正文；验证删除前历史配套恢复后同 ID 任务重新读取，以及旧历史各类操作结果不能覆盖恢复后的详情或较新操作。覆盖旧状态/许可/平台结果晚于新 DELETE 提交，以及旧 DELETE 成功或 Gone 晚于恢复后新操作的场景，确认当前反馈与共享写锁保持正确。实现机制由[软删除设计](../design/daynight-task-deletion.md)拥有。
