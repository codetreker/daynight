# Web 工作空间

本文拥有项目任务看板、任务详情和账号级 Worker 运行观测与配置编辑的可见行为。生产页面与 API 由同一 Go 服务交付；看板、附件、认证和 Worker 页面共享工作空间及语言状态。运行结果按对应源码保留在 PR、CI 或实际验收材料中，设计预览不构成产品整体验收结果。[设计](../design/daynight-web.md)说明机制。

[预定义属性需求](daynight-task-properties.md)的 server 接口、CLI 和任务详情中的
只读 PR 引用区域已实现。[架构](../design/daynight-task-properties.md)拥有该扩展的机制。

[附件需求](daynight-task-attachments.md)拥有已实现的文件树、单文件上传、覆盖、
删除、下载及预览行为，机制见[附件架构](../design/daynight-task-attachments.md)。
图与统计约定继续有效；任务字段写入包含下述状态、自动执行许可、暂停解除、平台、负责人和强制撤回操作。项目任务页在可见时每 15 秒、隐藏时每 5 分钟通过 task-sync 增量合并 IndexedDB 摘要并发布完整本地图，详情按摘要业务版本与恢复需要读取，成功同步 receipt 独立更新时钟，刷新保留浏览、焦点和附件操作状态；具体时序与错误语义见下文。[任务缓存需求](daynight-task-sync.md)拥有水位、原子存储、身份准入及详情缓存行为。

[鉴权需求](daynight-auth.md)拥有登录、CLI 设备授权、私有项目、成员管理、邀请和访问令牌界面。
生产 `Application` 在常驻 LocaleProvider 下区分公开首页、公开指南、登录完成页与认证应用；登录完成页在确认并发布账户后返回原目标。
`AuthenticatedApp` 及其 API 客户端拥有 `/login` 和认证后的工作空间；
[推广页要求](daynight-landing.md)拥有公开介绍、演示与入口，[鉴权架构](../design/daynight-auth.md)拥有私有生命周期。登录方式来自后端
真实 UniAuth App discovery，项目列表仅包含当前用户有权访问且符合当前范围的项目。登录、账户、
成员、邀请、设备授权、令牌与原有看板共用英语/简体中文目录及状态保持规则。
可信同源 frame、相对资源和键盘交互继续保留，附件请求按当前身份执行成员检查。

[双语需求](daynight-web-i18n.md)拥有英语与简体中文的完整覆盖、语言选择、独立保存、状态保持和 L1–L10 验收条件。生产入口、现有全部第一方组件、任务链图浮层及居中详情对话框已接入同一语言状态。业务与数据契约保持原约定；项目分区、任务类别及页面位置继续独立保存，图浮层打开状态不持久化。

[执行计时需求](daynight-task-timing.md)的起止字段与数据库图时间样本已有严格 Web 读取模型；
仅时钟样本变化的轮询继续复用图与索引，项目设置变化也保留任务索引。项目阈值设置、进行中/完成耗时及醒目提醒共享同一权威数据。

Webhook配置、订阅、投递排错与重投的业务结果、身份隔离、独立资料权限、固定操作恢复和机器验证由[独立规格](webhook-web.md)拥有；页面保留既有工作区shell和页面语言选择器。

## 目标与使用环境

用户登录后通过 `/projects` 进入默认 Team 的项目，也可在 `/teams/{teamId}` 浏览指定已加入 Team 的项目，或通过 `/shared-projects` 查看仅凭项目单独授权访问的项目；通过 `/workers` 查看当前账号近期 Worker 的运行观测，并在 Worker 详情中管理云端运行配置。
公开 `/` 的介绍与演示由[推广页要求](daynight-landing.md)拥有；进入工作台后的完整路径为：
项目列表 → 项目概览 → 任务列表 → 独立任务、任务链或 Goal → 查看详情。再次进入项目时
恢复上次选择的概览、任务列表、PR 列表或标签。Project 分区按“概览 → 任务列表 → PR 列表 → 标签”排列，桌面纵向、手机横向。PR 列表默认展示已保存的 open PR（包含 Draft），支持状态与标题/编号筛选和每页 6 条的双向游标分页。点击行打开独立 PR 详情；列表及详情的后台更新和分区切换保留筛选、页面、选中项、原文选择与阅读位置。任务图读取失败不阻断 PR 或标签目录。项目成员可搜索、创建、重命名和确认删除项目标签；删除预览显示当前名称、版本与可见 Task/Goal 数量，确认删除全部关联而不删除条目。名称须经首尾空白处理后为 1–64 个 Unicode code point，不含控制字符或换行，ASCII 大小写不区分重名。读取失败与空结果分别显示，权限不足禁用写入；冲突和未知结果保留草稿，核查不重发原操作。后台检查不得重置已有页面、焦点或草稿。未知数量、初始化、读取失败、成功空集合和同步异常时保留的数据分别表达；具体机制见[PR 读取设计](../design/github-pr-reading.md)。

沿用[服务端要求](daynight-server.md)的 project、Task 和全依赖执行语义；普通 Task 可直接归属一个 Goal，Parent 不改变依赖。
任务链是普通依赖的弱连通分量；多起点通过普通边合流时属于同一条链，外部边不合并成员。
代表任务取普通入度为零且在精确服务顺序中最早的成员。没有普通前置及普通后续的任务进入独立任务列表，
但仍可能被外部前置阻塞。分类不依赖状态，已完成前置仍保留普通关系。
页面展示当前用户可访问的数据；项目创建由鉴权工作空间提供，任务的创建、修改继续使用现有 API。

## 工作空间导航

桌面工作空间侧栏默认展开为 190px，可折叠为 68px 竖条。侧栏依次按当前团队或个人空间、“我的”和“工具”分组：当前范围包含 Team 选择器、项目树及团队设置；“我的”包含与我共享、我的 Worker 和助手；“工具”包含 Webhooks 和测试会话。Webhooks 入口使用 `/webhooks?owner=personal`，页面的归属选择独立于侧栏 Team，并受现有 catalog 准入控制。Team 选择器在名称上方显示“团队”或“个人空间”，未知类型保留空行；名称可省略，完整名称和已知类型可通过可访问名称及提示读取。Team 切换入口选择已加入的 Team 或创建普通 Team；普通 Team 只提供一个“团队设置”管理入口，打开所选 Team 的 `/teams/{teamId}/settings`，默认进入基本信息。成员管理归入设置的“成员与邀请”分区，使用 `/teams/{teamId}/members`；两个分区均选中侧栏的团队设置。侧栏和分区导航使用普通链接，保留修饰键、新标签页、直接访问、刷新及浏览器前进后退。确认选择 Personal Team 时，侧栏不显示 Team 设置，剩余入口连续排列；Team 名称不决定其类型。该规则适用于展开、折叠及窄屏导航，也适用于所有共用工作空间侧栏的页面。Personal 的两个设置分区地址仍支持直接访问与重载，原有只读和权限规则不变。“与我共享”和“我的 Worker”分别进入 `/shared-projects` 与 `/workers`。Worker 列表与详情都保持该入口选中。
Team 切换入口在桌面展开、折叠及手机竖条和抽屉中直接打开锚定的非模态菜单，不改变侧栏折叠偏好或抽屉状态，也不推移导航。菜单不受侧栏滚动区裁剪，随视口和滚动调整位置，长列表在菜单内滚动；选项按 ID 区分同名 Team，长名称可读。Personal、创建、分页及各类加载和错误重试均可操作。触发器具有本地化名称和展开状态；鼠标、触摸和键盘可打开、遍历及激活选项，普通链接保留修饰键和新标签页语义。再次点击、外部点击、Escape 或切换页面关闭菜单；Escape 恢复触发器焦点，手机抽屉中先关闭菜单，再关闭抽屉。Tab 可离开菜单，创建入口沿用创建窗口的焦点隔离和恢复。
右上角头像触发账户菜单，其中“账户设置”进入 `/account` 并关闭菜单，“退出登录”以分隔线和危险动作样式区分；顶栏不再提供独立退出按钮，展开及折叠侧栏均不显示账户入口。
选择菜单中的“退出登录”直接沿用现有退出流程，不增加确认窗口；退出中提示、失败重试、跨标签页清理和成功后的返回行为不变，账户设置页原有退出按钮仍可用。
触发器具有本地化可访问名称和展开状态，点击或 ArrowDown 打开并聚焦首项，ArrowUp 打开并聚焦末项；菜单内方向键循环移动，Home/End 定位首尾，Enter/Space 激活菜单项，Tab 可离开菜单。再次点击触发器、
点击菜单外部、按 Escape 或切换页面均关闭菜单；Escape 关闭后焦点返回触发器。菜单在
桌面及 320px、390px 窄屏内可操作，不超出视口，长姓名和默认头像也保持可用。
项目入口统一显示“项目”，`/projects` 与 `/teams/{id}` 的页面标题均为“项目”，上方显示已确认的团队或个人范围，文档标题与之同步。共享列表保留独立标题和说明。面包屑按页面实际范围显示，直接项目不借用侧栏 Team 名称推断归属。
项目入口下展示当前 Team 范围的缩进项目子项，按服务端顺序排列；共享列表活动时不将共享项目归入 Team 子项。点击项目直接进入
`/projects/{projectId}`；项目、成员及设置页面选中对应项目。明确 Project 和 Task 地址不会被 Team 选择改写。
子项使用普通链接，保留修饰键和新标签页行为；长名称省略显示，完整名称可通过可访问名称
和悬停提示读取。展开的桌面侧栏及手机覆盖导航显示子项，折叠竖条隐藏子项。

首次进入工作空间且没有记忆时，默认使用当前账号的 Personal Team。浏览器按站点和账号
记住已确认的 Team 选择；在项目、项目设置、共享项目、Worker、账户等工作空间页面
刷新或直接进入时恢复侧栏选择，不把一个账号的选择应用到另一账号，也不改变 CLI 的默认 Team。
明确 Team、Team 成员与设置地址以 URL 中的 Team 为准。同页普通导航保留当前内存选择，
包括尚未保存成功的选择；重新进入 `/projects` 时重新读取记忆。共享项目是独立入口，不作为
Team 选择保存。独立 Task、附件和授权页面不启动侧栏恢复，随后进入工作空间时才恢复。

恢复前按记忆的精确 ID 验证访问；只有可信 404 才清除对应记忆并回 Personal，不能从分页
选择器未列出某 Team 推断失权。恢复期间不先读取 Personal 的项目目录，相关 Team 导航等待
选择就绪；未知范围保留没有 href 且标记 aria-disabled 的项目和设置占位。网络、服务器或浏览器存储读取错误显示可重试的错误，不静默覆盖记忆；取消不安装
结果。保存失败时保留当前页面选择并提示未保存，允许重试。恢复独立于明确 Project、Task、
附件和其他页面主体的读取，不改写其地址，也不以 Team 读取的成功作为主体可用的前提。
同一已确认 Team 的后台精确验证期间保留当前选择和项目页面；首次进入或切换目标仍显示加载。
Team 选择器的后台复核保留已加载的全部页面、游标和交互状态，完整前缀读取成功后才更新；
内容变化正常显示，失败保留已有目录并提供重试。明确刷新仍执行实际读取。

健康页面从隐藏或外部失焦恢复时，Team 的当前选择、已加载目录前缀及活动设置分区按各自资源规则后台重读；成员分区重新确认成员与角色，成功且仍有管理权限后才重读邀请。页面和本地编辑在等待中保持，远程操作仍受新鲜权限约束。账户提示先检查共享记录；若观察到变化进入等待刷新，这些读取不得派发。前台返回不重复 `/me` 身份初始化。

团队设置统一显示“团队设置”标题和当前 Team 名称，标题下方提供“基本信息”和“成员与邀请”两个横向分区导航。英文对应 General 和 Members & invitations；窄屏可自然换行，长 Team 名称和 ID 不撑宽页面。普通成员可进入两个分区读取信息并在自己的成员行退出 Team，管理权限仍由当前角色决定。

已登录用户可创建普通 Team；基本信息分区以可选择的文本展示名称和 ID，删除 Team 位于该分区底部的独立危险操作区。普通 Team 的 admin 可通过名称旁的修改按钮打开浮层改名并可删除空 Team；名称与按钮同排时垂直居中，长名称及窄屏可换行且不遮挡操作。成员和 Personal Team 的管理操作只读。可查看设置的用户均可使用 ID 右侧的双框按钮复制完整的已显示 Team ID，文本仍可手动选择；在途操作不可重复，成功后才提示成功，剪贴板不可用或拒绝时提示手动复制并允许重试。按钮提供中英文名称与悬停说明，支持键盘操作和可见焦点；窄屏允许换行，ID 与按钮保持可读可达。切换 Team、身份失效或卸载后的迟到结果不得显示在当前页面。改名浮层以当前已保存名称初始化，保存成功后关闭并更新设置页、导航和 Team 列表；取消、关闭或 Escape 不提交。名称不得全为空白，保留有效原文并允许重名。创建成功进入新 Team；删除成功后更新 Team 目录并安全清理仍指向该 Team 的选择，完成时仍处于该 Team 的任一设置分区则进入 Personal 项目页，已前往其他资源时保留新路由。删除前必须手动输入当前名称，取消或 Escape 不提交。非空 Team 拒绝删除并提示先转出项目。版本冲突后重新读取并要求核对；未知提交显示结果未知，允许只读核对，不自动重放，也不能通过重新打开浮层绕过保护。主体不匹配或迟到响应不能安装到当前身份。

成员与邀请分区只向该 Team 成员展示完整目录、可空姓名和邮箱及真实角色；资料缺失时使用用户 ID 识别。成员行的角色控件保持等宽并在同一列对齐，说明文字可换行且不改变控件对齐；窄屏重排后仍可读取和操作，不产生页面横向溢出。普通 Team 的 admin 可修改成员角色或移除成员，任意成员可自行退出；Personal 的成员和角色固定，最后一名 admin 不能降级或退出。每次角色变更、移除或退出均显示对象与权限变化并要求一次确认；取消或 Escape 不提交。Team 成员变化不改写 Project 单独授权。自降后刷新本人角色；自退完成时仍处于该 Team 的任一设置分区则进入 Personal 项目页。离页后的迟到自退回执仅将仍指向已退出 Team 的内存选择回退为 Personal，不改变新路由；仅替换仍保存为该 Team 的浏览器选择，并丢弃该 Team 尚未保存的选择。另一标签页保存的新 Team 与缺失的记忆保持原样；读取或写入失败允许重试，重试仍须核对已退出 Team 的保存条件，不覆盖后来的选择。服务端拒绝、版本冲突与未知提交分别展示；冲突需重新核对并确认，未知结果只允许读取现状，不自动重放。已确认成功独立于后续刷新结果显示。仅有 Project 权限不能读取 Team 目录。

同一 Team 的两个设置分区切换时，已访问分区保留草稿、打开的确认、进行中或未知写入及一次性邀请链接；返回分区不重新创建操作实例或自动重放。不可见分区暂停交互和新写入，返回后写入仍须等待当前身份、权限与版本复核。离开设置后，受保护的进行中操作、未知结果和一次性回执继续绑定原账号与 Team；后台复核保留已显示内容和本地交互。真实失权与身份变更继续执行对应隔离和清理。分区失活后的完成回调不将焦点移入隐藏内容。邀请管理位于成员列表下方，仅当前 admin 可读取、创建或撤销。

项目导航与项目列表页面共享已加载页及分页操作。首次加载、空列表、加载失败及重试均有
明确反馈；“加载更多”可继续浏览全部项目，续页失败保留已有项并允许重试。
创建项目使用当前真实身份与打开对话框时捕获的 Team，在该 Team 中保存有效名称和仓库地址原文；共享列表不提供创建入口。响应主体不匹配时
重验身份，不安装结果或自动重放写入。创建结果未知时保留未知提示，通过身份绑定的只读分页
核对当前目录；读取不能确认原提交，也不提供原候选的一键重发。创建项目或移除自身成员关系后更新共享目录；认证身份变化清除旧身份目录。
正文长页面滚动及短窗口都保持侧栏切换按钮可达。折叠后保留主入口图标、
中英文可访问名称、悬停提示与键盘操作；顶栏账户菜单继续可用。

当前站点以 `daynight.web.sidebar.collapsed` 保存 JSON boolean。没有记录时展开，
不为默认值主动写入；刷新、重新打开、跨项目与账户切换恢复同一浏览器的外观偏好。
读取失败、非法格式和写入失败分别显示可理解的提示，保留本次内存切换，并提供保存当前

### 云端运行配置

全局表单包含并发上限、任务轮询间隔（毫秒）、自动恢复上限、托管模式、平台优先布尔控件和 Agent/model/args。托管模式在桌面运行设置卡片中位于恢复次数右侧，窄屏折为单列；中文标签为“托管模式”，英文为“Control mode”，原生 select 恰有 herdr、web 两个选项，说明“应用后用于新任务，已运行的任务保持原模式。”新配置缺省 herdr，旧未采纳目标保持未选中并说明等待同步；用户可显式选择。未确认服务能力时禁用该字段并给出升级说明，不阻断其它编辑。平台优先控件的标签使用当前 Worker 实际平台的既有展示名称（例如“优先领取 macOS 的任务 / Prefer macOS tasks”），平台信息不可用时使用通用标签。平台优先是当前 Worker 独立的云端设置，默认关闭；开启后优先在该 Worker 全部已选可领取项目中寻找指定实际平台的任务，再领取不限平台任务，更新只影响后续新领取。开关沿用表单的草稿、保存与取消修改；实际 false 显示为已应用关闭，null 保持等待确认，保存目标不能冒充已应用。项目选择使用完整可访问目录，保留已选条目的覆盖意图；已选但不可访问的项目只显示其 ID，仍可原样保留或删除，不补回旧名称或仓库信息。可信项目撤权立即撤回目录、侧栏和配置选择中的名称与仓库地址，包括已打开的确认窗口；迟到分页不得恢复内容。持久清理失败时保留撤权并显示错误，其他项目保持可用。项目 Agent 可继承全局；model 的继承、指定值及显式 null，args 的继承及显式 [] 分别保留。项目换用不同 Agent 时，未覆盖的 model/args 使用该工具默认值。默认及项目配置下拉框的箭头与边框保持留白，文字与箭头不重叠；窄屏长选项可截断，完整选项可在原生菜单中查看。参数以 JSON 字符串数组编辑；非法原文和具体校验错误保持可见，不通过截断、丢弃空值或改写原文制造有效输入。repositoryRoot、非工具的本机路径、Worker 身份、服务连接与凭据只在本机管理。

工具路径使用默认折叠的独立区域，Codex、Copilot、Herdr 各有一个路径输入和“恢复自动”按钮，沿用同一表单的草稿、保存、取消和离开提醒。未采纳 null 显示等待 Worker 导入，保持 null 直到用户操作；auto 显示空输入与“自动”占位。输入后清空仍是非法 path 草稿，只有明确恢复自动才写 auto。路径按 Worker 平台检查绝对路径语法、字符及 4096 UTF-8 字节限制，不判断远程文件是否存在。服务尚未确认能力或 Worker 最新快照没有工具报告时禁用路径编辑并说明原因，其它配置仍可编辑；已有能力报告的离线 Worker 可以保存目标。

各项实际结果保留自己的 targetRevision、appliedValue 和状态。托管模式参与草稿、取消、保存、逐项反馈及整体应用结果；实际 null 或没有同名应用观测保持待确认，旧 Worker 尚未上报不能显示已生效。目标值未变的独立标量或 native 项可沿用已有成功值；目标值已变时，旧成功值仍作为实际值展示，不能显示为新目标已生效。项目尚无当前目标观测，或最近移除版本不早于其准备/native 结果时，保留等待状态，不能用早先的成功覆盖移除后的未确认准备。准备、停止失败可与其他配置成功同时出现。即使项目已从目标移除，最近报告的移除结果仍可见。错误使用协议中的清洗 code/category/phase 及时间，当前错误、尚需报告的最近失败和重试期限各有含义，不显示原始命令输出。Worker 离线时可以保存目标，最近实际结果保留为上次确认值，恢复通信后才能确认应用。

草稿、未通过解析的原始输入、当前云端资源和提交快照独立保存。后台读取可以更新目标与应用结果，不覆盖编辑中的值、焦点、选区或项目展开状态。保存使用开始编辑时的目标 revision；应用观测变化不使草稿冲突。409 保留草稿，提供查看最新目标及明确载入新值的入口，不能自动覆盖或重试写入。明确保存失败保留输入；请求已发出但结果未知时，先 GET 核对当前资源，不重复 PUT，也不把值相同归因为原请求成功。核对期间不能提交另一份可能重复的写入，提交后继续编辑的内容不被较早响应覆盖。

配置数据和未提交草稿只属于当前账号、Worker 和页面生命周期，不进入项目缓存或 IndexedDB。账户变化等待刷新期间保留编辑器、对话框、未应用的项目选择、搜索、原始输入、展开、焦点和选区，本地编辑仍可继续；私有读取、新保存和其他网络操作等待准入。已发出的保存保持提交快照及实际结果分类，在准入恢复后发布，不因检查而重放。项目目录后台复核保留已加载的完整候选集，包括有效空集；首次加载、明确刷新和真实错误保留各自的反馈。账号或 Worker 改变后旧响应不能发布。详情页签、项目选择与确认对话框支持键盘操作和焦点恢复，中英文、长项目名与参数以及桌面和窄屏布局保持可用。表单可用性通过控件表达，真实字段错误、保存冲突及应用失败保留明确反馈。

配置或 Worker 提示词存在未保存修改时，包括未通过解析的配置原始输入，应用内链接、侧栏、返回 Worker 列表及同一导航历史段内的浏览器前进/后退只需一次离开确认。“继续编辑”为默认焦点，Escape 等同继续编辑；取消离开时，一份草稿有修改则返回所属页签，两份均有修改则返回最后编辑的页签，并恢复该编辑器的有效控件焦点。确认放弃后才离开，再次进入读取已保存资源。同一 Worker 的三个页签切换保留两份草稿且不提示；实际切换记录绑定账号和 Worker 的浏览器历史，重复选择不增加条目，前进/后退只恢复页签，不重放业务操作。两份草稿均无修改时不提示；刷新或关闭页面由浏览器原生离开提示保护。账号变化或会话失效直接清理旧私有草稿与待决确认，不允许离开确认阻挡访问撤销；已确认的资源不可用按对应资源处理。运行观测超窗不等于配置资源不可用。

### 个人 Worker Prompt

账号设置的资料、访问凭据和用户 prompt 页签切换记录浏览器历史；后退和前进恢复对应页签，重复选择不新增条目。页签切换保留编辑器、草稿、凭据结果和进行中或未知操作；恢复不重放业务操作。历史只保存绑定当前账号的阅读选择，不保存草稿、秘密或业务响应。无效的已识别状态显示导航错误，旧账号的选择不能用于当前账号。

账号设置、项目设置和 Worker 详情的提示词页签分别提供用户级、项目个人级和 Worker 级多行 prompt。普通项目成员可编辑自己的项目内容；它与管理员共享项目设置独立。Worker 运行配置的读取失败、校验或初始化状态不阻挡 prompt 读取和编辑，prompt 失败也不阻挡运行配置。首次进入提示词不要求读取运行配置或 Worker 在线；已打开的编辑器在页签间保持挂载，隐藏时暂停对应资源读取。空正文保存后移除该层追加内容，文字、空格和换行原样保存。页面说明服务端保存与 Worker 收到更新之间的时间差；组合效果使用当前层草稿和其他层的示例占位内容，不表示实际任务输入。

未修改时不能保存。后台读取与账户变化等待刷新或权限复核保留草稿、焦点和选区；真实会话失效或项目失权清除旧内容。保存冻结账号、版本和正文，允许继续输入；冲突保留草稿并提供最新内容及明确选择。已发送写入结果未知时只能读取当前值核对，不自动重放，也不把同值归因为原请求成功。应用内导航保护未保存草稿，Worker 同页两份表单共用一次离开确认；离开不撤销已发送的写入。

## 日常使用引导

顶栏语言选择器前提供书本图标及可见的“使用引导 / Setup guide”链接，普通点击在

当前语言。未登录直达、带 query 访问和刷新均直接显示该页，页面提供进入 `/projects`
项目列表的入口。

简介提供 MCP 和 CLI 与 Agent skill 的页内链接；两个章节始终展开，MCP 在前。MCP
不依赖安装 Daynight CLI，面向支持远程 HTTP MCP 的 Agent：

1. 配置客户端：显示可选中、可复制的当前服务 `/mcp` 地址及带可见标签的原生客户端
   选择器，默认 Codex，另支持 Claude Code 和 Copilot CLI。命令配置当前用户，Claude
   明确使用 user scope；Codex 和 Claude 的配置块同时包含 login 命令。`<endpoint>`
   表示实际地址，页面显示与复制的命令使用真实地址和 POSIX shell 单引号；页面明确
   指示在 POSIX shell 中执行这些命令，Windows 可使用 Git Bash：

   | 客户端 | 完整配置命令 |
   | --- | --- |
   | Codex | `codex mcp add daynight --url '<endpoint>'`，换行 `codex mcp login daynight` |
   | Claude Code | `claude mcp add --transport http --scope user daynight '<endpoint>'`，换行 `claude mcp login daynight` |
   | Copilot CLI | `copilot mcp add --transport http daynight '<endpoint>'` |

2. 授权账户：在客户端打开的浏览器核对账户并批准 `daynight:mcp`。取消、账户错误或
   连接失败时在客户端纠正账户或重新授权。Codex 和 Claude 提供 `--no-browser` 变体，
   分别为 `codex mcp login daynight --no-browser` 和
   `claude mcp login daynight --no-browser`，按客户端提示访问 URL 并回填完整返回地址；
   Copilot 的 `/mcp auth daynight` 明确是
   会话内输入。保存配置和批准均不证明工具已连接，`daynight login` 只登录 CLI。
3. 验证连接：重新加载或重启活动 Agent，确认连接并列出工具，提供可复制请求以调用
   `team_list` 列出可访问团队；成功标志是只读调用成功。

页面链接到公开 `/mcp` 安装手册、所选客户端官方文档和 `/account`；账户页选择 Tokens
管理令牌和应用授权。仅支持 header 而不支持 OAuth 的客户端可在 secret/environment
设置中使用已有 PAT，页面只展示 `Authorization: Bearer <PAT>` 占位文本。链接仅在用户
明确点击时导航，不预取。MCP 服务和 OAuth 协议由 [MCP 需求](daynight-mcp-oauth.md)拥有。

CLI 与 Agent skill 章节完整展开五步，供首次操作和重复查阅。每步说明执行位置、必要
前置条件、可复制内容与成功标志，命令遵循实际发布的 CLI：

1. 安装 CLI：准备 Node.js 22 及以上版本的最新补丁，在终端运行 `npm install --global @codetreker/daynight`，
   再运行 `daynight --version`，以版本输出确认可用。
2. 登录账户：运行 `daynight login`，核对终端与浏览器的短码、当前账户和访问范围后批准。
   远程终端可使用 `daynight login --no-browser`，终端明确报告登录成功。CLI 默认连接
   `https://daynight.cc`，日常使用无需先配置服务地址。
3. 创建或找到仓库项目：在具有 Git `origin` 的目标仓库运行
   `daynight project create "项目名称"` 和 `daynight task list`。单个匹配项目直接返回，
   多个匹配明确报错并由使用者选择项目 ID；没有本地绑定写入。新项目的空任务列表是正常结果。
4. 安装 Agent skill：至少已安装一个受支持的 Agent launcher，在交互终端运行
   `daynight skill install`，选择 Agent 和 User/Project 范围；Project 范围要求位于
   Git worktree。按安装输出中的 Agent 专属提示加载指令，以识别 `using-daynight` 确认可用。
5. 开始使用：以当前语言提供 Agent 请求示例，登记一个具体任务，然后通过 Web 或
   `daynight task list` 查看。自然语言请求与终端命令明确区分，登记任务不隐含自动执行许可。

页面展示 `window.location.origin` 作为当前服务地址，并以
`new URL("/mcp", window.location.origin).href` 生成 MCP 地址；它不改变 CLI 默认服务。
引导随构建发布，不接收凭据输入，不发起 provider 发现、项目、任务、令牌或完成度读取。文档根在直接访问或刷新时进行一次 `/me` 身份初始化；query/hash、页内定位、客户端和语言切换、复制及窗口焦点或可见性恢复不额外发起身份请求。公开内容不等待身份确认，显式进入项目或账户后遵守正常认证和资源准入。

## 项目整体进度

概览在七项完整项目统计下提供整体进度列表。任务链以普通依赖弱连通分量定义，每个未结束或近期结束的分量占一行；单成员仍按独立任务分类。成员按 ID 去重，代表参与进度，链外前置不计入。列表负责人和状态筛选不改变完整分量或进度范围。

Goal 列表、详情与整体图、普通及范围任务链、任务链详情和项目概览共用完成进度：分子为 done，分母为 total - cancelled。进度文案以“完成数/分母 已完成”或英文 completed 表达，概览行显示完成数/分母及百分比，所有可访问标签使用相同数字；轨道只有绿色完成段。分母为零时显示 0/0、0% 和空轨道，不推断 Goal 或链的状态。概览百分比向下取整，Goal 和链轨道使用未取整比例。9 done + 3 cancelled 显示 9/9、100%；4 done + 2 todo + 3 cancelled 显示 4/6、66%，轨道约 66.67%。取消成员仍属于真实成员与统计，done 变为 cancelled 后分子和分母均减少。

终态为 done/cancelled。全部 done 的链汇总为 done，全部 cancelled 汇总为 cancelled，混合终态汇总为仅供 UI 使用的 ended；ended 不是 TaskStatus。真实已结束数仍为 done + cancelled，与完成进度独立。尚未全部结束但已有终态或 in_progress 成员的分量为 in_progress，全部普通成员为 proposed 时为 proposed，其余未开始分量为 todo。Goal 自身状态独立于子 Task 的完成进度。

未结束项全部保留，不受创建日期限制；结束项按浏览器本地时区保留今天及此前6个自然日。边界从本地今天往前6天的00:00开始、包含起点并结束于当前时刻，跨DST仍按本地日历判断。done使用completedAt，cancelled使用cancelledAt。链使用全部普通成员当前终态时间的最大值，不使用代表、链外前置或updatedAt。只要仍有未结束成员，整组持续可见；全部结束的链有近期成员终态即可提供近期证据，全部未知或没有近期证据时默认隐藏。展开始终保留全部子任务，不按成员结束日期截断。

所有符合近期口径的独立任务汇总为一行：

```text
近期结束数 = 近期 done 独立任务数 + 近期 cancelled 独立任务数
真实总数 = 全部 proposed/todo/in_progress 独立任务数 + 近期结束数
展示分母 = 真实总数 - 近期 cancelled 独立任务数
完成百分比 = 展示分母为 0 时为 0，否则 floor(近期 done 独立任务数 × 100 / 展示分母)
```

更早结束或终态时间未知的独立任务不进入该行范围；行内说明统计范围。未结束 6 项、近期 done 4 项、近期 cancelled 2 项、更早结束 12 项时显示 4/10、40%；只有近期 cancelled 项时该行仍显示 0/0、0%。行是否存在和全部结束判断使用真实数据，不使用展示分母。七张统计卡仍采用完整项目统计；已结束卡的数值合并 done/cancelled，标签不误称为完成交付。

概览按in_progress、todo、proposed、终态优先级稳定排序再分页。独立汇总按近期集合生成同一UI汇总状态，处于同优先级末尾，不虚构创建时间。相同优先级保留真实分量顺序。

当前时刻使用服务端观察时间及单调差值推进；仅本地摘要阶段暂用本机时间，成功同步后替换锚点。跨本地午夜重算，隐藏暂停，恢复可见立即更新；近期过期不依赖成功网络轮询。刷新失败保留旧数据和错误，但时间范围继续推进。

空项目显示还没有任务；全部结束且无近期结果时显示相应结束空态。双语、320px、长标题、计数、百分比和操作保持可读，无整页横向溢出。定位、滚动、分页和焦点保留现有行为。

## Task 与 Goal 标签展示

项目独立 Task 行、Goal 行和 Goal 展开区域中的直接子 Task 行显示各自的标签；Task 与 Goal 详情显示自身标签，不继承父 Goal 的标签，也不汇总子 Task 的标签。改变 Parent 不改变条目的标签。没有标签是正常状态，显示“无标签”或“Untagged”。

Task 与 Goal 创建表单使用同一可搜索的标签多选控件，初始为空，父 Goal 的标签不会继承。创建时将所选集合与其他字段一次提交；标签无效或容量不足时保留草稿，创建结果未知时保留提交快照并阻止自动重发。选择器内新建标签立即加入项目标签库，取消创建不会删除该标签。

Task 和 Goal 详情可搜索项目标签并以多选草稿增删关联；保存提交完整集合，空集合清除关联。各状态和执行中的 Worker 不增加分类编辑限制。取消或 Escape 放弃未保存关联并恢复焦点；选择器内新建标签独立生效，取消编辑不会删除新标签，操作前显示这一说明。保存等待保留草稿，失败、冲突及未知结果保留选择并展示实际状态；核查当前已保存内容不重发原操作，采用新版本须由用户明确选择。后台身份或权限检查不清空草稿，真实身份变更和项目撤权退休私有内容。

## 项目任务搜索

任务列表顶部提供表达式搜索。Enter 或搜索按钮提交原始输入，非空草稿的编辑不改变已应用的查询。点击 × 或将输入删至空会取消已应用搜索及分页，恢复普通任务类别及其筛选、页码和滚动位置，焦点留在搜索框；标签条件继续在本地生效，清空不提交空表达式。在途搜索被取消，迟到响应不能恢复搜索视图。搜索覆盖当前类型的自身 ID、完整标题和 Markdown 描述，包括历史完成条目；支持 `id:` 限定，服务端决定匹配、顺序及上下文。结果显示完整标题、状态、负责人、任务 ID、标签、命中字段及可用的描述摘录；选择结果打开实际条目的完整详情。

搜索状态默认全部，负责人初始继承普通视图，之后独立于普通筛选。标签条件与普通列表共用，清除标签不改变文字或状态；Goal 视图只搜索 Goal。每页 15 条，筛选和重新提交回到首页。无结果、语法错误和读取失败分别呈现；失败可重试，保留的结果须标明其所属查询和刷新失败。语法错误标记原始输入中的位置，不把错误表达式当作无结果。空项目或项目图读取失败时搜索仍可用。

可见页面周期刷新当前页，隐藏时暂停。项目、身份、访问权限或历史改变时撤回旧结果与详情资格；旧请求不得恢复它们。翻页期间数据变化时回首页重读一次，持续变化显示可重试错误。关闭详情后焦点回原结果，结果已消失则回搜索框。帮助、筛选、分页和结果支持键盘操作，窄屏及长内容不造成整页横向溢出。表达式及服务端交换合同由[任务搜索接口](daynight-task-search.md)拥有。

项目任务视图提供标签筛选，默认要求全部选中标签匹配，也可选任一匹配或无标签；无标签与选中 ID 互斥。筛选与负责人、状态组合，Task 和 Goal 只按自身标签匹配，Goal 不因子 Task 命中而进入结果。顶层链按范围内至少一个成员匹配保留，展开和图保留完整上下文。普通任务列表的筛选栏依次显示负责人、状态、标签筛选；Goal 类别在其后显示唯一的子 Task 标签筛选，同一条件统一作用于所有 Goal 的直接孩子行。Goal 展开区只展示孩子列表。子项条件与 Goal 自身的标签条件独立，切换类别、收起或重新展开、翻页时保留；不改变 Goal 的可见资格、任务组成、进行中数量、暂停汇总、Session 提示或图上下文。搜索结果的标签筛选同样紧随状态，子项筛选只属于普通 Goal 列表。窄屏按同一顺序换行，打开的选择面板在视口内保持可读宽度。概览显式定位可清除挡住目标的有效标签条件，并保留定位的目标页；失效条件须由用户明确移除，定位不能静默清除。详情关系跳转的目标被标签挡住时仍可打开目标详情并保留标签条件。标签目录更新后保留所选 ID 和名称；失效条件与无匹配分别显示，须由用户明确移除后才恢复查询。后台检查保留选择器、输入和展开状态。

## 列表分页与定位

概览进度列表及独立任务、任务链、Goal 列表分别每页 20 个顶层条目。一条任务链或一个 Goal 计 1 条，
展开后的子任务不占额外条数；概览的独立任务汇总行计 1 条，参与同一状态排序。先形成
符合筛选的完整序列，再分页；项目统计、页签未完成任务数、Goal 成员与进度、图上下文
均不随页码变化。分页显示当前条目范围和符合筛选的总条数，并提供上一页、下一页；
只有一页时隐藏分页控件。

三个列表分别保留本次项目访问期间的页码，普通切换页签后恢复各自页码。改变负责人或状态
条件时，两个任务列表均回到第一页；午夜过期、同步或删除使总页数减少时，当前页立即落在仍有效
的页，不产生无效空白页。页码不新增浏览器存储记录，类别和滚动偏好继续按各自规则保存。Goal 行因翻页卸载后按 W5 重置展开状态；有效图资源由完整项目索引中的多成员分量决定，列表筛选及当前页不关闭该图。

点击概览任务链进度行进入“任务列表 → 任务链”，先切到目标 Goal 所在页，再滚动、聚焦
对应条目并短暂高亮，不打开依赖图。点击独立任务汇总进入“任务列表 → 独立任务”的第一页，
定位并聚焦列表开头。显式定位覆盖该次历史滚动恢复，返回概览保持概览位置；之后普通
切换恢复定位后的任务位置。定位期间刷新改变代表时，按原 task ID 解析当前分组及页码。
定位被负责人或状态条件遮挡时，调整必要条件以展示目标；目标已删除或成为单成员时，显示目标不可见提示并回到对应类别入口，不选择其他 Goal。请求消费后，后续同步不重复滚动。筛选、分页和定位
本身不增加 API 请求或修改 URL/history。链外卡片的“展开”只切换图或详情资源，不消费本节的列表定位，也不改变列表筛选、页码、展开状态或滚动。

## 任务条目状态背景

任务界面的生命周期、attention、error、activity、辅助文字及焦点／选择采用[UI 语义配色](../ui-design.md#semantic-color-roles)；该文档是精确色值、可读性及图节点双层轮廓要求的唯一所有者。概览整体进度行、独立任务整行、任务链和真实 Goal 的标题行、展开子任务行及依赖图任务卡片按生命周期状态着色。默认与悬停使用同一角色的背景，保留原有状态文字、布局和入口。条目整体透明度保持为 `1`，已取消条目仍可阅读和打开详情。任务详情及统计卡片保留各自的布局和中性容器，仅对应状态标记、圆点和数字消费生命周期角色；依赖图画布不按任务状态着色。

真实 Goal 使用自身的 `todo`、`in_progress`、`done` 或 `cancelled` 状态，不从子任务进度或任务链状态推导；子任务进度与 Goal 状态独立。独立任务、子任务及依赖图卡片使用自身状态，链外前置卡片同样如此；任务链标题及其概览行使用普通分量的整体状态，外部前置不参与聚合。全部 done 为已完成，全部 cancelled 为已取消，混合终态为已结束；尚未全部结束但存在终态或进行中成员时为进行中，全部普通成员为 proposed 时为待确认，其余未开始分量为待办。已有终态成员而没有成员正在执行的链仍使用进行中底色。概览独立任务汇总对该行当前计数范围使用同一规则；过期、未来或终态时间未知的结束项不影响其底色。汇总的显示条件及七天窗口沿用[整体进度](#项目整体进度)。

完成进度条只显示 done 的绿色完成色段，不包含 cancelled；进度分母及零值遵循[整体进度](#项目整体进度)，真实已结束统计仍分别保留完成和取消数。共享 Task Steps 的 `todo`、`in_progress`、`done` 使用对应生命周期角色，`skipped` 使用 cancelled 的中性配色角色并保留“已跳过”文字；Step 的四状态及其独立行为不变。

阻塞、暂停及暂停计数使用 attention 标签或既有提示条，底下保留真实生命周期颜色。独立任务及图卡片的既有卡住提醒优先使用 attention 默认／悬停背景，同时保留进行中标签、超时图标与说明；提醒不传播为整链或概览汇总的背景，也不为子任务新增提醒。图卡片的选中、前置检查、无关节点和键盘焦点均保留生命周期底色或卡住提醒底色；选中及前置检查使用选择轮廓，键盘焦点使用独立深色轮廓，概览跳转定位保留独立轮廓。两种轮廓同时可见，链外前置保留虚线边框。展开容器保持中性，每个子任务独立着色。

实际工作的 Session 注记、composer 活动标记、执行中的工具与 active Worker 指示采用 activity；等待输入、需要检查、暂时无法交互以及未知结果采用 attention，明确失败反馈和危险操作采用 error。Session `notice` 与 `warning` 均使用 attention，但保留各自文字及原聚合优先级；断连或停止本身不能证明执行失败。runtime 在线指示的绿色仅表达连接健康，头部状态文字使用中性辅助色，不代替实际活动标记。自动执行许可标签使用中性描边与明确的开启／关闭文字，现有开关的品牌选中色保留；许可不表示 Worker 已启动。读取及操作失败保留实际错误文字与恢复入口，颜色不改变数据、制造写入或把失败显示为空结果。

列表正文及辅助文字在默认和悬停背景上均满足至少 `4.5:1` 对比度。桌面及 `320px` 窄屏下保留长标题换行、状态及操作入口，不出现遮挡或横向溢出；空、加载、失败和禁用场景保留现有含义和可访问性。

## 统计与链外前置

```text
total = proposed + todo + inProgress + done + cancelled
todo = ready + blocked
blocked = status为todo且至少一个直接前置非done/cancelled的任务数
ended = done + cancelled
完成进度 = done / (total - cancelled)；分母为 0 时展示 0/0 和 0%
```

“待处理”包含“可开始”和“被阻塞”，三者不能相加作为总数；待确认、进行中与两种终态不计入todo。
创建默认 proposed，可显式选择 todo；ready仅在任务为todo且全部普通/外部直接前置为done或cancelled时为true。状态设置不完成其他前置，
也不授予执行权。[状态要求](daynight-task-status.md)拥有状态、版本、依赖与计时规则。

独立任务不显示单节点任务图，也不显示 0/1 式链进度。列表工具栏中的任务链条目数是多成员普通分量数，继续显示可见/全部条目数。前两个页签数字统计当前负责人条件下未归属 Goal 的未完成任务；选择全部负责人时，其和等于未归属 Goal 的待确认、待办与进行中任务数之和。链页签数字不表示链条目数，项目概览统计仍包含完整项目范围。

每条任务链的进度和聚合状态只计算其普通分量成员，不计算额外展示的链外前置。各链的成员集合互不重叠，一层 external 上下文只补齐直接前置，不扩大成员。相同前置可以出现在多个链的上下文中，但不会重复成为这些链的成员。

## 渐进图生命周期

画布保存实际可见 S，不持久化，项目/链/页签变化或卸载后清除。显式展开重新布局，在当前缩放居中操作卡片并聚焦主体；reset 重算概览并 framing，焦点保留 reset 控件。同一成员/代表作用域的成功刷新保留仍属于新 P 的实际可见 ID，加代表任务后只保留相应诱导无向连通部分，不自动加入新基线或新任务；刷新保持视口，失败保持旧数据/S/视口。显式重置重算概览；代表不变而成员变化时，仅重置 S、检查和旧动作并重新 framing，保持画布、全屏、活动详情及其 inert/滚动锁。代表变化才按链切换替换行和画布。自动合并、拆分或代表变化使已聚焦控件消失时，由稳定列表层恢复至存活链入口或列表控件；没有条目和筛选控件时回退到带可访问名称的列表区域，不能落到 BODY；已有详情和列表外焦点不被抢走。打开详情时刷新不抢焦点，消失入口使用原关闭回退。详情、附件面板、请求及 locale 生命周期保持，语言变化只重译新控件/计数。

主体检查、完整上游高亮、隐藏上游计数、独立 Details 与平滑曲线由
[任务检查要求](daynight-task-inspection.md) TI3–TI5 拥有，已与当前渐进概览集成。
选择及 Details/关系导航不展开、不布局、不编译几何或移动视口。

## 一致性与读取边界

task-sync 响应中的 Project、任务摘要（含 assignedTo）、完整 properties 与 observedAt 必须来自同一快照；Web 以原子合并的完整摘要集合派生完整项目图与统计。属性按任务版本整体替换并传播缺失键，图绘制投影去掉属性；缓存的升级和失败原子性由[缓存需求](daynight-task-sync.md)拥有。CLI 的按任务查询图仅包含本链及一层外部前置，不作为 Web 完整图输入。身份核验后先显示经完整性与生命周期校验的本地项目摘要，同时后台同步；成功前详情正文和任务写入仍遵守在线准入，运行中计时等待实际服务端样本。图节点和完整详情均保留必填可空的 `assignedTo`、`startedAt`、`completedAt`、`cancelledAt`。
图还提供必填数据库 `observedAt`；未知起止为 `null`，缺失或无效时间字段按协议错误拒绝，不能使用浏览器墙钟或旧元数据补值。
图节点与完整详情还必须提供 `externalDependsOn`，它是完整 `dependsOn` 的无重复外部子集；
共享解码器校验 UUID、去重和子集，缺失或 null 拒绝。图等价及详情新鲜度包含该数组，
仅性质变化也不能继续复用旧内容；仅时钟变化仍保留身份。归组使用普通分量，关系标签和边虚线消费显式性质，节点上下文角色分别计算，
遵守[外部依赖需求](daynight-external-dependencies.md)。
时钟样本在每次成功读取时更新，但其单独变化不得重建图索引、改变画布或焦点。
不得把现有任务列表的多个分页响应当作共同快照，也不得用筛选后的列表推断根节点。

切换项目时立即隐藏前一项目内容；新项目有经过完整性和生命周期校验的本地摘要时先显示该摘要并后台同步，否则显示加载状态。选中不同任务时使用新详情的加载和在线准入边界，不短暂显示其他任务正文；同一资源且同 cacheGeneration 的刷新允许保留上次成功数据。定时读取仅覆盖当前项目摘要同步与打开的任务详情，项目列表、附件列表及内容继续使用各自的刷新和写入后更新机制。页面隐藏不取消已发出的请求；重新可见时若已有图读取则沿用它。手动刷新立即取代当前图读取，自动时钟不会中断它。详情刷新期间保留同一任务的正文；普通后台读取不在标题区插入或移除进度提示，数据未变化时标题、页签和当前正文或附件区域的位置与可用尺寸在请求前、等待中和成功后保持稳定。真实读取错误、必需核对和已知陈旧信息使用限时气泡明确展示，不挤压正文；气泡关闭后，未解决的恢复操作保持可达。已有详情请求未完成时合并一次后续读取。页面隐藏时详情自动读取与排队的后续读取等待，已发出的请求可以完成。首次读取失败后自动重试仍保留错误，直到成功恢复。

当前所选任务从后续任务图中消失时关闭详情，并显示项目级提示。该提示最右侧提供
原生 × 按钮，具有当前语言下的“关闭提示”/“Dismiss notification”可访问名称、可见
键盘焦点，并支持 Tab、Enter 和 Space。关闭立即隐藏整条提示，无需刷新，不改变任务
数据、视图、筛选或已关闭的详情；同一事件不随自动刷新重现，新的任务移出事件仍会
提示。中英文长文本在窄屏自然换行，与关闭按钮互不重叠，页面不产生水平溢出。

节点详情在本挂载项目同步准入后可以显示匹配业务版本的持久正文；每次打开都记录该 opening 的 live GET 要求，包括操作 pending/unknown/核对阻止读取的期间；解除后完成必要 GET，磁盘、写结果或重开前核对不授予本次写权限。cacheGeneration 改变立即清除旧正文、PR 和已加载观察，即使新 GET 挂起或失败也不能显示旧历史。后续按任务摘要业务版本、项目 generation 和恢复需要读取，重复成功时钟 receipt 不触发未变化详情 GET。原始详情的状态、负责人、依赖、外部依赖、阻塞或更新时间与画布数据不一致时，保留差异证据并提示“任务信息已有变化，刷新任务图”，避免局部更新后产生错误的全图统计。ready/blockedBy 从当前完整本地图物化，不能用物化覆盖消除原始差异和禁写限制。详情持久化的版本、LRU 与失败恢复遵守[缓存需求](daynight-task-sync.md)。完整属性同时随摘要和详情读取，属性更新沿用 task 的版本和更新时间；服务端图响应和浏览器图节点不携带属性。摘要缓存中的属性不授予详情正文或写入权限。

项目同步与本地图完整保留实际任务和依赖，不复查存储集合的节点或边容量，也不把读取边界转成项目累计写入配额。完整数据的读取、解析、存储和布局成本随实际集合增长；固定拓扑的生产验收不保证任意 DAG 都具有相同耗时。自然读取、解码或持久化失败不发布部分图或统计，保留明确错误与恢复入口。

## 任务负责人

[负责人契约](daynight-task-assignment.md)拥有原生字段、许可重置和执行状态限制；Web 以严格 nullable `assignedTo` 消费 Task、summary 和图节点，缺字段、错误类型及非法 UUID 均拒绝。负责人参与相等、新鲜度、审阅和全部材料保持检查；姓名与头像来自已授权项目的版本化人员资源，在独立 profiles store 持久化；访问状态来自在线人员清单，二者均不进入 Task 版本或任务记录。

详情的状态与负责人同处 24px 紧凑控制组，之后为平台和 ready/blocked，自动执行靠右。负责人入口同时显示已保存值；选择不同人员或清空直接提交一次精确版本 PATCH，选择当前值关闭菜单且零写入。运行中、陈旧或未决操作禁用入口；成功消费完整 Task，冲突重新读取，未知结果只用 GET 核对。新增交互通过当前字段和控件状态表达规则，保留必要错误、访问状态与恢复入口。

人员菜单使用当前 task-sync 的完整人员版本清单，只补查缓存缺失或内容变化的候选资料；普通打开复用成功或在途结果，失败通过显式 Retry 恢复。只能选有访问权的人；保留的失权负责人可以展示、搜索和筛选。缺少资料或 nullable 姓名显示短 UUID，加载、失败或 unresolved 不能制造失权标记。支持姓名/UUID 搜索、键盘选择、分层 Escape 和关闭后的焦点恢复；菜单跟随滚动、全屏与视口变化，长姓名、头像失败和双语 320px/390px 布局保持可操作。

认证 scope 的人员所有者按项目合并列表、详情和具体人员筛选需求，以每次成功 task-sync 的完整 assigneeVersions 清单验证持久 profiles 内容，只读取缺失或内容版本变化的人员，每批最多 100 个；空需求零请求。合法 nullable 姓名和头像属于完整资料。刷新页面后先完成当前 /me 和项目在线准入，再复用匹配内容；重复打开任务、成功空 delta、graph owner 重挂载和普通菜单重开不重传未变化资料或 data URL 头像。当前 hasProjectAccess 取在线清单，访问状态单独变化不下载相同头像；旧资料不授予项目访问或任务写入。并发需求共享在途读取，同一历史有效结果不因需求变化丢弃；请求记录实际返回的内容 version，避免清单与资料交错读取造成错误标记或即时循环。观察到 generation/userFence 更替或当前在线清单为 null 时，立即撤回旧姓名/头像投影、资格、访问标记和目录 ready 状态；已请求菜单等待在线清单，不将未知清单显示成成功空目录。普通 epoch 更替保留同 userFence 原始内容供新清单验证后复用，发布仍受新 generation 约束；退出、换号、身份失效及项目撤权清理所属资料。失败保留可恢复错误；可信同用户项目 404 按原 ticket 撤回准入，即使菜单关闭或显示需求变化也生效，旧历史拒绝不能撤回新历史。

项目任务列表的全部、分配给我、未分配或具体人员条件按浏览器 origin、当前认证账号及项目独立保存，刷新或离开项目返回时在首次匹配和分页前恢复；缺失记录默认全部，选择全部也保存该选择。`me` 始终解释为当前认证账号。严格校验记录，非法数据回退全部并显示本地化偏好错误；读取或写入失败时保留当前会话操作并显示相应错误，不声称未成功保存。无匹配时保留选中条件并显示现有空态；概览定位清除遮挡条件时保存最终生效的负责人条件。状态、搜索及页码不随此偏好持久化。负责人条件与状态条件在同一任务上按 AND 匹配，在显示分页之前应用；任一条件变更使三个列表回第一页。独立任务只显示自身匹配项；链中任一范围内普通成员同时匹配即保留真实代表作为上下文，展开显示全部范围内普通成员。完整链进度、统计、依赖、ready 和图保持完整索引，概览显式定位可清除遮挡目标的条件。当前缓存持有 typed 摘要及独立的人员资料；升级和原子性由[缓存需求](daynight-task-sync.md)拥有，缺失字段不能按 `assignedTo:null` 补值。

## 自动执行许可与平台要求

`allowAgents` 是独立于状态和 ready 的持久布尔值，详情与图严格读取。新任务为 false，存量迁移为 true；显式任务执行接受两种许可值。Web 开关只表达是否允许自动选取，不选择实际用户、机器、agent 或模型，也不代表 worker 已启动。相邻许可标签采用[UI 语义配色](../ui-design.md#semantic-color-roles)的中性描边角色，开启与关闭保留明确文字；开关本身保留品牌选中色。服务的字段、版本和运行锁由[服务要求](daynight-server.md)拥有；worker与唯一 claim 仍按[worker 要求](daynight-worker.md)独立交付。

确认窗口展示完整任务名称和开启/关闭后果，取消为初始焦点并保留既有模态、Escape、焦点恢复规则。确认冻结目标值、project/task、源状态和精确 version；已知内容或版本变化后重新审阅，不自动换版本。成功响应验证身份、目标许可、未变生命周期与单次版本增长，再安装完整详情并刷新图；错误、冲突和未知结果遵循与状态设置共用的请求归属及读取核对。

requiredPlatform 的 null/三个枚举、缺失拒绝、创建默认与设置/清除由服务要求拥有。详情状态行的下拉框同时展示已确认值和修改入口；选择不同平台先确认当前/目标转换，确认后才以所审阅完整详情的精确版本提交枚举或 null，Any platform 对应清除。当前值不打开确认，取消、Escape、关闭或遮罩关闭不写入并恢复入口焦点。确认或提交期间保持已保存值，概览没有独立平台编辑区或保存按钮。

平台确认与状态/许可共用互斥写入和 GET 核对；后台已知变化使原确认失效，不替换新版本静默提交。成功不改变状态、许可、执行时间、PR 或边，其他操作省略该字段仍保留要求。平台不改变 ready、统计或任务执行授权；不将客户端筛选平台当作实际执行环境证据。

## 暂停展示与解除

暂停状态只来自完整属性中的 `paused=true`。缺席或显式 false 均不显示暂停标识；存在但不是布尔值的属性必须报协议错误，不能显示为未暂停。它独立于任务五态、`allowAgents` 和 worker.phase，既不改变任务状态统计、ready、进度或领取资格，也不表示 Agent 已停止。自动输入的实际门禁由[属性需求](daynight-task-properties.md#暂停自动输入)及[Worker 需求](daynight-worker.md)拥有。

独立任务行、任务链的代表及子任务、项目 Goal 展开区子任务行和图节点各自按原始属性显示自身的暂停标识，已完成任务也保留标识及详情解除操作。Goal 的项目弹窗、独立页及全屏中，已准入的嵌套 Task 详情显示该 Task 自身标识；恢复或跨资源打开的链弹窗与图节点显示暂停数量及各自标识。Goal 详情不通过子任务列表重复显示这些标识。暂停汇总只统计 `paused=true` 且状态不是 `done` 的任务；`cancelled` 仍按原属性计入。任务链列表及链弹窗的暂停数量仅统计完整普通分量成员，包含代表任务、排除链外前置；Goal 列表行及整体图只统计直属普通子 Task，排除范围外成员与外部前置；项目概览数量统计完整项目普通 Task，任务列表标题数量统计完整项目中匹配当前负责人筛选的普通 Task，沿用“全部、本人、未分配、指定负责人”的列表匹配语义。各数量均按任务 ID 去重，不受当前分页、列表类别、状态筛选或图的可见范围影响；概览和链数量也不受负责人筛选影响。数量为零时隐藏暂停汇总。概览入口按原任务顺序定位合格集合中的首个任务，沿用已有任务列表、任务链与详情导航。同步状态变为 `done` 时立即移出汇总；状态改为其他允许值后，按保留的 `paused` 属性恢复资格；汇总不新增 Task 状态或改变七项统计与页签未完成数量的含义。

详情在阅读页签之外的公共头部显示暂停区域，弹窗、独立页及全屏一致，概览、讨论、Session 与附件页签切换均保留。区域内显示“已暂停”及单一“解除暂停”按钮；自动执行许可开关保留自身语义。当前已同步的暂停详情且普通任务写入准入有效时允许解除，`in_progress` 本身不锁定该操作。只读、陈旧、pending、unknown 或核对未完成时保持状态可见并禁用提交；缺乏上下文的禁用原因可通过鼠标悬停和键盘聚焦访问。

点击解除暂停直接使用该次审阅的完整 task 和精确 version 提交一次普通 PATCH，body 仅包含 `version` 与 `properties:{paused:false}`。提交期间保留暂停显示并将按钮标记为忙碌，禁止重复和相冲突的任务写入；确认响应后更新详情与项目摘要、标识和汇总。响应须保留任务状态、许可、负责人、平台、计时、claim、依赖与其他属性。冲突重新读取后重新决定，明确失败保留暂停与错误，网络、5xx、协议错误或丢响应只用 GET 核对，不重发请求，也不把后来观察到的解除状态归因于未知提交。详情关闭、切换、身份变化及迟到响应沿用共享会话归属和历史准入；错误与恢复入口使用既有浮动提示层。中英文、键盘、长标题及 320px/390px 布局保持可操作。

相同任务和统计继续复用任务索引，版本大于 `2^53` 不丢精度。实时卡片、独立行及 Goal 子任务行共享[计时需求](daynight-task-timing.md)规定的时间事实，卡片与独立行同时消费项目阈值。

## GitHub 连接设置

项目设置的 GitHub 集成组展示仓库连接、PR 同步配置以及轮询和 Webhook 的独立状态。所有成员可读取这些事实；管理员可发现可用安装、连接或重连、手动切换 PR 同步、设置整数分钟轮询间隔以及确认断开。安装的有效性取决于服务配置的 App 对目标仓库的读取能力，不取决于操作者的 GitHub 账号。私有仓库同步内容按项目权限共享；断开保留已同步数据。

PR 同步默认为关闭，首次连接及显式断开后的重连不自动开启；恢复授权不可用的连接保留先前意愿。开关显示服务器确认值，未连接时不可开启并说明原因；服务或连接不可用时不能开启，但已开启的配置仍可关闭。同步意愿与实际健康独立：关闭时以中性状态说明数据不再更新，历史尝试、成功和错误仍可查看，不将历史错误显示为当前失败。开启后的初始化不妨碍读取已有记录。PR 页及其刷新只读取保存的数据，关闭同步不会清除列表、详情、筛选、焦点或阅读位置。

界面区分服务未配置、未连接、初始化、同步失败、授权不可用和断开；连接成功表示已建立绑定，不表示同步已开启或完成。已有连接在授权不可用或服务未配置时仍可断开。开关写入独立于间隔草稿，忙碌时阻止重复提交，并与其他项目管理操作互斥。冲突或写入结果未知时保留草稿和页面，只读核对而不自动重发；核对未完成时继续持有管理 guard 和原页面所有权。后台身份与权限检查保留编辑状态和焦点；真实身份或权限撤销仍清理旧内容，窄屏仍可操作。

## 任务执行耗时与卡住提醒

图 Task 卡片、独立任务行及 Goal 展开区子任务标题后显示当前执行的耗时：已知起点的进行中任务自动更新，已知起止的完成任务使用持久差值固定结果，待处理、未知起点或完成态未知终点不显示推算值。
图卡片和独立任务行只有在 `allowAgents=true`、进行中且原始毫秒耗时严格超过已保存项目阈值时显示琥珀强调、图标和“可能卡住了”/“Possibly stuck”，保留进行中状态；完成后撤下提醒。
`allowAgents=false` 的进行中任务仍实时显示耗时，超过阈值也不显示提醒文字、警告样式或可访问提醒含义。
可见格式区分不足一分钟、分钟、小时和多天，向下取整只改变文字。原有按钮可访问名称保持，图卡片和独立行的精确起止、阈值和提醒含义通过描述与提示提供，不逐秒播报 live region。
子任务行仅展示自身耗时，提示不包含阈值或卡住提醒，保留原按钮名称、状态、排序、详情及展开交互；短标题后紧随耗时，长标题和多天耗时在 390px 窄屏自然换行且无横向溢出。链汇总不冒充个体耗时，卡片保持 220×96/136 几何、Details、检查、展开、虚线和选择强调；时钟与阈值变化不重建图布局或移走焦点。
服务端样本与单调接收时间成对构成页面共享时钟；运行耗时和完成距今消费者共享调度，隐藏页暂停，恢复可见立即更新并沿原图读取重新校准。
本机墙钟不决定执行提醒，服务端采样至接收的网络/解析延迟仍是估计精度边界。完整数据和项目设置规则由[计时需求](daynight-task-timing.md)拥有。

Task、链与 Goal 的完成时间表达何时完成，与执行耗时并列但不代替耗时；Goal 自身事实与子任务进度独立，详情保留 Goal 自身精确完成时间；项目 Goal 展开区的成员各显示自身完成时间。事实、范围、相对文案和精确时间访问由[完成时间需求](daynight-completion-time.md)拥有。

## 描述与附件引用

显示当前语言的“暂无描述”。标题和仓库地址继续作为文本显示。Markdown 表格与
代码块在各自区域横向滚动，长描述在 320px 下换行，页面不产生整体横向溢出。

Task 概览和 Goal 详情的非空描述使用一致的浅灰细边框、圆角和内边距包围整个阅读内容；
独立页、弹窗和全屏一致，窄屏缩小内边距。空描述沿用现有占位样式，Steps 与附件 Markdown
不增加此边框。

描述中的相对链接和图片以当前任务附件根为基准；附件 Markdown 仍以文件所在目录
为基准，路径不能越过任务根。普通主键激活不带 query/hash 的有效相对附件链接时，
激活现有附件页签、通过同一个附件控制器选中文件并将预览带入焦点。链接保留真实
预览 URL；修饰键、非主键、上下文菜单、绝对/协议/根相对 URL、独立 fragment 以及
query/hash 链接保留现有 URL 策略与原生导航。本文不要求生成 Markdown 标题锚点。

只有完整分页清单才能判定文件缺失。加载、清单失败、非法路径、确认缺失与预览
失败分别显示；适用时提供重试。描述导航不能建立第二个清单或预览所有者。切换
任务、关闭详情及鉴权/资源失效取消旧请求，晚到响应不能改变当前身份；同路径覆盖
继续遵守附件 revision 与刷新规则。详细要求由[任务阅读要求](daynight-task-inspection.md)
TI8–TI11 与 TI15 拥有。

## 附件区域

附件页签位于任务公共标题下，与概览并列；左右分屏在 320px 窄屏继续保留。左侧是
目录树、刷新与上传，每个文件条目右侧“…”菜单中的删除先打开完整路径确认框，

优先处理 Escape，取消不改变文件或当前预览。概览保留描述、关联 PR、
关系与元数据。隐藏面板不参与键盘导航，切换页签保留选择、目录、预览和上传草稿；
切换 task/project 则重置页签和旧身份状态。每次选择一个文件，默认目标路径为该
文件名，用户可以修改为多层相对路径；相同路径直接覆盖。目录由完整文件路径形成。
加载、上传、删除及预览错误局部展示，续页失败保留已读取文件并明确标记列表
不完整；用户可以重试或手动刷新。切换 task、文件或关闭详情时，过期请求不能覆盖
当前选择。覆盖成功及刷新发现同路径 `updatedAt` 变化时重新读取所选内容；删除
当前文件清空预览，删除其他文件保留正在阅读的文档与位置。

Markdown 按 CommonMark 和 GFM（包括表格）渲染，`mermaid` 图块与描述共享静态
图表、错误隔离、源码、安全及局部滚动规则；原始 HTML 作为文本显示。相对

HEAD 成功不能证明实际内容已经绘制。预览没有独立弹窗、会话或隔离执行机制。

`noopener noreferrer`，不改变来源详情。完整页面通过现有完整分页清单确认精确

相对资源及文件接口。附件路径页面展示完整 Task Detail 并定位附件，复用其概览、状态、关系、任务操作及

## 部署与测试隔离

日常部署继续使用 `deployment/localhost`，完整应用一并启动，正常重建保留项目及任务数据。测试使用独立的 `deployment/dev-ci`，复用相同生产镜像构建和转发配置，在专用项目、端口、数据库、卷与网络中执行；不修改日常 localhost 环境。

测试正常完成、失败或取消均清理本次资源，其他运行和日常数据保持可用。清理失败必须使验收失败，并保留诊断与原始测试结果。子命令进程组在主进程退出后
仍归当前 run 管理，清理必须终止遗留后代；中断恢复只接受已有回执的有效 run ID，
并保留原始回执。Go 与 web 的覆盖率规则不变。

源码构建使用固定 Node/pnpm 依赖生成真实页面，缺少产物时 Go 构建必须失败。
Docker 构建完成相同流程，宿主机只需 Docker；最终运行镜像不依赖 Node。HTML、
task-sync、Worker 观测、Worker 配置与最新详情 HTTP 响应禁用缓存；受身份和生命周期保护的本地持久缓存遵守[缓存需求](daynight-task-sync.md)。哈希静态资源使用长期 immutable 缓存。未知 API 返回
JSON 404，缺失资源、资源目录与未知页面形状不得回退到 SPA HTML。已登记页面形状
中的无效 ID 沿用 index 加前端未找到页面的行为；附件原始路径守卫先拒绝非法路径。
