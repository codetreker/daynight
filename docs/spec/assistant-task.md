# 助手任务

助手任务记录一个用户交给助手的持续或一次性工作。它独立于项目 Task、Goal、Worker 执行 claim、Steps 和 Thread，不进入项目任务列表或 Worker 调度，也不需要项目任务的完成状态。

本文拥有通用服务端行为。具体应用的评估器、Worker 托管循环、CLI 和网站分别由其模块实现；服务端登记有效不等于助手或监控正在运行。[设计](../design/assistant-task.md)说明数据与接口，[认领合同](../design/assistant-task-claims.md)定义凭据、恢复与跨 Worker 转交。

## 归属与生命周期

用户创建助手任务时提供名称、目的、范围、持续或一次性类型、接手策略和初始手册。`application` 为空表示普通任务；非空应用标识在同一用户下唯一。通用模块不为 Watchdog 增加特例。

任务属于创建用户，该用户及其所有未删除助手可以读取登记、手册、修订和工作记录。其他用户不得读取或修改。Bot 身份通过 `X-Daynight-Bot-Id` 传递；服务端同时核验用户凭据、Bot 归属和删除状态。同用户的 Bot 共享用户权限，Bot 身份用于协作，不提供对同用户恶意进程的隔离。

任务状态为 `active`、`paused` 或 `deleted`。用户可以暂停、恢复和删除。暂停保留认领，允许续约和转交，但拒绝负责助手的应用工作写入；恢复后从已有事项继续。删除清除手册、附录、修订、事项、记录、事件、问答和认领回执，后续请求不能恢复已删除材料。删除负责 Bot 使认领失效，保留助手任务材料供接手。

## 认领与转交

认领同时最多属于一个 Bot。无人负责或认领已失效时，Bot 可以按预期版本和代次认领；有效认领阻止新的认领，包括同一个 Bot 更换身份重领。拒绝的 `claim_held` 返回负责 Bot、代次和期限。

负责 Bot 每 60 秒续约，租约固定为成功认领或续约准入时间之后 5 分钟。令牌由使用它的客户端预先生成并持久化，服务端只保存摘要。续约保留令牌、绑定操作和代次。持有者、代次、令牌或有效期不符时返回 `claim_lost`，不得提交工作写入。

用户可以释放或转交，负责 Bot 可以用当前凭据执行同样操作。转交立即废止旧凭据、推进代次并指定目标 Bot，未结束事项的跟进助手在同一事务中随之变更。事项身份、外部操作身份和既有记录保留，不因接手重复消息或报告。

转交进入有 5 分钟租约的 `pending` 状态。目标 Worker 发现登记后，绑定自己预先保存的令牌，再立即成功续约后才工作；无需再次请求用户同意。绑定不延长租约或推进代次。目标离线、尚未绑定或租约失效时不能声称工作正在运行。

认领、转交、接手和释放推进代次；释放后保留代次。公开的版本与代次使用精确十进制字符串。每个认领类操作使用预存 UUID `operationId`，其成功回执与业务结果原子保存。重复身份和相同指纹返回历史回执及独立的当前认领；不同指纹冲突。未知结果只读核对原操作，404 不证明回滚，不许可自动换身份重发。令牌、摘要不得出现在公开结果、日志、事件或记录中。

## 手册与经验

手册由 Markdown 正文和应用定义的结构化 `rules` 组成。手册版本只追加，当前版本明确可读。应用通过 `ValidateRules(old, new) (widens bool, err)` 校验不可越过的边界并判定是否扩大直接动作；未注册应用只允许空规则。

负责 Bot 可以引用工作记录追加手册附录，同时留下 note 记录和通知。附录只提供经验参考，不参与可执行规则，不能扩大直接动作。用户可以修改或删除附录。

负责 Bot 可以提交新的正文、规则、原因与证据记录作为修订提案。提案保留基准手册版本、`widens` 和后续决定。规则越界时直接拒绝；遇到相同规则的已拒绝提案时返回提示，供助手判断是否有新证据。新证据的判断不转化为自动批准。

只有用户可以同意、修改后同意或拒绝提案；携带 Bot 身份的决定请求一律拒绝。同意时生成新手册版本，修改后同意仍须校验应用边界；拒绝保留原因。回退复制选定历史版本的正文和规则到一个新版本，不改写历史。当前手册变化与提案决定须遵守预期版本，不能覆盖并发修改。

## 事项、记录与问答

事项保存应用定义的键、episode、状态、类别、跟进 Bot 和应用私有状态。通用模块保存这些事实，应用拥有异常分类、直接动作和复发规则。更新使用版本和认领条件，转交不能清除应用私有状态中已发出的操作身份。

工作记录只追加，区分事实、推测、动作、未知、问题、回答和备注。记录可关联事项、引用其他资源，并按服务端时间和 ID 排序分页。同用户的非负责助手可以留下按用户要求介入的行动记录，同时通知负责助手；这种记录权限不授予手册或应用工作修改权限。

Bot 可以向负责助手或打开事项的跟进助手提问，关闭事项使用当前负责助手。服务端保存问题、发送提问事件并追加 question 记录。当前负责 Bot 回答后保存 answer 记录并通知提问方；转交前尚未结束的问题由新负责 Bot 承接，保留原提问目标 `toBotId`，用 `answerBotId` 明示实际回答者。问答截止时间固定为创建后 5 分钟；过期仍未回答的问答在下一次读取或事件拉取时转为 `timed_out`，通知提问方无回应。超时不伪造结论，不新增服务端调度器。

## 事件与关注

事件属于助手任务并指定目标 Bot，保存类型、负载和 pending、delivered 或 expired 状态。Worker 拉取待投递事件并在自身 Session 接收成功后按原操作身份确认 delivered；经应用判断已失效的事件可以确认 expired，不能伪造投递时间。确认指纹包含结果状态，相同操作不能改成另一结果。事件确认幂等，不能因确认重试重复改变投递事实；事件过期不代替用户查看或提案决定，关注状态仍独立。服务端不替 Worker 发送 Session 消息。

新异常报告、升级、直接处理结果未知、待决定提案、问答无回应、认领被接手或失效需要用户关注。直接处理成功、附录新增、事项解决、定时触发不点亮关注。用户已查看时可以清除普通关注，待决定提案在用户作出决定前持续保留。事件已投递不等于用户已查看。助手列表计数及网站呈现由其对应模块消费这些事实。

可选定时触发最小间隔为 1 分钟，触发计算和执行属于持有认领的 Worker；暂停时不触发。服务端保存经过校验的触发配置，不新增后台调度器。

## 一致性与验收

写入使用调用方的预期版本或明确的认领条件。权限、Bot 删除状态和租约在锁等待之后及提交前仍须有效。跨表变化和成功操作回执要么一起提交，要么一起回滚；提交结果未知须保留为未知。列表和记录使用游标，每页最多 200 项，跨用户或改变筛选条件不能复用游标。

正常 API 验收顺序驱动真实认证、Server、DAO 和 PostgreSQL，检查创建、认领、续约、转交、绑定、附录、提案决定、回退、记录分页、事件确认与问答的返回内容及后续读取。core 验证规则和拒绝；HTTP 验证解析、错误码及调用边界；service 验证事务协调和完成语义；独立真实 PostgreSQL 验证并发认领、绑定竞争、租约与锁等待、旧令牌拒绝、回执原子性及用户隔离。测试入口和证据边界遵循[测试规则](../writing_tests.md)。

## 网站操作

创建、转交与记录筛选使用统一原生选择外观。选择负责助手保留原生必填验证和禁用的空提示；转交目标排除当前负责助手，确认前不提交。长名称保持完整选项文本且不造成页面横向溢出。

助手工作区显示助手任务列表、待处理数与负责助手。无人负责和认领失效计入
列表待处理；暂停、等待接手和负责中分别显示。用户可以创建提供初始手册的
普通助手任务，在详情查看认领及续约时间，并指定负责助手、转交、暂停、恢复、
释放或删除。删除确认明确包括手册、附录与工作记录。

工作手册展示正文、结构化规则、可编辑或删除的附录和全部修订历史。用户可以
同意、修改后同意或附理由拒绝提案；扩大直接动作的提案单独标明。回退须确认，
并创建新版本。工作记录按事项分组，支持事项、类型和作者筛选及分页；证据链接
打开相应记录。桌面和手机均可使用键盘访问操作，无横向页面溢出。

后台刷新保留阅读及编辑状态。用户开始编辑或确认的版本不会因轮询而改变；
冲突需重新核对，未知写入结果需先读取，不能自动重发。负责助手的聊天在输入区
附近显示待决定提案和未解决升级；看过通知不能移除尚未处理的升级。

Watchdog 开启入口要求选择负责助手。预置能力不可用时显示真实失败；等待助手
绑定、认领失效或 Worker 不可用不能被描述为监控正常运行。预置与运行机制由
Watchdog 应用提供。
