# 任务执行耗时与卡住提醒需求

本文定义任务执行耗时、项目提醒阈值及其界面消费者的可观察行为。
[架构](../design/daynight-task-timing.md)拥有存储、时钟与界面机制。
任务起止事实、数据库图时钟、项目阈值设置及实时卡片、独立任务行和 Goal 子任务行共同实现本页行为。
行为验证遵循 TT6 的真实服务、CLI 与生产 Web 验收边界。

## TT1：计时含义

执行耗时是最后一次实际进入 `in_progress` 到当前时间或进入 `done` 的墙钟时间。
进行中的任务持续显示耗时；完成时固定结果。早先尝试不累加，普通字段编辑不重置计时。
计时不表示 CPU 时间、人工有效工作时间或持续收到进度信号的时间。

状态由 `task set-status` 在 todo、in_progress、done 间设置，普通元数据更新没有 status。
同状态先核验精确版本并保持计时；实际进入 in_progress 开始新尝试，实际退回 todo 清空两端；
in_progress→done 保留可空起点并写终点，todo→done 仅写终点，耗时未知。
历史 proposed→todo 迁移只归类状态，保留已有起止时间，详见[状态要求](daynight-task-status.md)。

## TT2：起止时间与一致性

服务端生成 `startedAt` 与 `completedAt`，客户端不能提交或修改它们。
实际进入 in_progress 记录真实开始，进入 done 记录真实完成；修改标题、描述、依赖和 PR 属性保留起止时间。
状态、时间和任务版本在同一事务提交。版本冲突、无效转换、未完成前置、权限拒绝、取消或数据库失败均不能留下部分计时更新。

完成后的耗时不随时间、后续字段编辑、页面刷新或服务重启增长。
公开资源保留可空起止字段：新建、尚未执行及缺失历史事实的任务使用 `null`。
迁移不得从 `createdAt`、`updatedAt`、部署时间或页面首次读取时间推算起点。
缺少真实起点时，后续耗时展示不得推算时间或触发提醒。迁移后的旧执行任务完成时记录真实终点，但起点仍为 `null`。
完整任务、分页和 ready 资源以及图节点都返回这两个必填可空字段；图顶层返回读取任务与统计后的数据库 `observedAt`。
CLI/Web 读取器严格区分明确 `null`、缺失字段和无效时间，JSON 保留原值；仅图时钟变化的读取保持图与索引身份。

## TT3：项目提醒阈值

每个项目有独立的正整数分钟阈值 `executionWarningMinutes`，默认 `60`，旧项目通过迁移获得相同默认值。
项目设置页提供有明确分钟单位的编辑框、保存、取消及保存状态。保存后的值跨客户端、刷新和服务重启保持一致。
修改项目 A 不影响项目 B，也不改变任务的开始或完成时间。

项目成员可读取设置，仅项目管理员可修改。非成员沿用项目资源隐藏规则。
修改须使用读取时的精确设置版本；过期提交返回冲突，即使数值恰好相同也不报告成功。
成功的同值保存保留设置版本与 project.updatedAt；实际变化增加设置版本并更新 project.updatedAt。
设置迁移保留历史项目的创建与更新时间。完整 Project 的 settings 在创建、读取、列表、图与设置修改结果中一致，
CLI/Web 无损保留超过 `2^53` 的嵌套正 int64 版本，缺失数据不能补默认值。
缺失、`null`、非整数、零、负数、超出支持整数范围及未知字段必须返回明确错误。
未提交或取消的草稿、明确拒绝均不覆盖消费者使用的权威值。冲突或权限变化后读取 Project 与成员，
展示当前值和角色，由编辑者重新决定，不自动覆盖或重发。网络、协议或 5xx 使 PATCH 结果未确认时，
必须先核对 Project 和成员再允许另一次修改；核对失败明确阻止 Save 并提供读取重试。
取消请求或离开路由不证明服务回滚。用户/项目隔离和既有前台身份核验规则同时适用。

## TT4：实时显示与提醒

任务处于 `in_progress` 且已知起点时，Task 卡片自动更新耗时。
仅当任务同时满足 `allowAgents=true`，且未舍入的实际耗时**严格大于**本项目已保存阈值时，显示醒目的
“可能卡住了” / “Possibly stuck” 提醒。恰好达到阈值时不提醒。
`allowAgents=false` 的任务仍实时展示耗时，超过阈值也不显示提醒文字、警告样式或可访问提醒含义。
阈值从 `60` 分钟变为 `90` 分钟后，已运行 `75` 分钟的任务立即重新判断为未超时；改回 `60` 后恢复提醒。

提醒同时使用强调色、图标与文字，并提供含耗时及阈值的可访问说明。
保留原有状态和耗时；提醒只表示可能需要关注，不自动改变状态或宣告执行失败。
完成后移除提醒并保留最终耗时，即使完成耗时仍超过阈值。

实时计时不能依赖浏览器墙钟是否正确。页面保持打开时无需手动刷新即可跨过提醒边界；
隐藏页面停止无用更新，恢复可见时立即按最近服务端锚点和单调差值更新，并通过既有图读取重新对齐。
显示时钟仍受服务端样本传输与处理延迟影响，不声称消除网络延迟；执行计时不使用本机墙钟。身份通过核验后可先显示本地摘要，但实际同步样本到达前不显示运行中耗时或可能卡住提醒；已完成耗时仍按持久端点计算。最近刷新标签只在实际成功同步后显示，概览近期分类的暂时本机时间遵守[缓存需求](daynight-task-sync.md)。
卡片计时不触发布局、平移、缩放、选择、展开或键盘焦点变化。

## TT5：展示与资源覆盖

图中 Task 卡片及独立任务行共享耗时含义和提醒规则。
Goal 展开的子任务列表在每条标题后以时钟图标和低强调色显示该任务自身耗时：已知起点的进行中任务实时更新，
已知起止的完成任务固定显示最终差值。`allowAgents` 不影响耗时展示；`todo`、未知起点或完成态未知终点均不显示耗时。
短标题后紧随耗时，长标题或可用空间不足时自然换行，桌面及 390px 窄屏下多天耗时、状态和行操作保持可读且无横向溢出。
子任务耗时复用项目共享时钟和双语格式，不能逐行增加定时器或网络读取；其提示只包含耗时，提醒继续由图卡片和独立任务行拥有。
计时文字不参与子任务按钮的可访问名称，也不逐秒播报；状态、排序、详情、Goal 展开及键盘焦点保持原有行为。
任务链汇总代表多个任务，不将根任务耗时冒充整条链耗时。
完整任务资源、图任务资源和相关 CLI/Web 读取器保留它们需要的计时与项目设置字段。
不新增 CLI 设置修改命令，也不改变紧凑人类列表原有的字段选择。

保持 `220×96` 紧凑和 `220×136` 可展开卡片几何，保留独立 Details 操作、标题、自动执行许可、依赖检查、选择强调和展开控件。
中文、英文均覆盖耗时单位、阈值、提醒、设置说明及失败反馈。
不足一分钟必须与未知耗时可区分；分钟、小时、多天和长标题在窄屏中保持可读。
精确起点、已知终点和已保存阈值通过提示与 aria-describedby 提供，保留原卡片/独立行可访问名称，不逐秒播报 live region。
耗时使用语义 time，英文显示 `< 1 min`、d/h/min，中文显示“不足 1 分钟”、天/小时/分钟；显示单位向下取整不改变原始比较。
交互原型覆盖普通、进行中、允许与未允许 Agent 的超阈值任务、完成、未知历史、长标题、窄屏、加载、错误、空结果及设置保存状态。

## TT6：验收边界

- 10:00 开始、10:45 完成的任务固定显示 45 分钟；编辑、刷新与重启后保持不变。
- 重复或过期生命周期请求不能重置起点或改变已提交结果；存储层的新进入替换旧起点，不累加早先尝试。
- 确定性时钟验证 `allowAgents=true` 的进行中任务在默认阈值下，59:59 和 60:00 不提醒，60:01 提醒；显示单位舍入不改变判断。`allowAgents=false` 的进行中任务超过阈值仍仅显示耗时。真实服务和浏览器另行验证实际阈值跨越及两种许可下的展示。
- 同一打开页面中的自动推进、后台恢复和阈值保存均能更新判断，不改变图布局和焦点。
- 管理员保存、成员只读、非成员隐藏、权限变化、冲突、无效输入、失败、取消与项目隔离均通过真实服务验证。
- 新任务、旧数据及缺少起点的任务不产生推算耗时；完成任务不显示卡住提醒。
- Goal 子任务行在两种自动执行许可下均跨分钟自动推进，完成值固定，待处理及不完整起止隐藏；双语、长标题、多天耗时及 390px 窄屏保持可读，计时不改变按钮名称或焦点。
- 使用真实 PostgreSQL、实际 CLI 读取与生产 Web 资产完成整体验收，并通过所改模块的现有检查和覆盖率门槛。
- 设计与实现代码不能替代真实运行时的整体验收。
