# 产品介绍与公开入口

本文拥有 Daynight 推广页、公开演示及其与登录和工作台之间的体验要求。
[设计](../design/daynight-landing.md)说明页面、路由与身份的职责划分；
[鉴权要求](daynight-auth.md)继续拥有会话、邀请、CLI 设备授权和私有资源准入，
[看板要求](daynight-web.md)拥有工作台内的项目与任务行为。

## 目标与受众

首次访问者应能理解 Daynight 是什么、能解决什么问题，以及如何开始使用。
页面面向已经使用编程 Agent、需要持续推进项目的开发者，以及协调多人和 AI 工作的团队。
共同价值是让人和现有编程 Agent 围绕同一套任务工作，把需求、方案、依赖、参考材料
与交付依据放在可持续读取的地方。

页面通过具体工作情境建立理解。个人能够看到保存上下文和判断下一步的价值；团队能够
看到共享进展、识别阻塞与核对交付的价值。主要转化路径是先体验演示，再接入自己的项目。

## 页面与地址

| 地址 | 要求 |
| --- | --- |
| `/` | 公开产品介绍；匿名和已登录访问均可阅读，不因已有会话跳离介绍。 |
| `/#demo` | 进入同页的免登录交互演示。 |
| `/login` | 独立登录入口，使用当前服务提供的实际登录方式。 |
| `/projects` | 认证后的项目列表和工作台入口。 |
| `/setup` | 公开上手指南，沿用零 API 请求要求。 |
| 原有项目、任务、附件及账户路径 | 保留各自页面和直接访问能力；需要登录时恢复原目标。 |

首页、登录、工作台、API 与 CLI 继续使用同一服务 origin。推广页的主行动是体验演示；
演示后的“开始使用”进入 `/setup`。导航另有登录入口，已确认身份时显示“进入工作台”
并进入 `/projects`。公开内容不等待身份核验、项目读取或任务同步。

登录页聚焦身份验证，保留品牌、简短说明和返回产品介绍的入口。缺少回跳目标时登录成功
进入 `/projects`；已有会话访问登录页时直接进入有效目标或工作台。已提供但不合法的目标
必须明确拒绝，不能把非法目标悄悄当作默认目标。完整规则由[鉴权要求](daynight-auth.md#web-交互与状态)拥有。

## 产品叙事与可信内容

首屏必须同时说明产品类别、服务对象、实际结果和下一步行动。正文覆盖反复解释上下文、
难以判断进展与阻塞、缺少完成依据等具体困扰，并将每个困扰对应到可见产品能力。

可陈述能力包括任务与依赖、Web 阅读和进度、CLI、公开 Agent skill、任务文档及附件、
交付与验收记录。接入说明使用现有 Codex、Claude Code 和 GitHub Copilot CLI 工作方式，
完整操作交给 `/setup`。文案不把规划中的 Worker、常驻调度或恢复能力当成已交付功能，
不使用缺少依据的客户数量、评价、效果比例、价格或认证信息。

## 交互演示

演示使用明确标记的“团队邀请功能”示例，全部交互在前端本地发生，不读取或改写真实项目。
提供三个场景：

1. 上下文：阅读需求、方案和验收条件，理解执行者可以获得什么材料。
2. 下一步：选择任务、查看前置条件，并沿依赖定位阻塞原因。
3. 完成依据：对照已确认的要求查看完成后的示例验收和交付记录。

示例当前进度与完成后的示例快照应有明确区别。任务身份、状态、依赖和提示必须自洽：

| 任务 | 当前状态 | 前置条件 |
| --- | --- | --- |
| 需求与范围 | 已完成 | 无 |
| 交互与技术方案 | 已完成 | 需求与范围 |
| 邀请接口 | 执行中 | 交互与技术方案 |
| 邀请界面 | 可开始 | 交互与技术方案 |
| 邀请邮件 | 等待前置 | 邀请接口 |
| 整体验收 | 等待前置 | 邀请接口、邀请界面、邀请邮件 |

点击场景、任务、文档和交付记录时更新所选内容与可访问状态。依赖入口能定位对应任务。
使用本地数据的演示不伪造网络加载与失败过程，不展示样稿身份切换、模拟登录或预览路由。

## 语言、布局与文档信息

完整页面、导航、演示资料、FAQ、错误和无障碍文案提供英语与简体中文，沿用
[语言要求](daynight-web-i18n.md)的检测、保存和失败处理。切换语言保留演示场景、任务、
文档与记录的选择和操作焦点，不重发身份或业务操作。

页面使用现有品牌的深蓝、浅色工作区与靛紫色，并在桌面、768px、390px 和 320px 下
保持阅读与操作。长英文和窄屏不造成整页横向溢出；键盘可到达操作，场景标签支持方向键，
有可见焦点，FAQ 可用键盘展开，减少动画偏好有效。

原始构建 HTML 提供可识别产品价值的默认标题、description 与分享信息。公开页根据当前
语言更新标题、文档语言、description 和相应分享文案。此要求不承诺本地化服务端渲染或
搜索排名，不包含访问分析、转化率测量或新的站点发布系统。

## 可观察的完成条件

| 编号 | 条件 | 验证 |
| --- | --- | --- |
| LP1 | 首屏能回答服务谁、做什么、下一步；个人与团队的困扰与能力对应。 | 独立阅读文案，对照当前已交付能力检查。 |
| LP2 | 首页在身份等待或失败时仍完整可读；已有会话也能阅读介绍，导航进入正确入口。 | 可控身份等待、匿名、成功与失败用例；真实构建浏览器检查。 |
| LP3 | 三个场景、六个任务、文档、记录、依赖定位与 FAQ 可操作，示例状态与依赖一致。 | 组件与浏览器逐项操作，检查可访问选中状态。 |
| LP4 | 两种语言均完整，切换保留演示选择和焦点，已有语言偏好有效。 | 类型、目录、状态保持与浏览器检查。 |
| LP5 | 公开页、独立登录、工作台和现有直达路径、邀请及设备授权保持连续。 | 按鉴权要求验证目标保留、错误、退出和历史导航；原型不替代集成结果。 |
| LP6 | `/setup` 的直达、刷新、复制、语言与前台恢复仍为零 API 请求。 | 保留公开指南的网络断言。 |
| LP7 | 四种宽度及长英文无整页横向溢出，键盘与减少动画行为有效。 | 生产页面截图、几何和键盘操作。 |
| LP8 | 原始构建和当前公开页具备一致的默认/本地化元数据。 | 检查构建 HTML、DOM 及实际嵌入产物。 |
| LP9 | Web 与 Go 的既有检查、覆盖率和资源清理门槛保持。 | 运行文档命令；结果绑定实际源码、构建与环境。 |

组件测试证明页面与状态行为；嵌入 Go 服务的浏览器验证证明实际路由与构建组合。
受控身份提供方的协议结果、真实上游登录和真实访客转化具有不同证据范围，验收记录应明确区分。
