## 目标与范围

Task 可以保存设计文档、架构文档、图片及 HTML mockup 等附件。文件内容由独立
存储模块保存，元数据存在 PostgreSQL。Web 可以管理、预览和下载，CLI 可以管理
并直接读取内容。现有 project/task、依赖图和 review 行为保持原有职责。

| 编号 | 要求 |
|---|---|
| FA1 | 存储模块以 bucket 和真实相对路径提供写入、读取、删除的抽象接口；当前交付本地磁盘实现，接口可以用于其他文件用途。 |
| FA2 | 每次上传、覆盖或删除一个文件；同 task、同完整相对路径直接覆盖。保留路径结构，目录从文件路径生成。 |
| FA3 | PostgreSQL 保存 task 归属、相对路径、内容类型、大小和时间；附件操作不修改 task 的状态、依赖、version 或 updatedAt。 |
| FA4 | 通过作用域明确的 HTTP 接口流式上传、读取和删除单个文件；写入结果和错误明确返回。 |
| FA5 | 文件元数据支持完整遍历的游标分页，Web 和 CLI 根据路径构造目录树。 |
| FA6 | Web 在同一服务 origin 管理附件，通过固定 task 预览路径显示内容并保持相对资源引用；HTML 按可信项目代码在 iframe 中执行。 |
| FA7 | CLI 提供 task attachment put/list/read/remove，复用现有服务配置和 project 选择。 |
| FA8 | CLI read 输出原始字节；二进制传输、输出背压、取消、超时和错误传播有明确语义。 |
| FA9 | 本地附件根目录有明确配置和持久化部署；测试使用独立目录、数据库及卷，清理仅影响本次资源。 |
| FA10 | 文件与 PG 元数据不原子是已接受的已知问题；当前不实现一致性协调、补偿或恢复，普通操作错误仍明确暴露。 |
| FA11 | 通过实际存储、真实 PG、安装 CLI 和生产浏览器验证范围内行为，保留现有验证门槛和证据归属。 |
| FA12 | 交付范围不包含目录上传、整目录替换、历史版本、唯一对象 key、预览会话、独立预览 origin、Service Worker 或后台对账系统。 |
| FA13 | 附件业务层先按规范化 project UUID 隔离，再以规范化 task UUID 前两个字符分片，完整 task UUID 保持独立目录；公开 URL、API/CLI 参数和附件 path 对分片透明。 |
| FA14 | 存量附件通过显式停写维护迁入新布局；完整清单与内容核验通过后才发布。计划记录完整准备后才公开操作身份；公开前失败可重建计划，公开后的中断可按同一操作续作。迁移保留目录、有效字节及业务元数据，冲突和无法解释的状态明确失败。 |

## 文件寻址与目录

附件标识为 `(taskId, path)`，不另设客户端必须使用的附件 ID。`path` 是 task 内
完整的相对路径，例如 `docs/design.md`。相同名称位于不同目录时可以共存。

路径区分大小写，使用 `/` 分段，保存原始合法 Unicode 拼写。拒绝绝对路径、空段、
`.`、`..`、反斜杠、控制字符和非法 UTF-8；URL 按段编码并仅解码一次。非法路径
必须拒绝，不能自动清理成其他有效路径后执行写入或删除。

目录不单独登记，没有空目录操作。最后一个文件删除后，相应目录从展示树中消失。
文件和目录不得占据同一位置：存在文件 `docs` 时，不能创建 `docs/design.md`；
存在 `docs/design.md` 时，不能用文件覆盖 `docs`。命名规则的本地实现必须与目标
文件系统实际行为一致；LocalStorage 准备根目录时验证大小写能力。Linux 要求
大小写敏感存储，不支持时拒绝启动。macOS 原生开发允许使用普通大小写不敏感
目录，但不承诺大小写变体共存；实际文件系统能解析、目录项拼写却不精确匹配的
路径必须拒绝，不能读取、覆盖或删除另一个逻辑文件。写入别名冲突返回现有
`path_conflict`，且不新增附件元数据。大小写共存的真实存储覆盖由 Linux gate
及显式 APFS 专项验收承担。

任务附件使用固定 bucket `task-attachments`，业务存储路径为
`<canonicalProjectId>/<taskShard>/<canonicalTaskId>/<path>`，其中 `taskShard` 是规范化 task UUID
的前两个字符，最多 256 个值。分片由附件业务层统一计算，通用存储继续只接受 bucket/path。
每个 task 保留完整 UUID 目录；同一实例跨 project、同一分片跨 task 的同名附件互不影响。

原始附件相对路径必须先校验，再添加业务前缀；不能用前缀掩盖原本非法的绝对盘符或穿越写法。
客户端继续使用原有 project ID、完整 task ID 和 task 内相对路径。上传、列表、读取、预览、
下载、覆盖与删除的公开 URL、参数和响应 path 均不包含分片；既有 HTML/Markdown 相对资源
保持有效。空父目录清理可以逐层移除空 task、shard 和 project 目录，但保留 bucket 和所有非空兄弟目录。
项目目录是业务组织，不另设操作系统沙箱；权限仍由项目成员准入提供。没有 bucket 管理 API 或可配置分片。

## 元数据与修改

附件元数据包含 project、task、path、contentType、sizeBytes、createdAt、updatedAt。
数据库以 `(task_id, path)` 为主键，不保存派生的 bucket、存储 key 或历史记录。
覆盖保留创建时间并更新文件属性和更新时间；删除后重建使用新的创建时间。

内容大小来自实际保存结果。上传端提供内容类型，无法识别时使用
`application/octet-stream`。内容读取响应的长度必须来自本次实际打开的存储对象，
不能用可能过期的 PG 大小声明另一份内容的长度。

所有 task 状态均可操作附件。附件变化只刷新附件区域，不改变任务图或 task 版本。
project 不存在、task 不属于该 project 或目标附件不存在时返回作用域内的 `404`。

## HTTP 操作

设 task 前缀为 `/api/v1/projects/{projectId}/tasks/{taskId}`：

| 方法与路径 | 成功行为 |
|---|---|
| `GET /attachments` | 返回元数据页和 nextCursor；空列表为 items: []。 |
| `PUT /attachments/files/{path...}` | 请求体为一个文件的原始字节；新建返回 201，覆盖返回 200，响应为文件元数据。 |
| `GET /attachments/files/{path...}` | 返回原始字节及内容类型，供下载和 CLI 读取。 |
| `DELETE /attachments/files/{path...}` | 删除指定文件，成功返回 204；缺失附件返回 404。 |
| `GET /preview/{path...}` | 以浏览器展示方式提供 task 内的指定文件和相对资源。 |

未提供上传 Content-Type 时使用 application/octet-stream；非法或重复的 MIME header
返回 400。内容 URL 的普通 query 不参与文件名，预览相对资源可保留缓存参数。

文件列表使用现有 limit/cursor、items/nextCursor 约定，按 path 的确定顺序分页；
cursor 绑定列表类型、project 和 task。分页不保证多次请求属于同一快照。
CLI 完整列表只在所有页面读取成功后输出；Web 可以保留已加载页，但不能把失败
当作文件不存在。文件读写不经过仅接受 JSON 的请求体或响应解析通道。

参数错误返回 `400 invalid_input`，资源缺失返回 `404 not_found`，文件与目录占位
冲突返回 `409 path_conflict`，存储或
PG 操作错误返回 `500`，沿用现有 code/message/requestId 错误结构。流式响应已经
开始后发生错误时终止传输并记录关联错误，不在文件末尾追加 JSON 错误或成功文字。
失败或结果未确认的写入不得自动重试。

## Web 管理与预览

Task 详情在共同标题下提供“概览”和“附件”页签，每次打开详情或切换 project/task 时
默认进入概览。概览保留描述、关联 PR、状态、关系及元数据；附件页签独占文件管理与
预览。页签具有可访问的 tablist/tab/tabpanel 关联，支持方向键、Home/End 及原生
Enter/空格操作，隐藏面板不参与键盘导航。页签切换保留已选文件、目录展开、列表与
预览状态和未提交上传；切换任务或项目释放旧身份状态。描述 Markdown 的普通主键
无 query/hash 相对附件链接激活同一个附件页签与控制器，选中并聚焦已有预览；描述
相对资源从任务附件根解析，附件 Markdown 的资源从文件所在目录解析。链接保留
真实预览 URL 和浏览器的修饰键、非主键及上下文菜单行为，完整规则由
[任务阅读要求](daynight-task-inspection.md) TI8–TI10 拥有。

附件页签在所有支持宽度保持左侧文件列表、右侧预览，中间以竖线分隔；320px 宽度也
保留左右关系，不产生页面级横向溢出。左侧包含文件树、刷新与单文件上传，可以独立
滚动。单文件上传区域默认收起，点击“上传文件”入口或以键盘激活后展开，再次激活
可收起。收起时保留已选文件、目标路径和校验状态；切换页签保留展开状态，切换
任务或项目恢复默认收起。预览标题展示完整路径的可访问名称、元数据、下载和新标签页打开
操作，长路径不能遮挡操作。左侧每个文件条目右侧提供“…”菜单，选择“删除”后打开
显示完整相对路径的确认框；只有明确确认才发送单文件删除请求。确认框高度受视口
约束，超长路径由正文独立纵向滚动，用户能够到达路径末尾；标题、语言选择与
取消/确认操作保持可访问。目录只组织文件。
菜单与确认不改变当前文件选择；取消、Escape 或提交前点击确认框外部不删除文件，
初始焦点位于取消。菜单或确认框中的 Escape 只关闭当前层，焦点返回原文件操作入口；
成功删除原条目后移到仍可用的附件控件。确认处理中明确显示进度并阻止重复提交及
冲突写入，结果返回前保持确认框。错误显示现有诊断与 requestId，允许明确重试或取消；
界面保留最近已知清单与预览，不承诺 K1 下服务端文件未改变。隐藏附件页签、切换
任务或关闭详情清除尚未提交的删除状态；身份变化遵守既有请求隔离。菜单和确认
在中英文、窄屏、长路径下可访问，切换语言保留目标及进行中请求。上传目标初始为文件名，可修改为多层相对路径；MIME
按目标路径确定，相同路径直接覆盖。修改成功后刷新附件数据与相关预览；手动刷新
发现所选文件的 `updatedAt`
改变时，内容也重新读取。多个文件独立修改、独立生效，不承诺目录级原子更新或
多文件内容快照。

附件模式的对话框正文、分屏及预览外壳不承担纵向滚动。右侧内容过长时只有一个纵向
滚动区域：Markdown、文本/JSON/源码及大图由预览正文滚动；HTML/PDF 由占满可用
正文高度的原生 iframe 内文档或浏览器阅读器滚动。表格和代码块可以在局部横向滚动，
不能另设受限高度而引入第二个纵向滚动区。内容放得下时不显示多余滚动条。预览
标题与操作没有独立纵向滚动，左侧滚动不移动右侧内容或阅读位置。

视口高度较小时压缩公共标题与内容间距，844×390 下仍保留可用正文、文件选择、
全部预览操作和关闭入口；不得通过恢复外层详情滚动来包住已滚动的右侧预览。
概览有自己的正文滚动布局。独立完整阅读复用相同内容渲染和显式尺寸约定，不改变
固定服务预览 URL、文件传输或权限模型。

列表逐页读取，续页错误保留已读取文件并明确标记结果不完整，提供重试；描述导航
与文件树共享这份清单，只有完整读取后才能判定引用不存在。清单加载、请求失败、
非法或上越路径、确认缺失及预览失败保持不同的可见状态。列表、写操作和预览拥有
独立加载与错误状态。project/task 或文件选择变化及卸载会取消过期
请求，晚到结果不能覆盖当前身份的内容。没有附件与尚未选择文件是不同状态；
删除当前文件后清空其预览；删除其他文件保持当前预览、已加载文档和阅读位置，
覆盖后刷新当前内容。附件表单与同源 frame 中的
Esc、Tab 操作
继续遵守任务详情对话框的焦点约束及关闭恢复规则。

| 类型 | 展示方式 |
|---|---|
| Markdown | CommonMark 与 GFM（含表格）渲染，原始 HTML 作为文本；`mermaid` 图块按[流程图要求](daynight-task-inspection.md#markdown-流程图)展示静态流程图、局部错误和源码，图片节点在绘制前明确拒绝且不阻塞后续图块；按文档目录解析相对图片和链接，独立 `#fragment` 保留。 |
| 图片 | 图片展示。 |
| PDF | 浏览器 PDF 展示。 |
| 文本、JSON、源码 | 保留换行的文本展示。 |
| HTML | 普通 iframe，固定预览路径，支持其相对 CSS、JS、图片及正常脚本交互。 |
| 其他类型 | 文件信息和下载。 |

图片使用原生图片加载及错误重试；HTML/PDF 在原生 iframe 请求前检查 HEAD 可用性，
失败明确展示并可重试，不读取 HEAD 的 JSON body。原生 frame 负责后续正常资源
请求；HEAD 成功不能作为实际 frame 内容已绘制的验收证明。

预览入口为 `/api/v1/projects/{projectId}/tasks/{taskId}/preview/{path...}`，
不增加专用预览 token、预览会话、子域名、端口或 Service Worker。HTML 被视为
可信项目代码，运行在主站同源环境；该方案不提供上传脚本与主应用之间的权限隔离。
已接入的[鉴权需求](daynight-auth.md)在附件请求入口检查登录态和项目成员关系，
继续保留这一可信代码执行约定。

## 独立页面完整阅读

内嵌预览在“下载”后紧邻提供“在新标签页打开”链接，带外链图标、可访问名称、
`target="_blank"` 和 `rel="noopener noreferrer"`。链接使用当前所选 project、task
和完整大小写敏感路径，正文仍在加载时也指向当前文件。打开链接不关闭或重置原详情、
附件页签与文件选择。

`/projects/{projectId}/tasks/{taskId}/attachments/{path...}` 打开完整 Task Detail，
默认激活附件页签并选中文件；页面同时提供概览、状态、关系、PR、元数据及已有任务
操作。详情标题栏也提供保留当前任务、页签和附件选择的新标签入口。基础任务路径、
`tab` 查询参数、任务/页签/文件地址同步及浏览器历史由
[独立任务详情要求](daynight-task-inspection.md#独立完整任务详情)拥有。

两种详情展示共用 `TaskDetailReading` 及同一附件状态所有者。左侧目录树、刷新、
默认收起的上传区域和文件菜单，右侧预览、路径、元数据、下载与新标签操作沿用同一
完整附件面板。目录排序、展开折叠、选中样式、上传覆盖和删除确认保持一致。独立
详情中的文件选择及成功上传所产生的选择记录在地址中；弹窗中的选择只更新面板内
状态。同任务的页签与文件切换保留目录、附件位置及上传草稿，切换任务或身份沿用
既有隔离规则。删除所选文件后保留其地址，完整清单确认缺失时显示缺失状态；删除
其他文件保留当前阅读状态。

ID 沿用规范 UUID 解析，附件路径按段编码并仅解码一次，遵守既有完整相对路径校验；
编码分隔符、路径穿越和非法路径不得成为有效导航。已知页面形状支持 GET/HEAD，
其他方法返回 `405` 与 `Allow: GET, HEAD`；未知路径不回退到 index。符合页面形状
但 ID 无效时，沿用 UI 约定返回 index，由前端显示未找到页面；原始路径守卫先于
路由规范化拒绝非法附件路径。

完整分页清单才能确认新路径的元数据或文件缺失；初始失败、续页失败、非法路径、
确认缺失和内容预览失败分别展示，提供适用重试。刷新期间保留同任务、同路径最近
已确认的元数据。独立页面不依赖来源页内存、临时对象 URL、额外元数据 API 或预览
凭据，文件内容继续读取既有 raw/preview 接口及其作用域检查。上传和删除沿用现有
单文件请求、错误可见性及 K1 边界，不改变 task 版本或图。

Markdown、文本/JSON/源码、图片、HTML、PDF 与不支持格式继续使用既有展示规则。
Markdown 保留 CommonMark/GFM、转义原始 HTML、文档目录相对资源及同一 Mermaid
流程图行为；独立入口的图块错误、源码、异步切换和窄屏局部滚动与内嵌预览一致。
可信同源 HTML 保持脚本交互、相对 CSS/JS/图片和 fetch。第一方文案、HTML lang 与页面标题跟随
同一语言状态，附件内容按原文显示。独立详情使用普通浏览器键盘行为，不安装详情
弹窗的 frame 键盘桥；内部删除等确认窗仍承担自己的原生模态交互。

完整详情外壳按实际标题与页签高度为附件面板分配剩余空间，不使用固定标题高度扣减
frame。两种展示在 320px 窄屏保持左目录、右预览，左侧独立滚动；文档、文本与图片
由共享预览正文纵向滚动，原生 HTML/PDF 由拟合正文的 frame 内文档或阅读器滚动。
844×390 短视口仍可操作标题、目录与内容，长路径完整值保持可访问；外层页面不包围
已滚动的 frame 或正文再产生第二条纵向滚动条。

## CLI

```bash
daynight task attachment put <task-id> ./design.md --path docs/design.md
daynight task attachment list <task-id> --tree
daynight task attachment list <task-id> --json
daynight task attachment read <task-id> docs/design.md
daynight task attachment read <task-id> images/mockup.png > ./mockup.png
daynight task attachment remove <task-id> docs/design.md
```

操作均支持现有 `--project` 选择；省略时复用仓库关联。`put` 的来源必须是一个
本地普通文件，省略 `--path` 使用来源文件的 basename；打开后通过实际句柄检查
文件属性，再通过该句柄上传，不上传目录或推导目录批次。上传内容类型根据最终
目标逻辑路径的扩展名推导，未知扩展名使用 `application/octet-stream`。
`--path` 是 text 选项，接受 `--path=value`；`put/read/remove` 接受 `--` 结束选项
解析，保留前导连字符的位置路径，所有选项须放在终止符之前。
`list` 默认显示元数据，`--tree` 按目录组织，`--json` 输出完整元数据数组；tree 和
JSON 为互斥展示方式。`read` 原样输出字节，不附标签、转义、JSON 或额外换行。
错误输出 stderr，沿用成功 0、参数错误 2、操作失败 1。

传输与 stdout 必须支持二进制及背压，沿用共享取消、信号和总期限。文件内容使用
有界缓冲流，不套用元数据 JSON 的单响应和累计字节上限；元数据继续遵守原有预算。
读取途中失败时 stdout 可能已有不完整内容，必须非零退出。元数据列表的完整输出
要求不扩展为文件 read 的全量缓冲要求。stdout 的等待、取消、超时和管道关闭均须
明确结束本次拥有的输出执行，命令结束前回收辅助资源；清理失败保留原因。
原有帮助、版本和其他命令的依赖隔离继续有效，首次非空字节输出前不启动输出辅助
进程。

## 存量布局迁移

旧 `task-attachments/<taskId>/<path>` 布局通过同一服务二进制的显式离线维护命令切换。
维护命令只读取数据库和存储根配置，不启动 HTTP、鉴权客户端或自动 SQL 迁移。
操作方停止全部服务及直接数据库/文件写入者，保留旧镜像并捕获配套备份；保持停写直至迁移核验结束。

初始 manifest 和 planned 状态须在独立未发布命名空间中完整写入并同步，再原子公开为正式操作目录。
正式操作目录出现时必须已经有完整的初始记录对。公开前失败或进程中断不移动附件，可重新 plan；
遗留的未发布准备目录不属于可续作操作，也不能阻止创建新计划。普通错误只清理本次未发布尝试，
不扫描清理其他尝试或正式操作；公开后的失败保留正式记录并要求按同一 ID 续作。

迁移清单保存已核对的 task→project 归属、业务元数据摘要、全部 task 根和目录项（含空目录），
以及普通文件大小和 SHA-256。已知 task 中未登记的普通文件整体保留并列明，不补写元数据；
未知归属、已登记文件缺失或大小不符、符号链接、特殊文件和目标冲突必须明确拒绝。
新计划先检查已有操作：未完成操作返回 `resume_required`，已完成操作返回 `already_migrated`，
两者均报告 operationId；前者要求显式 resume，后者要求用同一操作验证。公开 bucket 缺失和
零元数据行不能掩盖已暂存的内容，已完成新布局也不能被再次解释为旧布局。

旧 bucket 先进入同根暂存目录，再按 task 重组目标目录，避免合法的 project/task UUID 同名冲突。
完整目标清单和内容校验通过，且新的独立快照证明业务元数据未变后，才发布最终 bucket。
正常 plan/apply 进行三次完整内容摘要读取：计划清点、移动前复核、发布前目标核验。
显式 resume 使用同一操作身份与清单解释实际位置；既不覆盖或合并冲突目录，也不以目录名猜测迁移完成。
真正空存储可产生可核验的空计划与完成回执。普通进程中断的续作和配套备份回退属于布局转换职责，
不承诺任意文件系统或硬件断电下的跨介质事务。

维护过程不重写业务表、历史 schema 迁移或 task_cache_epoch。回退使用匹配旧镜像及配套备份，
恢复写入后的回退需要另行保全新增数据。具体命令与持久化状态由[架构](../design/daynight-task-attachments.md#存量布局迁移)拥有，
操作顺序由[部署说明](../../deployment/localhost/README.md#attachment-layout-upgrade)拥有。

## 部署与已知问题

服务使用明确的本地存储根目录，在接受文件请求前检查目录可用性和写权限。正常
重建或停止保留 PG 和附件数据；dev-ci 使用独立卷，既有定向清理覆盖该卷。
备份和恢复须包含匹配的 PG 元数据与文件目录。停止服务及其他写入方后同时备份
两者；恢复到空卷时，先恢复匹配的 PG 与附件目录，再启动服务。正常停止、重启、
重建以及保留卷的 teardown 必须保留两者；显式删除卷会同时销毁元数据与附件文件。
此流程不修复备份前已存在的跨介质不一致；本次不交付自动备份系统。

**已知问题 K1：文件内容与 PG 元数据更新不具备原子性。** 文件替换或删除成功后，
数据库失败、进程退出或并发操作可能留下内容与记录不一致。普通操作错误必须返回，
写请求可能已经产生变化；不能承诺失败一定保留旧内容或自动恢复。

K1 保持已接受的边界。普通附件操作不增加用于修复 K1 的跨存储锁协议、事务协调、补偿、恢复、
状态台账、后台扫描或对账服务，也不把跨存储回滚或故障后一致性作为验收门槛。
显式布局迁移的操作清单只解释目录转换与续作，遇到预存不一致时暴露错误，不修复业务元数据。

## 验收归属

FA1–FA14 的验收覆盖存储、HTTP、CLI、Web、部署、布局迁移和跨层集成。各组件测试
验证正常行为、路径拒绝、普通 IO 失败及错误传播。真实进程与 PostgreSQL 验证
持久性，实际安装 CLI 验证二进制字节，生产浏览器验证相对资源和可信 HTML 交互。
Go 和 Web 既有覆盖率、race 及原生 CLI 检查持续有效。

Web 前端 mockup 复用实际组件与 CSS，通过内存元数据和本地文件展示交互，不需要
Go/PG。它及本地现有浏览器探针验证前端状态、视觉和焦点。实际服务验收在原生和
生产容器两个目标上由已安装 CLI 与页面交叉读取同一 task 文件；二进制按原始字节
比较，PDF 必须在 compositor 截图中出现预期色块，HTML 相对资源通过可见交互验证。
验收通过正常 UniAuth 登录取得会话或 PAT，API 数据准备和安装 CLI 复用当前用户
凭据，凭据只写私有夹具元数据。图场景保持只读，但 `refresh-staleness` 仅允许一次已登记 fixture task/file PUT，挂起真实上传响应并跨自动读取验证状态保留；附件场景和[双语需求](daynight-web-i18n.md)的 `language-state-preservation` 仅允许精确 fixture task/file 的 PUT/DELETE，后者检查切换期间操作只执行一次。JSDOM 不具备布局，
不能证明隐藏元素的浏览器焦点行为。

Go 的独立安装 CLI 旅程覆盖超过一页的附件列表、原始内容、拒绝及 requestId、同根
重启和完整 task 不变，并把附件根目录实际删除纳入清理 gate。Web 完整运行复用
一次安装产物，保留源码、tarball/entry 摘要、浏览器、生产镜像和进程/组回收证据。
组合机制与证据边界由[验收决策](../../.agents/notes/implemented/testing/2026-10-21-task-attachment-cross-layer-acceptance.md)拥有。

每份运行证据归属其测试源码、PR 和 CI；文档校验或设计审查不证明运行时已实现。
项目隔离验收在同一服务、数据库和存储根内创建两个 project，并用固定 UUID 覆盖同分片与不同分片 task；
与两个独立部署的卷隔离分别观察。迁移验收保留真实旧目录，覆盖 project/task UUID 同名、空目录、
未登记普通文件、各阶段中断、发布后回执缺失、冲突拒绝及重入；核对完整目录、字节摘要和不变元数据。
K1 的记录和范围一致性需要检查，但其修复不属于 FA11 的交付条件。
