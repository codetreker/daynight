# 创建前原生模型能力发现

## 目标

用户调整新助手设置时，可以读取指定 Worker、Provider 和工作目录下实际原生模型及每模型推理强度。普通名字创建不触发额外全量模型查询。查询不借用现有助手 Session，不发送业务输入，不创建持久助手，也不修改原生配置文件。

## 能力与默认

模型标识、显示名称、别名、隐藏标记、推理强度与原生默认强度来自各 Provider 的实际目录。不能用共同模型清单或统一 effort 枚举替代原生能力，也不能按 Provider 整体禁用 effort。未知的默认模型与失败的目录读取分别表达；目录可用但默认未知时仍返回模型列表。

同一 Provider 使用 Worker 最终有效配置及来源；切换 Provider 不继承另一 Provider 的模型和参数。显式模型只覆盖模型，仍需核对继承的有效 effort。当前明确配置不兼容时返回选择错误，不能跳过该配置。默认来源区分 `explicit`、`local`、`cloud`、`native` 和 `unknown`；原生强度未给出具体默认时保留 `null`，不猜测 medium 或 high。

## 有效性与资源

查询使用[只读通道](worker-readonly.md)的用户、Worker、请求和连接代次绑定。结果额外绑定 Provider、规范化 cwd、有效配置、工具目标、检查后选择身份和本次目录快照。首次按需准备取得检查证明本身不得使请求断线；捕获选择后，其身份或相关配置变化时不得返回陈旧结果。切换目标、配置变化、取消或断线后的迟到结果不得进入新请求。分页只能继续同一查询及仍有效的短期快照。

读取按需执行。单次模型操作预算 25 秒，转发期限 30 秒；目录浏览保留自身的 10 秒转发期限。分页快照保留 30 秒，最多 8 个。原生目录最多 500 项，单页最多 100 项和 64 KiB；超限明确报错。隐藏模型默认排除，但默认解析和选择核验使用完整目录。

短命探测必须由现有进程所有者管理。取消、超时及异常后仍回收子进程；清理拥有独立有限期限，不能把请求结束当作进程已停止。停止未确认保留原始所有权证据、真实清理失败和重试责任，后续探测与 Worker 退出均须处理它。

## 验证

回归覆盖三 Provider 映射、未知默认、无 effort、显式/本地/云端/原生来源、切换 Provider 和模型、隐藏项、分页、能力变化、旧配置及旧连接、权限、网络、输出上限、超时取消和清理失败。真实原生探测、受控 SDK 响应、HTTP/WebSocket 和 UI mock 的证据必须分别报告。列表失败只影响需要该列表的调整路径，不改变既有默认创建或已有助手冻结配置。
