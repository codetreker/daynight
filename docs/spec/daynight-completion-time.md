# 已完成任务、任务链与 Goal 的完成时间展示

## 目的与范围

用户浏览项目的任务、任务链和 Goal 时，需要直接知道各项何时完成，并判断完成的先后与距今多久。近期完成项使用相对时间，较早完成项使用实际日期时间。

本规格覆盖项目中“任务 / 任务链 / Goal”三个列表及展开后的任务行，以及 Task 和 Goal 详情中的精确完成时间。Goal 子任务的列表时间归属于项目 Goal 展开区；Goal 详情不重复列出子任务。Goal 详情无论以弹窗、独立页或全屏形式打开，适用相同要求。

本规格定义完成时间展示，不改变完成、取消、重新打开、依赖、Goal 归属、筛选、排序、分页和近期可见范围。执行耗时继续表达一次执行用了多久，完成时间表达何时完成。依赖图节点、CLI 列表及其他资源的时间展示不属于本次列表需求。

## CT1：完成时间的含义

只有当前状态为 `done` 的项展示完成时间。

| 对象 | 完成时间 |
| --- | --- |
| 普通 Task | 自身真实的 `completedAt` |
| Goal | Goal 自身真实的 `completedAt`，表示它被标记完成的时刻 |
| 任务链汇总行 | 该行所汇总的成员全部为 `done` 时，取这些成员中最晚的真实 `completedAt` |

Goal 的完成事实不由子任务进度推导：所有子任务完成不替代 Goal 自身的完成时间；Goal 已完成也不把未完成的子任务显示为完成。

任务链的成员范围必须与该行进度一致。按范围展示的链段，仅使用该范围成员；外部依赖、范围外成员和代表任务均不能代替实际汇总集合。只有当前范围全部完成时，链汇总行才显示完成时间；范围内已完成的任务仍各自显示自身时间。

缺少真实 `completedAt` 的完成任务或 Goal 保留已完成状态，隐藏完成时间。链内任何成员缺少完成时间时，该链汇总行也隐藏完成时间。不得从创建时间、更新时间、其他成员时间或页面读取时间推断缺失事实。

完成时间不要求存在执行开始时间。直接进入 `done`、没有 `startedAt` 的任务，只要完成时间已知，就必须显示完成时间。

重新打开后隐藏完成时间；再次完成后使用新一次真实完成时间。同状态操作与标题、描述等元数据编辑不改变完成时间。`cancelled` 不显示为完成，即使它保留了历史 `completedAt`。

## CT2：近期相对时间与较早绝对时间

相对时间按真实经过时长划分，`N` 向下取整。一天按 24 小时计算，一星期按 7 × 24 小时计算。

| 距完成时长 | 中文文案 |
| --- | --- |
| 不足 60 秒 | 刚刚完成 |
| 满 60 秒、不足 60 分钟 | N 分钟前完成 |
| 满 60 分钟、不足 24 小时 | N 小时前完成 |
| 满 24 小时、不足 7 天 | N 天前完成 |
| 满 7 天，完成年份与当前本地年份相同 | MM-DD HH:mm 完成，例如 11-05 14:30 完成 |
| 满 7 天，完成年份与当前本地年份不同 | YYYY-MM-DD HH:mm 完成，例如 2025-11-05 14:30 完成 |

绝对时间使用浏览器本地时区，列表精确到分钟；省略秒数不改变真实完成时间或排序。是否跨年同样按浏览器本地时区判断。

中文与英文表达相同含义，英文使用自然的单复数、相对时间及本地化日期时间。两种语言都必须能明确辨认这是完成时间。

本规格的一星期切换阈值只控制文案，不改变现有按本地自然日计算的近期可见范围。“显示所有”仍按既有规则提供较早记录；不能为了显示绝对时间而自动改变筛选条件。

## CT3：列表中的可读性

Task 和 Goal 的完成时间位于各自行的次要信息区。完整任务链与范围任务链的汇总完成时间位于左侧标题下方的次要信息区，与负责人或子任务数及 Worker 信息并列，不占据进度与状态之间的右侧列。项目 Goal 展开区的每个成员显示自身完成时间。完成时间使用低强调样式，保持可读对比度；链汇总时间及 Goal 自身完成时间在收起、展开时位置一致且仍可见，展开后的各完成任务独立显示自身时间。

有执行耗时的任务同时显示两者，并通过“完成”含义明确区分。例如同一任务可以显示执行耗时“2 小时 10 分钟”和完成时间“3 小时前完成”。完成时间不会替换标题、状态、负责人或已有操作。

中英文、长标题、长负责人、Worker 信息、长耗时、跨年日期，以及 320px 手机宽度下都保持可读。空间不足时可自然换行，不横向溢出，不遮挡行操作。鼠标和键盘仍能打开原有详情或展开列表，增加时间信息不能破坏这些操作。

没有可展示项时保持现有空态；读取中及读取失败时沿用既有加载、错误和重试行为。时间信息不能把失败伪装成空结果，也不能把尚未读取的完成时间显示成“刚刚完成”。

## CT4：精确时间与可访问性

已知完成时间的 Task 和 Goal 详情提供始终可读的完整本地日期时间，包含年份并精确到秒，明确标识为完成时间。相同资源在弹窗、独立页及全屏详情中表达一致。

列表完成时间可通过鼠标悬停或键盘聚焦查看相同的完整精确时间。触屏用户可以通过现有详情入口读取 Task 或 Goal 的精确完成时间，不能只有鼠标悬停这一种访问方式。

任务链汇总时间的精确值同样须能由鼠标、键盘和触屏获得；具体交互形式由方案设计确定。精确值使用 CT1 的同一成员范围与完成事实。

时间说明在读屏访问中可辨认；自动推进不连续播报相对时间，也不改变既有任务入口的名称或焦点。提示的出现和关闭不改变列表展开状态。

## CT5：时间推进与状态更新

页面持续可见时，完成时间文案无需手动刷新即可自动推进，跨过分钟、小时、天和一星期边界后展示对应形式。页面从后台恢复可见时，重新显示符合当前时间的文案。跨本地年份后，旧记录的绝对时间补充年份。

单纯的时间推进只更新受影响文案，不重排列表，不关闭详情或提示，不重置筛选、页码、展开、滚动、焦点和草稿。真实状态或成员变化按既有规则更新；完成时间同步使用新状态及其对应事实，不能残留上一次完成时间。

完成时间展示不得改变保存的状态或时间字段，不通过生命周期写入维持文案更新。已有执行耗时、完成排序与近期过滤继续各自遵守原有规则。

## CT6：验收条件

以下条件均以普通项目成员可读取的真实资源为基础，中英文界面都适用。

| 编号 | 操作或输入 | 预期结果 |
| --- | --- | --- |
| A1 | 在任务、完整链、范围链、Goal 列表及项目 Goal 展开行中查看已完成项 | 各已完成项使用 CT1 的真实时间；链汇总时间在标题下方次要信息区，收起和展开时位置一致且仍显示时间 |
| A2 | 距完成分别为 59 秒、60 秒、59 分 59 秒、60 分钟 | 依次显示“刚刚完成”“1 分钟前完成”“59 分钟前完成”“1 小时前完成” |
| A3 | 距完成分别为 23 小时 59 分 59 秒、24 小时、6 天 23 小时 59 分 59 秒、7 天 | 依次显示“23 小时前完成”“1 天前完成”“6 天前完成”和绝对日期时间 |
| A4 | 已超过 7 天的完成记录，当年、跨年及浏览器本地午夜跨年 | 当年省略年份，跨年包含年份，使用本地日期与分钟精度；跨年后自动补充年份 |
| A5 | Task 无开始时间但完成时间已知；已完成 Task 或 Goal 缺少完成时间 | 前者正常显示完成时间；后者保留完成状态且隐藏时间，不推断历史 |
| A6 | 同一链的部分成员属于其他 Goal，或存在外部依赖 | 汇总只取当前行实际统计的成员；外部成员的状态和时间不能污染该行结果 |
| A7 | 链内全部完成且时间已知；任一成员时间未知；任一成员未完成 | 分别显示最晚成员完成时间、隐藏汇总时间、隐藏汇总完成时间；已知完成成员仍显示自身时间 |
| A8 | Goal 完成但有未完成子任务；子任务全部完成但 Goal 未完成 | 分别显示 Goal 自身时间且保留子任务真实状态、不显示 Goal 完成时间 |
| A9 | 任务或 Goal 重开后再次完成；修改元数据或重复设置同状态；查看已取消任务 | 重开隐藏、再次完成使用新时间；元数据与同状态操作保留原完成时间；取消项不显示为完成 |
| A10 | 鼠标悬停、键盘聚焦、触屏查看精确时间 | 三种方式都能读取包含年份与秒的完整本地时间；Task 和 Goal 详情直接可读 |
| A11 | 同时显示执行耗时、长标题、长负责人、Worker 信息及跨年日期，在桌面及 320px 手机宽度浏览 | 两类时间含义清楚，标题、进度、状态和操作可用，无横向溢出或遮挡，中英文均成立 |
| A12 | 页面驻留跨显示阈值；隐藏后恢复；保持展开、滚动和输入草稿 | 文案自动更新，当前交互状态保持；无需手动刷新或执行写入 |
| A13 | 使用原有筛选、排序、分页及“显示所有”；观察加载、空态与读取失败 | 保持原有语义与行为，不因相对时间或绝对时间展示改变数据集合，不掩盖错误 |

- [Goal 容器需求](daynight-goals.md)定义 Goal 自身生命周期及子任务开始时的状态联动。
- [Web 需求](daynight-web.md)拥有现有列表、排序、筛选和分页。
