# Worker Bot 库存需求

Worker 的 Bot 托管准备不依赖 Git 仓库、Project、Task、claim 或 worktree。`worker run` 的空仓库启动和旧 Task 恢复遵守[Worker 需求](daynight-worker.md)。本地库存提供后续 Controller 执行所需的稳定身份，不表示 Bot 已启动、已同步或可用；完整托管接入前不报告 `assistantHost` 能力。

## 身份与责任

Bot 库存使用 Worker 原有配置根、实例锁及 SQLite 格式，按服务、账号、Worker 和 Bot 隔离。Bot 数量不计入 Task `maxConcurrent`，不改变 Task 终态清理期限、重试次数或资源预算。重新打开数据库必须得到原启动意图，不能因网络结果未知生成另一组执行身份。

首次启动准备在任何 register、ticket 写入或 spawn 之前，持久保存注册、独立执行、Controller、launch 和初始 operation 的身份、恢复上限及私有资料路径。首次注册版本与最新观察版本分别保存；服务端推进版本后，重试仍能使用原请求身份。sessionId 只能来自服务端绑定，不在本地伪造。已绑定 Session 但本地启动证据缺失时，拒绝准备新的执行。

配置与角色一旦冻结，后续观察或 Worker 升级不能改写。角色全文、revision 和 digest 可在首次角色准备时持久冻结；库存不生成模板或发送用户输入。后续执行必须继续验证环境和权限，持久记录本身不是启动许可或进程停止证明。

## 清单对账

必须完整读取绑定 Worker 的全部分页后才能判断缺失。重复 ID 和本地缺失项先经过权威单项读取，不能把分页缺失、读取失败或 404 当成已完成清理。网络、协议、身份或分页错误保留本地责任，并返回错误；不可把失败包装为空清单。

删除投影只包含 Bot、Worker、版本和删除责任，不能用它清空原冻结定义、Session 或执行资料。404 只作为缺失结果返回；清理和删除回执由执行生命周期承担。本地不提供根据清单缺席直接删除库存的操作。

## 验证边界

验证须覆盖：普通目录非交互启动；同一实例的重复 runner 被锁拒绝；空仓库仍保留原 Task 与清理责任；数据库重开复用原启动身份；冻结配置与角色冲突拒绝；分页中断、重复及缺失项核对失败不丢库存；删除精简投影保留责任；旧 SQLite 迁移失败时 schema、版本和原记录原子回滚。

库存和受控 HTTP 测试不证明真实 Provider 启动、授权续期、恢复、删除执行或浏览器交互已完成。
