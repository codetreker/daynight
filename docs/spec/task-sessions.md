# Task Session 需求

本页描述 Task Session 的执行模式和页面行为。Herdr 的[Session v2 协议要求](session-v2.md)另行定义终端内容、控制和归档的生产消费保证。


Session 消息、归档、长轮询、SSE 和 WebSocket 保留各自的协议额度及生命周期，不套用普通 JSON 的 1 MiB 或 15 秒期限。废弃的 `PUT /api/v1/controller-resources/{resourceId}` 不读取上传正文；有效资源继续使用现有 Controller 资源流程。

## 目标与模式

任务执行采用 `herdr` 或 `web` 中的一种控制方式。两者复用现有任务资格、认领、worktree、managed assignment、进度及完成规则。模式在执行开始前确定，同一 claim 不热切换、不双启动，也不因连接失败自动降级。

- `herdr`：worker 通过 Herdr 启动原生终端会话，Task Session 提供只读终端观察和明确授权的控制；Herdr 承载终端通道。
- `web`：worker 直接启动 Daynight controller，由 controller 持有私有原生会话，经 Daynight server 将结构化事件和操作连接到 Task Session。整个生命周期不依赖 Herdr 安装或服务。

模式由 Worker 云端配置的已应用 agentControlMode 决定。首次采纳读取 `~/.daynight/config.yml` 的 `worker.agentControlMode`，缺省为 `herdr`，已有本地 `web` 保持其值；旧服务继续使用本地模式。模式变更仅用于新 claim，原 claim 保持冻结模式、native 配置和执行身份，不提供 repository 级模式覆盖。Codex、Claude、Copilot 均属于两模式的支持范围。Codex Web 使用私有 app-server stdio；Claude Web 使用 Agent SDK；Copilot Web 使用 SDK 连接 Controller 自己启动的私有 headless runtime，不连接 shared runtime 或原生 TUI。

本文件定义要求，不以字段或协议存在宣称运行时已完成。各组件的实际可用性与拒绝行为由[实现设计](../design/task-session-protocol.md)说明。

独立 `daynight controller <provider>` 测试入口复用 Web 会话实现，其用户行为由[独立测试会话需求](controller-test-sessions.md)定义。Test 会话具有独立创建者和执行身份，不属于另一种 Task 模式，也不能替代下述 claim 与 worker 生命周期验收。

## 执行身份与页面入口

服务端保存 claim 的实际模式；支持扩展 Worker 协议的客户端获得显式 mode，旧数据缺字段按 `herdr` 读取。模式与 Provider、worktree、worker、claim 一起冻结，普通摘要或属性 PATCH 不允许改写。新 claim 才能选择新模式；release 后的 task 按普通资格创建新 claim，强制撤回沿用归属清除规则。Web 同 claim 的原生恢复保留已冻结配置与停止证明，Herdr 原生重启使用其当前适用设置。

Task 的 Session 页签按真实会话生命周期自动呈现，不提供常驻执行记录选择器或记录列表刷新行。已有 claim 时按其身份定位真实 Session：活动 Web 执行使用结构化会话，Herdr 使用终端视图；已认领但尚未注册时保持可辨认、可恢复的等待状态，不能用时间最近的旧记录冒充当前会话。任务完成后，主阅读区自动展示该 claim 对应的只读记录，不提供发送、审批回复、设置修改、执行命令、Interrupt 或终端控制。任务完成、会话 draining 与归档 ready 分别判断；pending、failed、unavailable 和读取失败如实显示，保留既有恢复入口，不伪造完整历史。

没有当前 claim 时，可自动呈现最近实际 Session 的只读历史。只有确认任务不存在任何 Session 时才隐藏 Session 页签；首次读取、权限失败、启动待注册或其他未知结果都不能作为无会话证明。任务退回 todo 不删除已有历史入口；仍保留的 completed claim 继续展示其原会话的只读记录；release 后从历史目录读取原会话。原执行记录继续经“附件 → Session 记录”查阅；同一 claim 内恢复保持原 Session 归属，不增加一次可选执行，不同 claim 的记录不合并、不删除。

打开页面、刷新、恢复焦点和传输重连只读取或重新连接原会话，不创建 native conversation、不重发 assignment、不重放用户输入。旧执行记录下拉选择的浏览器缓存不得覆盖自动定位，只清理本功能拥有的选择键。账号、项目、任务、claim 切换及权限撤销严格隔离内容和迟到响应；普通后台检查保持已显示内容、阅读位置、焦点、草稿、显示模式和全屏状态，不因短暂检查隐藏或重挂阅读区。真实身份或生命周期变化沿用相应切换规则。终端的画面和输入准入要求见 [Session v2](session-v2.md#控制与输入)。

## 旧客户端兼容

服务端升级不要求已有 CLI 和 Herdr worker 同步升级。旧客户端继续读写其支持的 Herdr Codex/Copilot 任务，WorkerClaim 响应保持原有字段集合。新客户端能够读取旧服务端未提供 mode 的响应，将其规范化为 `herdr`；使用 Web 或新增 Provider 能力时，客户端和服务端必须均支持对应能力。

混合项目的普通任务列表和详情保持可读。旧客户端无法表示的 Web 或 Claude claim 不出现在其 worker 摘要中，任务本身及其状态、版本、依赖、资格仍保留真实值；这不表示服务端没有 claim。旧客户端不得据此认领、恢复、撤回、清理或修改该执行，服务端必须基于实际 claim 拒绝相关写入。

旧 worker 的执行清单不得隐藏不支持的 claim，以免触发错误恢复或清理；应明确拒绝不完整清单。自动候选发现则跳过无法执行的历史 claim，分页持续前进，不因连续不兼容页阻塞其余可执行任务。普通任务列表不应用这一候选过滤。

## 基础会话交互

Daynight 提交的通知输入通过可选的 `origin: "daynight"` 标记来源；普通输入可以省略来源或使用 `origin: "user"`。来源不改变 Session 的提交权限和原生执行语义。旧输入和旧历史缺少来源时，显示行为保持不变。

时间线中的 Daynight 输入在 Standard 和 Conversation 模式下均显示为一行带图标的“Daynight 通知”（英文 “Daynight notification”），默认折叠，可以用鼠标或键盘展开完整内容及其资源，不显示为用户气泡。刷新、同一 Session 的执行恢复以及归档读取后仍保留该来源和展示方式。来源字段不触发事件投递或额外的 Agent 回合。

Session 与 Task Overview、Attachments 并列，弹窗和独立详情页共享内容。基础能力包括消息、Markdown、reasoning 展开、工具参数/结果/错误、长输出、历史分页、流式合并、滚动跟随、文本草稿及输入法处理。

具有当前项目访问权限的成员可以阅读活动 Session、历史、资源和归档；只有该 Session 持久记录的 owner 可以发送消息、回答审批、问题和表单、停止当前 turn、修改设置、执行命令或刷新原生控制目录。Herdr 的人工输入、取得和维护控制租约、处置初始提交及恢复自动执行同样只允许原 Session owner。项目管理员和通过 Team 继承访问的其他用户只读，当前 Task assignee 不替代 Session owner。非 owner 保留实时内容、分页、资源、显示模式、刷新和全屏阅读，全部执行交互禁用；活动 Session 的只读权限不能被误判为已结束归档。

Copilot 新会话没有原生待办时，初始化及后续空待办读取不得单独产生合成空 todo 条目。已投影待办后清空必须更新同一条目；恢复会话必须投影当前待办，包括空列表，以清除可能保留的旧内容。此规则属于 Provider 投影，不改变 Session 显示模式过滤。

Codex 原生 `sleep` 显示为 `clock.sleep` 等待工具行，开始、完成与恢复历史保持同一条目身份。有效请求时长明确标为请求的最长等待时间，不作为实际耗时或工具结果；缺失或无效时长只显示等待。其他未知原生条目仍显示不支持的诊断。

消息与 reasoning 保留普通换行并安全渲染 Markdown；没有公开正文的 reasoning 不显示空折叠条目，不从加密内容推断正文。正常工具文本保持原始字符、缩进和换行，不将日志重新解释为 Markdown。折叠工具摘要保持单行，显示展开入口、可读工具名、超长省略的输入摘要和状态；预算内的输入与输出保留在展开区，超限内容明确显示截断或显示大小限制。命令摘要去掉一层可确定的 POSIX shell 包装及外层引号，按引号规则还原转义，让实际命令优先可见；不能确定的格式保留原样，不求值或改写命令。此显示规则适用于 Codex 的命令文本及其他 Provider 的 JSON 命令字段，不改变非命令字段、原始输入、输出或审批卡。工具状态使用可辨识的文字，长输入与输出支持局部滚动和键盘阅读，折叠后不挂载重内容。工具完成状态遵守原生字段，不能从自由文本推测成功；原生结果中的不同内容保留，相同摘要与详细输出不重复显示。

原生非交互正文中的 NUL 和孤立 UTF-16 surrogate 必须显示为带说明的可见转义，不能因合法命令输出包含这些字符而停止 Controller。转换覆盖 user/assistant 的 text part、reasoning、工具输入与输出文本、error message、compaction summary 和 todo 正文；同一异常文本段内原有反斜线也须转义，使字面转义与真实非法字符可区分。中文、合法 emoji、换行和 tab 保留。异常消息与 reasoning 使用字面文本展示，不能由 Markdown 折叠反斜线或解释正文标记而混淆转义。条目身份、工具状态、交互请求与响应、操作输入保持原有校验，不得通过通用文本修复放宽协议。

三个 Provider 的实时与历史正文使用同一显示转换。显示副本不回写原生记录或增量缓存；跨 delta 到达的 surrogate pair 在后续累计完整时恢复为正确字符，不重复转义。转义膨胀仍受显示与 wire 预算约束，截断不能切断 Unicode pair 或生成的 escape token，且必须有明确提示；工具的既有截断状态不得丢失。保留范围内的显示可辨认，不承诺超限显示完整无损。真正的持久化、身份和协议结构错误仍须暴露。

自动跟随尊重阅读意图：触屏轻点不能暂停跟随，向上阅读、键盘阅读旧内容和脚注跳转应暂停。消息重排、窗口缩放与历史加载保持可见阅读位置，提供返回最新入口。脚注在各条消息间隔离，表格可以用键盘进入滚动区域。

共享 Timeline 可按调用方选择导出轻量阅读书签，用于同一账号、会话执行代次和 historyEpoch 内的卸载重挂。恢复依据条目与文字锚点，宽度变化不以旧 scrollTop 猜测位置；模式隐藏行、文字消失和历史确认缺失均有明确降级，暂停意图不因布局变化消失。目标尚未加载时保留书签供历史分页定位，读取失败不能把尾页当作原阅读位置；错误身份或 historyEpoch 的书签必须拒绝。书签不包含全量 Timeline、原始 key 集合、DOM 或资源，不要求跨页面持久化；省略此接口的原调用者保持现有跟随和分页行为。

文本草稿在同一浏览器 tab 的刷新与页面切换后可恢复，并按账号、会话归属和执行代次隔离；存储失败不能阻止内存编辑。明确受理回执只清除对应提交版本，不能覆盖提交后的编辑；不确定结果保留草稿且不得自动重发。退出账号、切换身份、执行换代或重新访问被拒绝的会话时清理对应草稿。离开页面后的草稿不承诺即时远程擦除。输入框随内容和宽度变化伸缩并限高，发送完成后的焦点恢复不得抢占审批、其他控件或隐藏页面。

Codex 原生错误必须区分明确重试、明确终止和未知诊断。只有可靠匹配本会话与当前轮次、且 `willRetry === true` 的通知才能中性显示为重试通知；`false` 和原生失败终止仍须可见告警，缺失或非法字段不得猜测为可重试。重试行是发生过的通知，不代表当前网络状态；普通正文、工具输出和 HTTP 成功不能证明恢复，也不能结算轮次、完成任务或触发输入重放。

错误默认显示可读短摘要，原始错误码、message、additionalDetails 等有界技术详情可通过键盘展开；中文、英文与窄屏均保持可读。旧 `native_error` JSON 仅改善只读显示，丢失的重试信息不能补猜，归档不得改写。纯文本、未知错误、其他 Provider 错误、权限失败和取消行为必须保留。

Codex 子代理活动显示为正常的启动、交互或中断操作，未知活动种类使用中性名称，不误报执行错误。操作完成不表示子代理任务完成；默认折叠且不读取或展开子代理会话。已保存的同类误报在能够准确识别时采用正常操作显示，不能推断丢失的操作状态；损坏数据和其他错误仍须可见。

Chatbox 提供文本发送、按原生能力追加、停止当前 turn，以及当前有效审批、问题和表单的响应。原生未提供的能力不显示为可用；不能用排队或中断后重发冒充 steer。停止 turn 不等于完成 task 或停止整个 controller。Claude 工具执行中或回复生成中断后，SDK 合成的固定中断文本不显示为用户气泡，顶层中断以“本轮已中断”表达；恢复原生历史时保持相同投影。普通用户消息、包含该文本的引用与其他内容不受影响。

会话处于 `waiting_input` 且存在当前可回答的交互时，Chatbox 不显示“此会话为只读”。交互卡可见时不另加说明；卡片、`Waiting for an answer` 和禁用的 Send 表达等待回答。当前可回答的卡片不在时间线可见区时，时间线底部提供带请求标题和方向的定位按钮，例如“待处理请求 · Approve Write ↑”。按钮与可访问名称按页面语言显示，鼠标、键盘和触屏均可激活；激活只滚动并聚焦卡片，不代替用户回答。卡片进入可见区或不再可回答后，对应入口消失。存在多个请求时，入口定位按时间线顺序遇到的首个不可见请求。归档、权限失效等真正只读说明与同步、设置待确认、首次输入待受理等提示的既有优先级保持不变；发送、回答、中断和草稿门禁不变。

正常发送、命令、设置、停止和交互回答的提交、投递、受理、后台核对及成功确认全程静默：Chatbox 上方不显示回执文字、spinner、慢等待提示、核对入口或空白占位。超过 10 秒但尚未真正截止的等待仍属于正常过程。设置尚未确认时保留已确认的控件值和既有操作门禁，不能提前宣称目标值已生效。Agent 自身的 Working、Idle、原生询问及真实断连或会话不可用提示独立显示。

真实失败、拒绝、过期、携带错误的回执和真正未知结果必须可见，用可读语言表达具体问题及已知结果；未知不能冒充确定失败，也不能推断未经证实的网络或 Provider 原因。错误长文在窄屏换行，输入和恢复控件保持可用。只有真实未知操作提供既有原操作核对入口，查询不重发输入；核对期间保持错误可见，成功恢复只清除对应操作的错误，其他未解决错误保持。

当前页面仍连续观测的提交与协议初始 `unknown` 分开判断；底层初始状态不能造成误报。页面等待达到现有 30 秒截止、传输失败、明确未知回执，或刷新与恢复后缺少确认依据时，保留未知提示与安全恢复入口，不能无限隐藏异常。页面等待标识不持久化；正常静默仅改变呈现，不改变操作账本、operationId、幂等、后台自动核对、权限、重复发送门禁或草稿提交版本。未明确受理时保留草稿，输入、焦点、选择和阅读位置不因核对改变。回执随页面语言显示，固定英文操作标签不变。


初始 managed prompt 获得原生受理且快照同步完成前，普通网页发送保持禁用，避免用户输入抢先改变任务。初始化期间真实存在的原生审批可单独响应。旧交互、已解决的请求以及换代前的请求不可再次提交。

Codex 命令审批正文先显示完整原生命令，保留 shell 包装与换行，随后显示工作目录和原生说明。文件修改审批列出同一原生请求涉及的文件、改动类型及可用 diff；没有可读改动时保留原生说明。请求写入目录、网络及额外权限等决策信息不得丢失。正常正文不显示 thread、turn、item 身份、时间戳、环境 ID 或原生按钮与执行规则字段；未知内容保留可读原文，超过既有长度上限时明确提示截断。此投影只改变正文，不改变标题、可选动作、决策映射、交互身份、过期或原生确认流程。

Claude 审批正文按工具显示纯文本：`Bash` 先显示完整原生命令，再显示 `description`；`Write` 显示 `file_path` 和保留真实换行、引号的内容；`Edit` / `MultiEdit` 显示路径及逐条替换前后片段。其他工具逐行显示“参数名: 值”，字符串保留原始换行，嵌套对象可使用紧凑 JSON。额外参数、空字符串、`false`、`0` 和 `null` 不因格式化丢失；文件操作的额外参数在正文前显示，超长正文沿用既有上限并明确提示截断。已知工具输入形状异常时保留原有可读内容；NUL 或孤立代理项等不能直接进入 Session 文本的值保留 JSON 转义表示，不得导致审批丢失或会话停止。此转换仅改变 `detail`，不改变标题、动作、原生工具入参、权限模式和交互确认流程。

已处理与已过期的交互卡保留标题和本地化状态，并提供默认折叠的“查看请求内容”（英文 “Show request”）。展开后只读显示审批的原始 detail、问题及选项、表单字段名；不挂载回答控件，也不显示本地输入值或推测协议未记录的回答结果。长内容在限高区域内换行并可用键盘聚焦滚动，窄屏不得横向溢出。折叠与展开沿用时间线的跟随和阅读锚点规则；只读归档同样可以查看这些请求。

图片/文件输入、历史编辑、fork、Team 和跨本机原生历史会话发现不属于基础交付。Daynight 已登记的独立 Test Session 列表由 [Controller 需求](controller-test-sessions.md#session-view)定义。消息内容保留 typed parts 的扩展位置；Timeline 中已有资源按会话权限安全展示，不能将任意本机路径暴露为下载入口。

Copilot 的 model 或 effort 未指定时保留原生默认值，不补造模型或推理档位；Web args 只接受 `--effort low|medium|high|xhigh`。计划审批通过已有 form 提供 `exit_only`、`interactive`、`reject` 与可选 feedback，不启动 autopilot。URL elicitation 与不能投影的二进制资源必须明确报错，不能伪装成完整的可交互内容。

## 启动结果与恢复阻断

共享 Codex Provider 新建会话时，明确指定的 model 和 reasoning effort 必须在接受输入前保存到原生持久会话，即使没有发生任何用户 turn。未指定字段保持原生默认语义，不把目录默认值或显示回退值固化为用户选择。物化空线程被拒绝时，除已核实的原生空历史兼容响应外，必须立即终止，不能用后续设置更新回执代替线程已持久化的证据。设置更新回执仅表示受理，必须进一步观察到绑定原线程、本次更新之后的完整持久设置记录，并确认冷恢复使用的 SQLite 元数据同一行已提交明确字段，才可就绪；旧同值记录、内存设置或显示默认值不能替代该证据。文件身份、实际数据库目录与线程归属必须核实，配置读取、更新与持久化观察共享有界期限，不直接写入原生历史或数据库。明确设置首启要求可读取受支持的原生 SQLite 布局；数据库、行或提交证据缺失不能降级为仅凭历史文件成功，未知布局或损坏必须失败。保存被明确拒绝、回执无效、异步错误、持久证据缺失、超时或断流时，初始化不得宣称成功；关闭本次拥有的进程，保留已经观察到的原生身份，不自动重试保存、发送输入或创建替代线程。恢复继续读取同一原生线程的最新设置，不使用冻结的初始配置覆盖会话内已经确认的变更，也不补写旧线程缺失的历史选择。

Web Task Session 必须提供与当前 claim、Session、executionGeneration 和 controllerInstanceId 绑定的启动观察及独立恢复阻断。明确原生拒绝或操作系统拒绝启动才能记为失败；初始化超时、传输中断及证据缺失保持结果未知。原生初始化完整完成后才能确认 ready，早到的 idle 通知不能替代完成证据。ready 表示本代曾完成启动，不代表当前连接仍可用。Codex、Copilot 和 Claude 的明确初始化拒绝遵守同一分类，SDK 传输异常不因共用错误类型被误判为拒绝；失败清理不能覆盖原始启动分类或绕过停止证明。

Worker 即使无法通过 Controller relay 连接服务，也须通过既有认领更新上报其持久本机事实；首次 hello 前的故障不能永远停留为正常 initializing。Worker 已观察到本代 `controller_start_unknown` 后，仍停在 starting/initializing 的旧 journal 不能将其改回启动中，非终态 lifecycle 也不能替代新的启动结果证据。此规则同时约束普通执行推进和独立摘要对账，不依赖提前暂停恢复，也不能在执行路径读回旧记录后失效。同代 journal 后续确认的 ready、明确拒绝或具体初始化未知结果仍可更新报告；其他执行身份的结果不能参与更新。恢复缺失原生身份、预算耗尽或其他安全门禁须保留独立原因，不用恢复受阻覆盖未知启动结果。摘要只包含稳定原因码，安全文字由固定映射生成，不暴露原始凭据、私有路径、完整日志或输入。

编排前置条件等待不属于原生恢复失败，不得报告恢复预算耗尽或将健康原生执行显示为已停止。已连接、同步且无真实原生阻塞的会话仍可读取历史；写操作继续通过既有权限、执行身份和原生输入门禁。工作树恢复及旧误分类纠正后，同一 generation 的更高 revision 报告须让现有页面恢复准确状态，不重建连接或重放输入。真正 native recovery blocked 不能仅凭 connected 绕过。

服务端在当前执行所有者、完整代际身份和任务版本检查后持久保存报告。旧 claim、旧代际、旧修订和同修订不同内容均不得替换当前结果。上报失败必须先重新读取对账，不得消耗原生恢复预算、重放 assignment、创建替代会话或删除原工作区。成功的同一报告可幂等确认；换代后只能读取新身份的报告。

旧消费者保持原协议形状，新消费者将缺字段视为未知。观察时间不作为在线证明，也不因重复上报而刷新；陈旧 starting 只允许降级为待确认，不能推断确定失败或触发恢复。Task/current 的现有读取权限及原生恢复授权不变，具体字段、协商与持久化由[协议设计](../design/task-session-protocol.md#启动观察的独立上报)定义。

CLI 回归须覆盖真实子进程在认证 IPC 完成前退出、journal 保留非终态 initializing、Worker 持久结果经独立摘要发送并在下一轮对账不变的组合。另须使用默认恢复策略且不手动暂停的 Coordinator tick，实际执行 `advance` 后验证启动未知仍被保留；原生身份缺失造成的恢复阻断必须独立上报，不能启动替代会话或授权重试。重复读取旧 journal 不递增 revision 或刷新 observedAt；恢复阻断的真实变化仍递增报告 revision。控制场景须证明同代新结果可以推进，executionId、claimId、Session、generation 或 Controller instance 不匹配的新结果不能覆盖本代报告；报告阶段不启动原生执行、不消耗恢复预算或授权重试。

Session View 使用同一选择规则呈现当前状态：终态先采用归档语义；请求无法验证时显示状态暂时无法确认并保留真实错误；有效的明确启动失败和恢复阻断先于一般连接状态；超时未知不能转成失败。新的 starting 观察仅在 90 秒内且时间不在未来时可显示启动中；未连接时显示等待执行环境连接，陈旧观察退回启动未确认。缺字段不能从 waiting、connectionEpoch 或 nativeSessionId 推断是否启动；本代 ready 或本页面已实际见到本代连接后失联，才采用连接中断提示。启动、连接与恢复提示随页面语言变化，正常原生活动和操作标签仍使用指定英文。

页头只显示一处主要状态。明确失败、启动未知或恢复受阻可展开固定安全原因及观测时间；同一 controller_offline 不在空态和 Composer 重复显示。真正权限、协议和历史损坏错误仍须可见；权限失效清除受保护内容并保留安全错误说明。草稿和输入框在同一执行内保持挂载，未就绪不发送输入；初始化期间已在线可用的原生审批仍可响应。

未连接、未同步、明确启动失败或恢复受阻时不请求 live 历史，保留已经读到的内容。即使连接快照尚未变化，同一历史身份的 controller_offline 也停止自动重试；更新后的连接快照或用户刷新允许重新核对。Worker 报告通过独立 current 读取更新，健康 WebSocket 不因此重连。有效报告和连接恢复后恢复尾页与分页；归档使用独立只读接口，不进入 live 历史恢复循环。

## Task 详情的完整 Current 读取

只有 Task 详情的 Session tab 被选中且文档可见时，该详情才允许发起完整 `sessions/current`。Overview、尚未选择或已隐藏的 Session tab 和隐藏文档不预取完整当前会话；native、Herdr、直接详情及完成任务入口遵守同一读取可见性要求。

可见 tab 内的首次发现、显式刷新、未注册发现、启动和恢复观察、重连及归档最终身份核验保持原有功能与节奏。native 的现有 3 秒 current 观察不因隐藏前保留的健康连接而取消；重新可见后继续观察，而非无条件重启连接。Worker 报告、完整 current 响应、目录、实时传输及操作规则保持各自职责。

隐藏仅取消或延后完整 current 及其定时读取，不代表失去执行所有权。native 健康 channel、已显示内容、草稿和阅读位置保留，账户变化时立即停止远端传输；Herdr 保持隐藏时的 channel 和 control lease 释放政策。取消的 current 在实际 settle 前仍占用读取名额，快速隐藏和重开不得产生重叠请求或发布取消后的旧结果。恢复需重新核对当前执行、请求、身份与读取可见性。

归档 ready 后的最终 current 核验可延后到可见，但不得跳过原执行身份和正文验证。完成任务的发现先等待现有身份准入，随后在发 HTTP 前及每次等待结束后复验 tab、文档、原请求和任务绑定。独立 Test/Bot 的现有 authority observation 不受 Task tab 门禁改变。

## Session 显示模式

Task、Test 和可读取的只读归档共用 Session View 顶部的 Display（显示）菜单，与 Session 全屏和刷新按钮并列。菜单只有 Standard（标准）与 Conversation（对话）两个单选项，checked 表示当前选择；新 Session 或没有有效保存偏好的 Session 默认 Conversation。显示模式是阅读偏好，不改变历史、执行状态、操作权限或 Provider 行为。

Standard 保留完整时间线的现有条目、折叠方式和资源展示，两种模式均不显示正文为空或全空白的 reasoning。Conversation 的显示规则如下：

| 内容 | Conversation 行为 |
|---|---|
| 用户与助手消息 | 保留完整 Markdown、图片和文件等 parts，顺序不变。 |
| todo 与计划工具 | 保留当前内容、状态和资源呈现。 |
| 审批、问题、表单及已完成交互 | 保留；响应能力仍由当前权限、版本和 pending 状态决定。 |
| 真实 error，包括中断与取消结果 | 保留当前展示，不增加通知分组。 |
| reasoning、compaction、普通工具及其输出资源 | 隐藏，不挂载隐藏条目的输出或资源组件。 |
| 子代理活动 | 按工具隐藏，不读取子代理会话。已严格识别的旧格式活动遵守相同规则，其他错误保留。 |

计划工具仅按名称最后一个 `.` 分段精确匹配 `update_plan`、`TodoWrite`、`todo_write`、`EnterPlanMode`、`ExitPlanMode`、`enter_plan_mode`、`exit_plan_mode`、`TaskCreate`、`TaskUpdate`、`TaskList`、`TaskGet`；不从自由文本、相似前缀或工具成功状态推断类型。顶部状态、Chatbox、必要操作回执、归档状态、连接错误和历史加载错误不受此过滤影响。

偏好在当前浏览器 origin 内按已认证账号与稳定 `sessionId` 隔离保存。同一 Session 从 Task、Test 或归档入口打开时使用同一选择；重连、historyEpoch 变化和转归档不重置偏好。不同账号或 Session 不共享模式，身份变化首帧不得套用上一身份的值；尚未确定身份时使用默认 Conversation，不读写匿名偏好。显示偏好独立于草稿、操作账本和执行 fence。首次缺省不写入默认值，刷新或重新打开恢复有效保存值，同页同一账号和 Session 的多个视图保持一致；不承诺跨标签实时或跨设备同步。

读取失败或值无效时使用 Conversation；保存失败保留当前内存选择，并仅在 Display 菜单内说明错误及提供重试，不谎报保存成功。重试保存当前选择，不回读旧值覆盖它；成功清除提示，无错误时没有常驻说明。菜单及错误、重试文案跟随页面语言，不属于 Session 原生操作标签的固定英语例外。

菜单支持键盘打开、单选项导航和选择。Escape 仅关闭当前菜单并恢复触发器焦点，不关闭外层任务弹窗或全屏；菜单与 Chatbox 提示层协调关闭顺序。点击外部或焦点移出关闭菜单。320px、390px 和桌面窄容器中，触发器、选项、错误和重试均可访问且不溢出。

显示选择本身只从完整原始 entries 派生可见列表，不改写资源索引、cursor、hasOlder 或实时归并；后续历史读取由独立的视口需求判断。切换不重建 Session client、WebSocket、Composer、交互卡或保留的消息节点，不丢失草稿，也不确认、拒绝或重放任何操作。切回 Standard 从已有条目恢复显示；消息与保留的计划工具资源继续按原规则读取。

已加载历史没有任何原始条目，且没有更早历史或已确认历史完整时，两种模式都显示“尚无对话。”或“No conversation yet.”。存在原始条目但 Conversation 过滤后无可见条目，或仍有更早历史、无法确定历史是否为空时，Conversation 显示“当前对话模式下暂无内容”或“No content in conversation mode.”，不能表示历史为空。历史分页按实际视口需求继续，连续全隐藏页不代表历史终点；加载错误及重试独立于可见条目。正在跟随时切换后继续跟随，正在上读时保留暂停和仍可见的文字锚点。锚点被过滤时按原始时间顺序定位最近前一可见条目，无前项则使用后一项；没有可见内容时保持暂停。宽度变化、流式更新、历史加载与 inactive 恢复遵守同一阅读意图，不承诺隐藏条目的精确像素位置。重选已选模式不重置滚动。

## Session 历史自动加载

Task 与 Test 的 Standard、Conversation、窄屏及全屏使用同一分页行为。用户向上阅读接近已加载历史顶部时，按 timeline 自身滚动位置自动读取更早内容；滚轮、触摸、键盘和滚动条拖动均有效。正常态不显示常驻“加载更早活动”按钮。读取中显示紧凑且可访问的 loading 状态；失败显示实际错误和可键盘操作的重试入口，失败后不得自动循环重试。无更多历史时停止请求，不增加常驻提示。

最新尾页已填满视口时，初始挂载、跟随最新、程序化锚定和单纯切换显示模式不得扫读历史。初始或过滤后的可见内容不足视口且仍有更早历史时，可在初始尾页定位和布局完成后串行补屏；填满或历史耗尽即停，并保留原 following 意图。每页成功合并、渲染及锚定完成后，必须重新检查当前需求，不能一次预取整段历史。合法过滤空页或修订合并没有新增可见条目时，依据实际页完成与游标前进继续判断，不把 DOM 高度未变当作终点。

自动读取仅限 active、可见、当前身份与认证有效、在线可读取且历史已就绪的 Session。正在读取、已有历史错误、无更多历史、隐藏或失活、auth pause、断线或已离开顶部阅读区时，不得继续顶部预取。Session、historyEpoch 或连接代次变化、返回最新和卸载使旧的自动继续意图失效；迟到结果不得污染新身份或新代请求状态。归档已经完整读取时沿用完整内容，不增加分页协议。

上读分页前保存当前条目和可见文字的相对视口位置，prepend 后恢复同一阅读位置，不叠加另一套 scrollHeight 差值补偿。稳定布局下，同一可见文字的分页前后偏差不得超过 1 CSS px。图片尺寸变化、流式追加、工具展开、显示模式与宽度变化继续遵守既有文字锚点和返回最新语义；DiscussionTimeline 的行为不因 Session 自动分页改变。

连续分页必须验证不透明游标的进展：`hasMoreBefore=true` 时 `beforeCursor` 非空、不同于本轮请求游标，且未形成重复或循环。异常转为可见历史读取错误并停止；Session 或历史重置时清理进展记录。不得对游标做数值排序，也不得改变资源索引、最新修订合并、`reset_required` 和鉴权失效语义。

## Session 默认头部

Task、Test 与只读归档的默认头部按 Session 容器宽度排列。容器不足 480px 时，Provider 名称与 Display、全屏、刷新操作共用第一行，主要状态独占第二行；不足 260px 时按名称、状态、操作分成三行。名称空间不足时省略显示，辅助技术仍可读取完整名称。状态保持完整可读，不增加第二处主要状态，也不改变固定英文原生标签和启动、恢复详情入口。容器达到 480px 时保留现有桌面排列。

窄容器的刷新与全屏按钮均为 36×36px 图标按钮；Display 保留文字。刷新具有本地化可访问名称、悬停和键盘聚焦提示及可见焦点，鼠标、键盘与触屏调用同一个刷新操作，权限暂停时仍禁用。容器变宽恢复文字刷新按钮，不更换按钮身份。自定义 `renderHeader` 的布局与收到的控件呈现保持原样。

## Session 独立全屏

Session View 工具栏在 Display 菜单之后、刷新按钮左侧提供独立全屏图标按钮，与任务详情标题栏的全屏入口区分。按钮具有随页面语言变化的可访问名称、悬停及键盘聚焦提示和可见焦点；进入后原位置变为退出全屏。普通任务弹窗、已全屏的任务详情、独立任务详情页及 Test Session 使用同一能力。

全屏占满浏览器可见内容区，保留地址栏，不调用浏览器原生 Fullscreen API。画面保留会话工具栏、消息、工具与交互内容、必要状态和错误、输入框；任务标题、负责人、认领信息、Tabs、任务页脚及其他背景操作隐藏并退出键盘与辅助技术访问范围。退出恢复原任务详情布局，进入前已处于任务详情全屏的仍保持该状态。

进入和退出保留同一个 Session client、连接、React 子树与关键 DOM，不另建 Session，不切换 portal 容器，也不自动刷新、重放操作或产生服务端业务写入。草稿、输入设置、工具展开、审批和历史加载状态保留；流式更新、待审批响应和分页继续遵守原有权限与操作语义。全屏尺寸变化沿用既有文字阅读锚点和 following 意图，不能强制跳到底部，也不改变 Display 模式或其偏好。

按钮和 Escape 均可退出。Display、权限、命令菜单及其他内层控件优先消费 Escape，其后才退出 Session 全屏，再由后续 Escape 处理外层任务详情；单次按键不能跨层关闭。模型、权限、交互表单单选或录制缩放的系统原生菜单打开时，首次 Escape 只取消原生菜单，保留设置面板、表单值、文本草稿与全屏；IME 和已消费按键不能触发退出。后续非 popup Escape 才按当前层级关闭和恢复焦点。全屏内限制 Tab 遍历并阻止背景获得焦点；退出恢复全屏入口焦点或仍可用的安全焦点。背景滚动锁与外层 modal 的锁共存，退出或卸载只释放自身所有权。Session 全屏期间保存并固定根页面位置；退出后恢复原位置和受控样式，其他 modal 仍持有的锁继续生效。键盘缩放可见视口或视口平移时，不透明背景仍覆盖完整布局视口，内部内容使用可见视口，系统键盘附件栏不属于网页控件。时间线、长输入框、菜单与横向代码保留合法滚动，边界拖动不得滚动底层任务或页面；多指缩放、文本选区、中文 IME 及顶部拖动读取历史不能被全局触摸禁用破坏。

全屏是临时视图状态，不写 URL、localStorage 或服务端。离开 Session、切换账号、task、claim 或已知实际 Session 身份、关闭与卸载均清理状态，不将上一会话的全屏带入另一身份。同一目标首次从加载态取得 Session 身份时保留全屏；加载、未注册、暂时缺少快照、断线、错误、归档准备中和只读归档保留可达的退出入口。只读状态不因此恢复写入能力，原有错误说明与恢复操作仍可访问。

桌面、320px 与 390px 窄屏、桌面窄容器和长内容不得造成横向溢出。工具栏退出入口在短 viewport 及软键盘缩小可见区域时仍须可达。布局与键盘验收应分别记录真实浏览器、模拟移动视口和真实移动设备的证据边界；尺寸模拟不能替代真实软键盘验收。

## Chatbox 设置、命令与运行状态

Chatbox 使用一个共同的可见边界容纳文本输入、模型/权限/命令入口、活动状态和发送/中断操作。快捷键说明附于发送操作，悬停或键盘聚焦时按需显示，不单独占据常驻布局行；提示可见时，Escape 只关闭该提示，不关闭外层任务视图。输入区位于上方，不单独成框。聚焦输入时须有清楚的焦点提示，按钮继续保留独立的键盘焦点。展开设置、命令列表和真实错误保持可访问，不改变输入处理、状态可用性或操作确认语义。

Chatbox 外框与时间线正文容器的左右边界对齐，不能以有缩进的用户气泡或代码块为基准。正文是唯一阅读宽度来源：默认 Task/Test 保留 960px 上限，助手保留其 760px 阅读列；窄面板沿用所在入口的侧边距并按实际可用宽度收缩。输入列须计入正文滚动条与 scrollbar gutter 的实际占位，有无纵向滚动条时，左右边界差各不超过 1 CSS px。设置、命令面板和已有附件随输入列对齐，保持可关闭和可滚动；不增加裁切，不改变错误展示策略。常规、展开、全屏及窗口调整沿用同一 Session、输入节点、草稿和阅读意图，自定义头尾部保持原契约；没有 composer 的只读入口不增加占位。

默认底部区域按设置入口（模型、Permissions、`/`）、运行状态（状态点、标签、计时）、主操作（Interrupt 与发送类按钮）分成三组。主操作组保持在右下角，Interrupt 与发送类按钮不能拆到不同布局行。布局依据共同边框内扣除 padding 后的可用内容宽度，不依据 viewport 或单个元素偶然溢出；视觉顺序和 DOM 顺序一致，键盘按设置入口、Interrupt、发送类按钮遍历。设置入口组保留按能力添加入口的位置，不实现额外附件能力。

| 内容宽度 | 运行状态和 Interrupt 均不可见，主操作仅为普通 Send | 有可见运行状态 |
|---|---|---|
| 小于 234px | 设置、主操作两行 | 设置、状态、主操作三行 |
| 234px 至不足 346px | 设置与主操作同一行 | 设置、状态、主操作三行 |
| 346px 至不足 516px | 设置与主操作同一行 | 设置一行，状态与主操作同一行 |
| 不小于 516px | 设置与主操作同一行 | 三组同一行 |

无可见运行状态时，若 Interrupt 仍可见或主操作为 Awaiting provider confirmation、Executing command 或 Add to current turn 等长标签，不足 516px 的内容宽度仍使用设置、主操作两行；达到 516px 后同排。上述行数指组的排列，长状态或主操作标签可在组内换行并完整显示，不能截断、覆盖或造成横向溢出。状态与主操作同排时须各自保留可读空间，长操作标签不能挤占或覆盖状态。模型入口最小宽度为 52px，只对名称文字显示省略号，独立的 `▾` 始终可见；空间充足时显示更多名称，完整名称仍可在模型设置面板中查看。`pointer: coarse` 时，默认底部各入口和主操作的可点击高度至少 36px，`/` 入口宽度至少 36px。状态变化、容器尺寸变化和语言切换保持草稿与控件身份；设置和命令面板位置、快捷键提示与 Escape 层级不变。自定义 footer 继续获得原有 settings、包含 Interrupt 的 activity 和 submit，不因默认布局分组而改变其操作契约。

Session 顶部和 Chatbox 底部的活动状态、Permissions 入口、主发送按钮、中断按钮，以及 timeline 内建的 Command/File changes 工具类型标签在中文和英文界面中均使用已有英文文案。正常原生活动覆盖空闲、工作、等待输入、停止和未知，顶部只读状态保持原英文；启动、断连和恢复诊断按上述启动状态规则本地化，且只显示一处主提示。操作覆盖 Send、Add to current turn、等待受理、Executing command 和 Interrupt 的请求/处理中变体。固定文本及对应可访问名称保持一致，并标明局部英语语言；Provider 返回的名称与用户内容保持原值。周围说明、错误、操作回执、交互卡、工具执行结果状态、输入提示及设置面板继续按当前语言显示，语言切换不改变草稿、操作或权限语义。

Chatbox 按 Provider 发现的真实能力提供模型、reasoning effort 和权限选择。默认值保留原生语义；没有可读实际值时显示未知，不猜测默认模型或权限。选择后区分待确认目标与已生效值，只有原生确认或回读才能更新实际状态。显示生效范围；不支持运行中生效的设置不能伪装改变当前推理。失败和未知结果可见，不能自动重复设置操作。

设置面板中的 Daynight 内置设置名、权限选项、原生默认值选项和说明随页面语言显示；说明保留各 Provider 的独立语义。模型名称、原生推理强度值、skill 名称及原生说明保持原文。未知设置或选项回退到 Controller 原文，不隐藏或拒绝。命令菜单中的 Daynight 内置命令说明及缺省说明同样本地化。语言切换即时更新已打开面板与菜单的文案，保留选择值、待确认目标、已确认值、命令选择和草稿，不重新派发设置或命令。

权限设置保留 Provider 的独立含义。Codex 的 approval policy 与 sandbox 分开并遵守配置约束；Claude 保留原生 permissionMode；Copilot 的工具审批不代表路径或网络授权。新建无人值守 Worker 会话按其已配置的执行策略初始化权限；其余权限变更须由用户明确选择，不因恢复或打开设置面板提高权限。

斜杠菜单提供目录、前缀过滤、键盘导航和参数输入。提交排除前导空白后按完整命令名匹配当前目录，model/permissions 保留为本地设置入口。零匹配按普通消息发送，包括绝对路径、未知 slash、仅前缀匹配、单独 `/` 和多行正文；Enter、Send 与追加到当前轮次采用相同分类。普通消息只沿用既有外侧 trim，保留正文内部空格、换行和斜杠，不增加分类提示。其可用性由普通发送及 steer 能力决定，目录缺失或加载失败不能额外阻止发送；离线、账户变化等待刷新、只读、未同步和待确认操作仍限制发送。目录加载失败保留错误和重试入口。

一个完整匹配走现有命令路径；多个同名匹配、已知但不可用、非法参数和过期目录或 turn 均明确拒绝，不能改发普通正文。菜单默认高亮不代表用户选择：`/mo` 直接 Enter 按普通消息发送，点击、普通 Tab 或明确箭头选择后 Enter 才选择候选。输入、目录和菜单生命周期变化清理临时候选选择。显式选择带参数命令后，保存 commandId 和命令头；参数编辑、目录刷新及 Escape 关闭菜单保留该意图。提交按当前目录和 revision 校验同一 ID；目录移除、同名换 ID、不可用或歧义均报错。修改命令头、清空草稿或切换 Session 才清除此意图，不新增撤销入口。

命令进入 execute_command 后，无论 Provider 拒绝、网络失败或结果 unknown，均保留原操作回执和草稿，不能再发送普通消息或创建第二种操作。普通消息失败或受理不确定也保留草稿；明确受理仅清除对应提交版本，不覆盖期间的新编辑或无关草稿。Web 只保证发送操作类型与正文，不约束 Provider SDK 对原生文本的进一步解释；服务端、Controller 和 Provider 命令协议保持不变。

命令菜单按 Session 容器扣除其他可见控件后的实际空间收缩，不能仅以 viewport 比例或固定高度限制列表。长名称、长描述和多行草稿不得使输入、发送操作与命令开关被菜单挤出可见区域。菜单标题、刷新入口和具有可访问名称的关闭按钮保持可见，目录内容独立滚动且保留可点击的可视区域，不能只剩标题；键盘选中项超出列表可视区时滚动菜单使其可见，不带动外层任务页面。空间不足时多行输入在保留可编辑高度后内部滚动；任务详情的元数据区域为 Session 必要控件让出空间，并保留自身滚动。窄屏、低高度窗口和缩放沿用同一行为与 Chatbox 样式。

命令条目在非高亮时最多显示两行描述，超出部分省略；唯一高亮项展开完整描述，参数提示也只在该项显示，不能在整个目录逐条重复。完整描述始终保留为选项可访问名称的一部分，Provider 返回的 skill 与自定义 command 名称、描述和参数提示不改写，内置命令说明沿用本地化规则。鼠标或笔移动到条目时切换高亮，展开与收起应保持指针目标在列表中的阅读位置；触屏点击沿用选择语义，不先模拟悬停展开。悬停本身不构成明确的命令选择，不能改变 Enter 的提交分类。键盘导航继续将高亮项滚入可见区，指针浏览不强制将展开项滚到列表顶部；两者均不得带动外层页面或跳到无关条目。目录首尾也须保持指针目标位置；仅在滚动边界无法容纳位移时可保留必要的临时空白，切回键盘导航或重置输入、目录与菜单生命周期时清除。条目密度变化不改变目录来源、排序、筛选、可用性、参数补全和执行路径，也不改变菜单位置与高度分配规则。

目录正常时刷新入口显示“刷新命令”/“Refresh commands”；只有目录加载失败且菜单显示真实错误时才显示“重新加载”/“Reload”。刷新进行中显示“正在刷新…”/“Refreshing…”，禁用重复点击并向辅助技术暴露忙碌状态。文案随页面语言变化，刷新调用、目录校验、错误处理、按钮位置与点击尺寸及原有控制可用性条件保持不变。

输入框中的非 IME Shift+Tab 先关闭候选，再按现有反向焦点顺序离开输入框；候选不可成为该次导航的焦点目标。此行为在断线、候选不可用、无匹配、账户变化等待刷新和操作待确认时仍成立，保留草稿，不选择、补齐或执行命令，也不打开设置面板。普通 Tab 的候选确认和不可用状态行为保持不变。

关闭按钮、再次点击命令开关和非 IME 的 Escape 均可关闭菜单。在没有更内层 Display 菜单或快捷键提示消费按键时，无论焦点位于命令菜单、输入框还是 Session 标题栏，Escape 都先关闭命令菜单并恢复输入焦点，不能同时关闭任务详情或退出 Session 全屏；IME composition 的 Escape 保留输入法默认行为，同时不得关闭外层视图。点击外部关闭菜单时不抢走目标焦点，也不吞掉目标操作。关闭只改变本地展开状态，保留完整草稿，不执行命令、不发送消息、不更新会话设置。加载中、加载失败、无匹配、断线及控制权限不可用均不能禁用关闭入口；关闭后继续正常输入。

工作状态与 Chatbox 放在一起，区分工作、等待输入、中断申请中及已确认结束。计时依据 Controller 观测到的原生 turn 开始证据，未知时不伪造。工作中发送按 Provider 支持执行 steer；中断保留独立入口并绑定当前 turn。Claude 的追加必须具备输入生命周期与取消排队能力，不能只打开按钮；停止后不能留下未显示的排队输入继续执行。

设置、命令和普通输入共享当前执行与权限约束，多个网页同时操作须拒绝旧目录版本。中断和审批不能被等待中的设置阻塞。账号核验、失焦连接保留、断线与恢复继续遵守下述可靠性要求。

## 内容归属与结束后历史

[任务 Thread](daynight-task-thread.md)独立保存参与者显式发言与引用回复，不属于原生 Session 内容，不依赖 Controller 在线，也不触发 Agent 或改变执行状态。任务描述与附件继续保存有效要求和正式成果。

执行中的消息、reasoning、工具参数和结果、资源及 Session View 动态状态由对应 Agent 执行环境及 Controller 保存。Controller 以标准化 timeline 更新和已登记资源作为归档来源，正文写入本机待归档文件；SQLite 只保留执行身份、完整操作证据、内容索引和有界投递 outbox，不另存整份 timeline 或资源正文。旧 SQLite 正文必须先可靠导出，再清除原内容表；已停止执行的受支持旧 journal 也必须能够自动补齐结构迁移后归档，不能要求重新启动 Agent。没有完整历史来源的旧 journal 在自动升级后仍须保持不完整状态，不能将迁移新建的空表当作完整空历史。Daynight 服务端负责经过鉴权的在线转发和有界临时缓存，不将会话正文写入 PostgreSQL。

活跃执行的历史读取仍要求 Controller 在线且本地数据存在。在线时支持刷新、跨网页访问和历史分页；活跃执行断线不被误判为已完成归档，已打开网页可保留当前离线画面。重新上线后从本机同步。

执行结束并确认原生进程停止后，Controller 封存标准化 timeline 和资源，通过服务端文件存储保存只读归档。PostgreSQL 只保存归属、状态、对象位置、大小和 SHA-256。新 Task 归档按原项目分组，独立 Test/Bot 归档按原 owner 分组，再按 Session UUID 前两位分片。既有文件与元数据保持原状，读取继续使用已登记的对象位置；目录调整不改变正文、校验值、回执、公开 URL 或上传重试语义。归档 ready 后，原 Session 页面无需 Controller 在线即可阅读消息、展开工具和读取资源；所有输入、审批、设置、命令和中断操作必须禁用。归档不具有原生 resume 能力，不恢复任务或重放输入，也不承诺逐 token 动画或 Provider 未提供的内容。

Task、独立 Test 和 Bot 的归档 ready 后，结束状态只在 Session 头部显示，保留固定英文 `Completed · Read-only history` 和可访问的状态语义，正文直接显示对话记录，不重复结束提示。归档内容仍在加载、pending、failed、unavailable 或 draining 等待归档时，正文继续显示对应提示和现有刷新入口；从附件打开其他历史记录、Session 全屏及显示模式不改变此规则。

归档上传和正文读取共享占用额度：每服务实例同时一项，同一共享存储根内每个归档原 owner 同时一项。额度满时立即返回 429 `resource_busy`；额度覆盖正文读取、校验、存储和响应发送，发送结束或失败后释放。上传正文和响应发送分别有 120 秒实际 I/O 期限；超时不得将未完成传输报告为成功。额度不扩大原有访问与删除后收尾权限。

归档 pending、failed、unavailable 必须明确显示；未确认完整上传不得删除唯一历史源。失败只重试归档，不重新执行任务。Worker 对已证明的历史不完整采用[待修复与低频条件探测](daynight-worker.md)；保留原 generation 的 receipt 对账机会，不通过清除完整性标记释放原件。任务软删除不能阻断仍具有效凭据和项目成员资格的原执行 owner 完成归档及清理；此收尾权限不恢复已删除任务的页面、历史正文读取或控制权限。归档建立的持久原生身份须在所有共享存储的服务实例上保持一致，旧 live cache 和终态清理不能将其回退。归档须验证原执行归属、代次、条目顺序、资源引用及字节完整性；不完整或超限内容明确失败，不能静默截断。当前归档上限为 64 MiB，单资源 8 MiB；本机源保留供诊断与重试。容器在完成上传前销毁仍可能丢失内容，运行中远端增量备份和独立容器管理不属于此能力；普通 worktree 不能被称为安全 sandbox。

服务端重启或网络积压不能仅因显示事件无法转发而停止健康 Agent。显示传输限额按实际 JSON 编码后的字节计算；合法文本中的 HTML 字符或 Unicode 转义不能让同一事件永久阻塞确认与重同步。真正超预算的非交互展示内容仍保留在本机，传输端必须提供有界、可继续同步的降级路径，不能丢失操作证据或伪造已完整回放。带权限语义的交互必须保持完整，不因展示降级改变审批问题或答案。原生执行证据和操作日志必须继续在本机保存；重新同步前不开放控制。服务端暂收命令不等于 Controller 已持久接收，网页只在真实原生受理后清除对应草稿，未知结果不得自动重发。历史、传输和最小操作账本分别具有明确容量边界，不能通过危险清理去重记录来维持容量。

## 生命周期与可靠性

浏览器打开、刷新、翻页和重连不创建 Agent，也不重发任务正文。浏览器或 relay 断线不停止 Agent loop。Controller 在 Agent 执行环境本地持久记录原生身份、输入结果与会话内容，恢复先对账；不确定结果保持 unknown，不自动重放。

切换应用、窗口焦点或浏览器可见性不触发账户复核；Session 自身的可见性规则仍适用。观察到账户变化时立即停止远程传输和控制，保留时间线、草稿、阅读位置及已解码图片，直到用户刷新；可信不同账户的帧不得安装。真正权限撤销或执行失效按各自生命周期隔离会话。

同一执行只有一个原生 writer。连接代次与原生执行代次分离，网络租约过期不能证明旧进程已停。Controller 崩溃后恢复须确认旧进程停止并使用确切原生 ID；没有恢复证据时明确暂停，不新建会话冒充连续执行。

操作同时要求当前项目访问权、认证用户等于持久 Session owner，以及正确的 claim、执行代次和当前 turn/interaction。服务端在接纳、派发、原生调用授权及重连对账中重新检查原操作者的 owner 资格，不能由 Controller 或项目角色代替。已排队的非 owner 操作不得继续派发；Herdr 旧非 owner 租约与迟到控制 ACK 不得恢复控制。服务器接受命令不等于原生受理，原生受理不等于任务完成。高频事件独立于 Task version，断线后可从有界缓存补齐；缓存失效时必须从在线 Controller 重读，不假装仍有完整事件回放。

清理前必须确认对应 backend 的真实原生进程停止；Web Windows 完整停止须保留原 Job lease、在终止前固定已知原 Controller/native 出生实例的进程句柄，并在原期限内确认这些原句柄 signaled 和同一 Job 成员清空。ESRCH、退出码改变、空成员列表或缺失 Job 名称均不能单独证明完成；退出过渡、未知状态、身份冲突和句柄关闭失败保留责任。Web 正常终止还须确认归档 ready，再删除 worktree。网页关闭不能触发清理。任务完成遵循 Worker assignment 的运行约束和 claim-bound done，不以 native idle 替代验收。

## 验收

验证模式冻结、旧记录迁移、非法组合、当前执行页面入口、首次输入门控、跨浏览器并发、审批失效、断线恢复、未知结果及进程清理。权限矩阵覆盖原 owner、其他项目管理员、普通成员与 Team 继承成员：非 owner 可读且全部交互拒绝，owner 保留项目访问时不因角色降为 member 失去交互权，凭据或项目访问撤销仍拒绝。验证直接 API、browser channel 的权限投影、排队与重连操作、terminal 控制派发、旧租约和迟到 ACK。Web 须在没有 Herdr 的环境运行；Herdr 须在没有 Session relay 的环境保持原行为。

自动入口验收覆盖首次读取、确认无记录、启动待注册、活动会话、断线恢复、完成到归档 ready、pending/failed/unavailable、权限拒绝及恢复。组合多个历史、当前 Session 同时出现在历史页、旧选择缓存、新 claim 尚未注册、释放后重执行、退回 todo 和切换账号/任务。弹窗、独立详情和全屏在中英文、390px 与桌面宽度均不显示记录选择行，附件历史入口仍可达；后台检查保留草稿与阅读位置。通过实际请求观测确认打开和恢复不发出 native launch、assignment 或输入重放，完成态不存在写请求；模拟组件与交互原型证据不能代替原生生命周期验收。

Codex、Claude、Copilot 的原生执行、恢复与交互必须分别提供真实证据。Copilot 的发送、原生 steer、取消、审批、问题、表单、计划审批及精确恢复都需要独立实测；其他 provider 的历史验收不能替代这些证据。纯前端原型、协议 fixtures、编译成功及单元测试不能代替跨层验收。既有 Copilot Herdr 需要回归，平台支持只在对应平台验证后声明。

归档验收覆盖旧 SQLite 正文导出、停止后上传、上传失败保留与重试、旧 completed 执行补归档、服务端重启后读取、错误归属与内容篡改拒绝，以及 Controller 离线时真实浏览器只读渲染和所有写操作拒绝。

显示模式验收覆盖实际 Task、Test 与可读归档入口的默认 Conversation、保存的 Standard、两种语言、菜单键盘与分层 Escape、320px/390px 和桌面窄容器。验证账号和 Session 切换首帧、刷新与重开、同页共享、归档保持、存储读取/无效/写入错误及重试。组合验证各条目分类、混合资源、待响应交互、连续过滤空页、历史失败重试与真实浏览器阅读锚点；比较切换前后 client、连接、Composer、草稿、保留节点和操作请求，不能以纯 selector 测试或原型代替入口与几何证据。

底部操作区验收覆盖实际 Test Session 与任务详情 Session，以及 Session 全屏和桌面窄面板。在 320×640、375×667、390×844 移动模拟中检查空闲、Working、Waiting for an answer、Interrupting… 和 Awaiting provider confirmation：默认分组不超过三行，内容宽度达到 256px 时空闲发送与设置同行，320×640 等待回答时审批卡在时间线可见。比较修复前后的 Chatbox 高度，并记录内容宽度和各组边界；不以 viewport 宽度替代容器测量。使用 `GPT-6-Astra`、`Default (recommended)` 和超长模型 ID 验证下拉提示、无溢出与无重叠；验证至少 516px 内容宽度的单行排列、触控尺寸、鼠标点击、Tab 顺序、分层 Escape 及中英文切换时的草稿和控件身份。实际页面结果与原型、组件测试分别记录，移动视口模拟不能证明真实手机或软键盘行为。

命令菜单验收覆盖任务详情弹层、任务与 Session 全屏、独立 Task/Test Session 入口的长目录与长描述、无匹配、加载与失败、控制不可用、320px/390px 窄屏、1360px 桌面、低高度窗口、缩放和多行草稿。记录打开前后容器、textarea 与底部操作的真实 DOM 边界，验证输入与操作可见可点击、列表滚动后关闭仍可用、菜单内各焦点位置的 Escape 层级及草稿保留；同时回归前缀搜索、上下键、Tab/Enter、指针与触屏点击、参数补全、IME 和 model/permissions 的原生语义。Codex、Claude、Copilot 的实际 Test Session 分别验证非高亮描述限两行、高亮全文与唯一参数提示、完整可访问名称、指针切换和键盘导航的滚动位置，以及各宽度无横向溢出；大量 skill 的 390px 目录须以几何记录证明同屏可见命令数量明显增加。组件和纯前端原型的结果与实际入口验收分别记录，不能相互替代。
