# Web 任务缓存与增量同步需求

状态：服务端窗口摘要、配置、身份响应头和 epoch，以及浏览器 IndexedDB 摘要、原子合并、本地图投影和按需详情缓存已实现。摘要业务版本驱动详情更新，成功同步的时钟 receipt 不单独触发未变化详情 GET。

[架构](../design/daynight-task-sync.md)拥有协议、缓存与恢复机制。任务生命周期、依赖性质、附件及计时沿用各自现有合同。

## 已确认范围

图和列表所需任务摘要持久保存在 IndexedDB；完整详情按需读取与缓存。可见页面维持约 5 秒读取，隐藏暂停，返回前台或本机写入后主动同步。缓存用于在线加速，断网保留已打开视图。

同步水位取客户端通过项目同步接口接受并保存的任务摘要中最大的 updatedAt。服务端将这个时间向前回退配置窗口，返回窗口下界之后的当前任务摘要；窗口默认 **10 秒**。允许重复传输，客户端按任务 ID 与已有业务 version 合并去重。

## R1：装载与范围

无可用缓存时读取完整摘要；以后以项目摘要缓存的最大 updatedAt 请求增量。请求不能用本次时间、上次响应时间或浏览器时间替代水位。客户端离开超过窗口后，仍从已有任务水位追赶，不局限于当前时间附近的数据。

当前挂载必须先成功完成一次实际用户匹配的项目同步，才可显示持久缓存中的私有内容；此前的 `/me` 或其他标签页的广播不能替代这次准入。保留最多 1,000 个任务、5,000 条边的容量合同；超限明确失败，不显示部分图。完整 task-graph 继续供 CLI、其他调用者与对照验收使用。

## R2：查询、配置与重复

服务端查询 updatedAt >= since - overlap，包含等值边界，默认 overlap=10s；通过 DAYNIGHT_TASK_SYNC_OVERLAP 配置正 Go duration。非法值使配置失败，不由客户端决定窗口。配置变更直接作用于后续读取，无需转换客户端保存的原始水位。

接口只返回当前任务行，不承诺逐个交付中间业务版本；客户端可以从 v5 直接观察到 v7。没有新任务变化时，末尾窗口中的任务仍可每轮重复返回；这是已接受的行为。相等版本不重写缓存、失效持久详情或替换已发布图索引，较旧版本不覆盖新版本。重复摘要不重新读取未变化详情；已存在读取错误、原始派生差异或未完成核对时仍允许必要的 GET 恢复。业务语义无变化仍遵循原有 version/updatedAt 不变规则。

## R3：变化与派生一致性

创建、标题、description、PR 信息、三状态设置、Agent 许可、执行平台要求、依赖及外部性质变化通过任务摘要的业务 version 被发现。任务事实、所有依赖、阻塞列表、可执行性、统计、链成员与进度在一个本地快照中一致。前置完成后，后继即使自身未编辑也正确更新派生状态。

## R4：原子应用与多标签页

摘要和对应最大更新时间一起持久提交；失败不能让水位领先于数据。不同任务可以具有相同 updatedAt，不能仅凭水位相等就认定内容相同。迟到响应按 ID/version 与当前持久集合合并，避免回退或丢失其他标签页的更新。

详情 GET、单次写操作结果、Project.updatedAt 和 observedAt 都不能推进项目同步水位，它们不能证明项目的其他任务已经被读取。

## R5：适用条件与历史替换

保持现有正式任务写入的项目行锁和同事务 updatedAt。数据库时间不倒退时，同项目较晚写入者无法越过未提交的较早写入，因此长事务本身不会被已返回任务的最大时间跳过。重叠窗口提供时间重叠和有限回退容忍，不宣称能处理任意时钟跳变或绕过正式路径的 SQL 维护。

数据库恢复、导入或替换历史必须在维护流程中轮换项目缓存 epoch，使浏览器完整重建。普通写入和重启不改变 epoch。当前没有任务删除 API；未来物理删除须同时提供清除缓存记录的协议。

## R6：失败恢复

缓存缺失、schema 不兼容、结构损坏、数据库异常关闭时允许重新装载完整摘要。active 与 invalidated manifest 都必须验证归属、生命周期及对应格式；invalidated 的 epoch/project/水位必须全为 null，任务与边计数全为零，不能把残留 epoch 作为增量基线。用户 fence 损坏时，在一个事务中轮换 fence 并清除或失效该用户可重建数据，不依赖损坏 fence，也不影响其他用户；旧绑定 scope 和 ticket 不能跨修复发布。IndexedDB 打开、升级、配额、修复及写入失败明确进入现有错误/Retry 状态；失败事务保留原持久状态和允许显示的当前快照，不能当作空项目或同步成功。重试先读实际存储。

## R7：计时与项目设置

每次实际成功同步都取得新 observedAt 与当前 Project；只用于本页显示计时和设置。持久缓存不恢复 performance.now 锚点，重复响应不重建图布局。项目设置通过已有 settings.version 合并，迟到响应不得回退设置。

## R8：身份与失效

按 API origin、用户、项目隔离。同步、详情及三类任务写响应在正文或资源错误处理前核对实际 `Daynight-User-ID`；缺失或无效头属于协议错误，不能据其 404 清理有效缓存。可信不同用户、会话失效与项目撤权立即释放所属内容，旧请求不能恢复它。每次增量读取仍检查服务端访问权限。

项目同步的可信 `404 not_found`，以及启动 GET 时摘要中已存在的任务或三类任务写的同用户可信 not_found，立即撤销捕获项目 generation 的内存准入和正文复用权限。先核对 ticket 的 userFence/cacheGeneration，旧 E1 响应不能清除 E2。未知任务 ID 的 404 只作为该任务局部缺失，避免对不存在地址不断重建整个项目。

撤权立即生效，持久清理失败也不能使 Retry 从磁盘恢复私有正文；重新显示需要待处理清理完成和新的在线项目同步。撤权负向提示只使匹配用户 fence/generation 的其他标签页拒绝旧内容，不授予访问，身份核验暂停期间也可立即处理；存储清理和正向读取仍等待身份 gate。清理只操作 ticket 匹配的持久 generation，不扩展为删除其他历史或新 generation 的承诺。

## R9：交互与详情

保留筛选、展开、选择、视口、全屏、滚动，以及独立详情页和附件工作区的阅读/操作状态。磁盘正文显示同时要求本挂载成功同步 receipt 和 scope 当前仍授权的项目 generation；撤权后旧 revision 不能恢复准入。每次打开记录本次 opening 的 live GET 要求，pending/unknown/核对期间也保留；磁盘、写结果或重开前核对不能替代它。项目 generation 改变立即清除旧正文、PR 与已加载权限，相同任务 ID、版本或时间不能证明属于同一历史。

重复摘要不触发没有变化的详情 GET。前置变化在本地更新派生字段，原始服务端差异继续保留陈旧提示与禁写。暂存版本高于摘要时等待，相等时受保护准入，已被摘要越过则丢弃并通过现有读队列重新 GET。普通读取恢复保持普通读取的用途：失败显示读取错误与 Retry，成功 GET 清除其读取阻塞状态，不改变原操作阶段；操作结果核对继续保持核对用途、意图和 outcome，失败时检查状态可用，成功只清除相应核对阻塞。两者不得相互留下不可见的永久禁写标记，也不重发写操作。

详情每项目最多 32 条、总 8 MiB、单条 2 MiB，按自身内容的精确 UTF-8 JSON 字节与 lastUsedAt 淘汰；超大成功正文可在会话显示而不持久化。真实缓存错误可见、可 Retry；同资源、同 generation 且仍获授权的成功内容才可在恢复性错误中保留。附件继续独立按需读取。

## R10：验证与效率

用权威完整图对照本地投影。验证同时间戳不同任务/版本、边界包含、重复去重、迟到响应、多标签页、完整初始化、离开超过窗口后的追赶、详情不能推进水位，以及恢复/账号失效。

响应 ID 集合等于对应快照内窗口条件选中的任务，重复是合法数据；移除“无变化必为零任务”和“只改一个任务必只返回一个任务”的要求。记录实际窗口命中数、重复率、正文与传输字节、IDB 读写及投影耗时。重复数据不得导致重复 IDB 写入、详情失效、图布局或广播。

保留四种容量图各五次的既有门槛：打开图不超过 3,000ms，选择、详情、缩放和平移反馈不超过 300ms。新增缓存耗时先实测，不设无依据的绝对门槛。

## 范围边界

保留在线写入与服务端权限、版本、依赖检查。当前不包含离线冷启动、离线写入、即时推送或扩大图容量。时间窗口重复传输是主动接受的取舍；不增加变更日志、同步递增序号或独立的事后 updatedAt 写入。
