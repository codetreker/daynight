# Web 任务缓存与增量同步需求

服务端每条同步摘要包含必填 `tags:[{id,name}]`，无关联时为 `[]`。标签改名和删除通过关联条目的新 version 和 updatedAt 出现在普通增量中，不轮换任务缓存 epoch；每条普通 Task 的依赖状态与摘要版本一致。

状态：服务端窗口摘要及完整属性、配置、身份响应头、epoch 和轻量完整 Session 状态集合，以及浏览器 IndexedDB schema 12、原子合并、权威依赖状态与本地图投影、按需详情和版本化人员内容缓存已实现。摘要业务版本驱动详情更新，成功同步的时钟 receipt 不单独触发未变化详情 GET。

[架构](../design/daynight-task-sync.md)拥有协议、缓存与恢复机制。任务生命周期、依赖性质、附件及计时沿用各自现有合同。摘要与浏览器 Task、详情、图投影都包含[负责人契约](daynight-task-assignment.md)的必填 nullable assignedTo，以及必填 Type/Parent；摘要单独保存普通 Task 的权威依赖状态。schema 12 在严格解析前重建任务内容，并保留人员内容和用户身份；完整 snapshot 可清除可重取的 Session 目录。

## 已确认范围

图和列表所需任务摘要持久保存在 IndexedDB；完整详情按需读取与缓存。项目页面保持挂载且浏览器允许执行时，可见每 15 秒、隐藏每 5 分钟自动读取；隐藏以 `document.visibilityState === "hidden"` 判断，失焦不改变周期。首次打开、返回可见或本机写入后主动同步；显式刷新仍立即读取。隐藏转换不发请求或取消在途同步，每次转换从该时刻重新计时；自动触发遇到活动同步时跳过，显式刷新取消并替换。浏览器节流或冻结时，周期仅为名义值。身份核验完成后，项目先显示有效本地摘要并后台同步；断网或同步失败保留已显示视图。

同步水位取客户端通过项目同步接口接受并保存的任务摘要中最大的 updatedAt。服务端将这个时间向前回退配置窗口，返回窗口下界之后的当前任务摘要；窗口默认 **10 秒**。允许重复传输，客户端按任务 ID 与已有业务 version 合并去重。

## R1：装载与范围

无可用缓存时读取完整摘要；以后以项目摘要缓存的最大 updatedAt 请求增量。请求不能用本次时间、上次响应时间或浏览器时间替代水位。客户端离开超过窗口后，仍从已有任务水位追赶，不局限于当前时间附近的数据。

当前身份通过核验后，打开项目立即发布通过用户、项目、生命周期与完整性校验的本地摘要，无需等待本次 task-sync；有效空项目同样可以显示。后台同步成功后原子更新页面，普通失败保留已有摘要并提供错误与 Retry；没有有效摘要时保留加载与初始失败状态。本地摘要展示不授予详情正文或任务写入的在线准入；普通摘要来源仍要求本挂载成功同步，direct 来源使用当前 opening 的实时 Task 观察。同步保留全部可见 typed 资源，普通图保留全部可见 Task 及其依赖引用，不复查存储集合的节点、边或字节容量；自然读取、解码及持久化失败不发布部分图。CLI 的 task-graph 按指定任务查询完整本链及一层外部前置，不作为完整项目图；其边界由[服务端需求](daynight-server.md#任务链图查询)拥有。

## R2：查询、配置与重复

服务端查询 updatedAt >= since - overlap，包含等值边界，默认 overlap=10s；通过 DAYNIGHT_TASK_SYNC_OVERLAP 配置正 Go duration。非法值使配置失败，不由客户端决定窗口。配置变更直接作用于后续读取，无需转换客户端保存的原始水位。

接口只返回当前任务行，不承诺逐个交付中间业务版本；客户端可以从 v5 直接观察到 v7。没有新任务变化时，末尾窗口中的任务仍可每轮重复返回；这是已接受的行为。相等版本的自身字段不重写缓存或失效持久详情，较旧版本不覆盖新版本；同版本依赖状态变化仍需持久化并发布图投影。重复摘要不重新读取未变化详情；已存在读取错误、原始派生差异或未完成核对时仍允许必要的 GET 恢复。业务语义无变化仍遵循原有 version/updatedAt 不变规则。

## R3：变化与派生一致性

创建、标题、description、标签引用、完整 properties、五状态设置、Agent 许可、执行平台要求、负责人 assignedTo、依赖及外部性质变化通过任务摘要的业务 version 被发现。snapshot 和 delta 的每条任务记录都包含同一数据库快照中的 assignedTo 与完整当前 properties 对象；没有属性时为 {}，不补入缺失键。属性设置、删除与 Worker 生命周期变化沿用任务整体 version/updatedAt，普通属性变化不轮换 epoch。

服务端同步响应还包含 `dependencyStates`：完整 snapshot 覆盖所有可见普通 Task，delta 为自身或直接前置命中同步窗口的 Task 提供状态 patch。每项携带所属 Task 的精确版本、未满足前置和自身 ready；普通 Task 摘要必须伴随同版本状态。隐藏前置的真实状态仍决定满足性，父 Goal 状态不改变 Task.ready。该字段与摘要、epoch、时间和 Session source 属于同一数据库快照；查询失败不能返回部分结果。Web 严格消费该状态，按所属 Task 版本合并，不从可见图推断隐藏前置的满足性。

客户端按任务 ID/version 替换整条摘要和属性对象，缺失键自然删除；不使用属性 tombstone。浏览器严格解析必填标签引用，并比较包括 assignedTo 和标签引用在内的全部自身字段和全部属性键与 JSON 值，属性对象成员顺序无意义，属性数组顺序有意义，缺失、空数组与 null 不相等；标签按 ID 和名称的集合比较。同版本自身内容不同是协议错误，较旧响应不能复活已删除属性。图绘制投影去掉 properties 和 tags，完整属性保留在摘要集合中。状态的阻塞列表必须是所属 Task 依赖的子集，ready 须符合 Task 状态及阻塞列表；相同 Task 版本下依赖状态变化可更新阻塞、可执行性与统计，即使后继自身未编辑。同一版本的不同前置观察可能乱序到达，旧状态可暂时覆盖新状态；后续相关变化或完整 snapshot 可刷新，不能保证下一轮轮询必然修正。资源存在性包括 Goal，普通图只包含 Task，保留指向不可见前置的引用，不制造隐藏节点或拒绝合法图。取消不轮换epoch、不删除节点，也不清空仍可读的详情和附件。

## R4：原子应用与多标签页

摘要和对应最大更新时间一起持久提交；失败不能让水位领先于数据。不同任务可以具有相同 updatedAt，不能仅凭水位相等就认定内容相同。迟到响应按 ID/version 与当前持久集合合并，避免回退或丢失其他标签页的更新。

详情 GET、单次写操作结果、Project.updatedAt 和 observedAt 都不能推进项目同步水位，它们不能证明项目的其他任务已经被读取。

## R5：适用条件与历史替换

保持现有正式任务写入的项目行锁和同事务 updatedAt。数据库时间不倒退时，同项目较晚写入者无法越过未提交的较早写入，因此长事务本身不会被已返回任务的最大时间跳过。重叠窗口提供时间重叠和有限回退容忍，不宣称能处理任意时钟跳变或绕过正式路径的 SQL 维护。

数据库恢复、导入或替换历史必须在维护流程中轮换项目缓存 epoch，使浏览器完整重建。[Task 软删除](daynight-task-deletion.md)在删除事务内轮换同一 epoch，使其他页面完整替换缓存并移除已删除任务；显式解除引用所更新的源任务版本、关系与 ready 同属该完整快照，不扩展 delta 为墓碑消息。其他普通写入和重启不改变 epoch。

## R6：失败恢复

缓存缺失、schema不兼容、结构损坏、数据库异常关闭时允许重新装载完整摘要。schema 12 在升级事务内清空 projects/summaries/details 与相应水位，随后读取完整 snapshot；升级保留 profiles、userScopes 和兼容的 Session 目录，完整 snapshot 可清除项目的可重取目录；从 schema 1–4 升级轮换 userFence，从 schema 7 升级清除缺少完整空证明的 Session 目录。旧缓存不能以缺字段→null 回退解析。旧摘要缺少 tags、properties 或 assignedTo、旧 Project 缺少 ownership 均不能补默认值。active 与 invalidated manifest 都必须验证归属、生命周期及对应格式；invalidated 的 epoch/project/水位必须全为 null，任务与边计数全为零，不能把残留 epoch 作为增量基线。用户 fence 损坏时，在一个事务中轮换 fence 并清除或失效该用户可重建任务、人员及 Session 目录内容，不依赖损坏 fence，也不影响其他用户；旧绑定 scope 和 ticket 不能跨修复发布。IndexedDB 打开、升级、配额、修复及写入失败明确进入现有错误/Retry 状态；失败事务保留原持久状态和允许显示的当前快照，不能当作空项目或同步成功。网络、响应解析及属性读取失败不提交局部摘要或推进水位。读取直接消费规范存储属性，不重复结构或容量检查；自然查询、解码、编码及事务完成故障继续传播，不发布局部成功。重试先读实际存储。

## R7：计时、项目设置、当前权限与 Session 状态

每次成功 snapshot 和 delta 都包含必填的顶层 `actorAccess`，与 Project、任务和属性
来自同一数据库快照。它使用[本人权限合同](daynight-auth.md)的
完整 ProjectAccess：真实 projectId、ownerTeam、ownership、effectiveRole、teamRole、
directGrant 与 canTransfer。ownership 和 grant 版本是无损正 int64 JSON number，不同于任务摘要
version 的十进制字符串。即使 delta.tasks 为空，本人角色和实际 grant 也必须返回。
客户端先核对响应身份，再解码并发布这一投影；旧请求、旧身份和旧项目不能覆盖新观察。
Project 内在字段含必填 ownership，同一 epoch 的 delta 中设置与归属按各自精确版本独立合并，旧版本不能回退，
同一历史中相同归属版本对应不同 Team 是协议错误。新 epoch 的 snapshot 完整替换旧 Project，
数据库恢复后较低的真实版本和归属也必须生效。actorAccess 只进入内存权限所有者，不写入 Project/Task 或 IndexedDB，不改变 epoch、
任务业务版本或同步水位；权限失败与内容缓存失败分别遵守各自错误边界。

每个成功 snapshot 和 delta 同时返回必填的非 null assigneeVersions 完整清单，每项为 {userId,version,hasProjectAccess}，即使 tasks 为空也必须更新。资格、资料内容版本、Project、权限和任务来自同一数据库快照；结构、版本及覆盖规则由[负责人契约](daynight-task-assignment.md#web-人员版本持久缓存与筛选)拥有。清单不传姓名或头像，只在当前已认证、已在线准入的项目内存中发布，不作为持久授权；仅本地摘要 preview 没有这一清单。跨标签页历史更替先产生 assigneeVersions:null 的当前投影时，立即撤回旧人员显示、资格和目录 ready 状态，等待本页新的在线清单；未知清单不等于成功空清单。清单变化不改 Task version、同步水位或图索引，相同资料版本可从独立 profiles store 复用，只读取缺失或内容变化的人员。

每次实际成功同步都取得新 observedAt 与当前 Project；只用于本页显示计时和设置。持久缓存不恢复 performance.now 锚点，重复响应不重建图布局。仅本地摘要的页面不显示最近成功刷新时间、运行中耗时或可能卡住提醒；已完成任务仍可使用持久起止时间显示耗时。概览的近期分类按浏览器本地时区的自然日计算；暂时当前时刻使用本机时间，成功同步后切换为服务端样本与单调时间，分类口径由[Web 需求](daynight-web.md#项目整体进度)拥有。项目设置通过已有 settings.version 合并，迟到响应不得回退设置。

### 轻量 Session 集合与列表读取

每个成功 snapshot 和 delta 都包含必填且非 null 的 `sessions` 对象，即使 `tasks=[]` 也重新返回全项目当前适用会话的完整集合。键为 Task ID，值只允许 `working`、`notice`、`warning`、`pending`；无贡献时返回 `{}`。集合不受任务 `since` 窗口限制，不传 claim、Worker、Worktree 或 Session ID，也不传目录、能力、操作、启动报告、原始活动或连接字段，不增加 Session hash、cursor 或版本。

适用项要求 Task 未删除且仍为 `in_progress`、当前 Worker 适用 Web Session，并且持久 Session 与当前 Task、claim、Worker、Worktree 和控制模式可靠匹配。缺少适用 Worker、当前 Session 或可靠持久绑定时省略 Task 键。仍在进行中的 Task 所关联的 disconnected、idle、stopped、draining 和 archived Session 继续贡献，不能只返回 working 会话。

非 active 生命周期或 disconnected 为 `warning`；已连接且同步的 waiting_input 为 `notice`，idle/stopped 为 `warning`，working 为 `working`。初始化或同步中的可靠会话为 `pending`，表示无角标但仍保留可用的 Session 入口。active 且未断线的 unknown 活动不提供可靠贡献，应省略键。缺少本机 live 状态或 live fence 不匹配时沿用 disconnected、未同步、unknown 的既有归一化，最终为 `warning`；不能把该情况解释为会话不存在。持久 LastSeen 缺席或距今严格超过 30 秒，以及已到 DrainUntil 的生命周期规则保持。

Task、Worker 和持久 Session 的读取共享既有只读数据库快照；live 活动仅从应用共享 Engine 的已提交状态取得。轻量读取不写生命周期，不推进归档、不读取完整 Current，也不改变 Worker 启动、报告、WebSocket、目录、操作、Test/Bot 或 Session 内容访问规则。查询、自然解码和编码、Engine admission、取消及事务完成失败使整个 task-sync 失败，不能变成 `pending` 或成功空集合。状态的最小集合及其判断机制由[同步架构](../design/daynight-task-sync.md#服务端-session-状态投影)拥有；现有列表呈现与入口由[Session 状态设计](../design/task-session-status.md)拥有。

列表仅使用可见时现有 15 秒 task-sync 更新 Session 状态，不另建逐 Task Current 或 status 请求。初始化或同步期间的 pending 入口、完整链的全部普通成员及根任务、折叠与负责人筛选隐藏成员、warning > notice > working 优先级以及原有导航和可访问性必须保留；Goal 列表展开时直接为可见成员提供各自的 Session 状态与入口，不汇总范围链。完整 Current 内容和操作权限继续由详情客户端核验，列表状态不能成为该授权来源。

状态有效期为 30 秒，从成功响应 body 读取完成的本地单调时间起算；捕获必须早于 JSON 解码、source scan 和合同校验。历史、IDB、渲染和普通缓存通知不得续期；处理到发布前已过期的观察不能短暂安装。正常同步等待保留尚有效贡献，当前失败、身份暂停、项目准入失效和执行变化撤销对应贡献，恢复后通过现有同步取得新观察。旧或被取代的响应不得撤销较新观察；身份暂停后恢复也不能让暂停前的响应重新发布已撤销的 Session 贡献。

同一次请求的 Task 观察基线与 epoch、水位从原有同一 IDB 事务取得。snapshot 的执行观察来自实际响应 Tasks；delta 以该基线覆盖实际响应 Tasks。状态值和键缺席均只对 observed/current Task 执行绑定完全匹配的项生效；不能使用最终缓存保留的较新 Task 给旧状态改绑。Task ID 相同但 claim、Worker、Worktree、Worker state、模式或适用状态变化时，旧值及旧缺席均不能新增、替换、删除或续期较新执行。

Session 列表状态仅驻留当前账户和项目的页面内存，由页面同步所有者独立发布给其消费者。其它标签页或缓存来源只可使失效 Task 绑定撤销，不发布或续期本页 Session 状态。状态变化不写 Task properties、version、updatedAt 或 IndexedDB，不进入 BroadcastChannel，不增加普通 Task 通知、正文读取或额外任务图构建；task-sync 原有 Task 应用仍保留。Session 记录目录保持独立持久合同。Web 严格要求必填四态 map 和规范 Task UUID，不限制其存储任务条数；缺字段、null、非法形状、键或值为协议错误。服务端支持先于新 Web 消费，回退服务端前先回退该 Web consumer。

## R8：身份与失效

按 API origin、用户、项目隔离。同步、详情及全部任务写响应在正文或资源错误处理前核对实际 `Daynight-User-ID`；缺失或无效头属于协议错误，不能据其 404 清理有效缓存。可信不同用户先同步通知根账户 owner 并拒绝响应；根 owner 进入等待刷新，保留已呈现内容和原 scope，停止远程准入。会话失效与项目撤权仍立即释放所属内容，旧请求不能恢复它。每次增量读取仍检查服务端访问权限。

项目同步的可信 `404 not_found` 撤销捕获项目 generation 的内存准入和正文复用权限。Task GET 或已提交写入的同用户可信 `404 not_found` 先撤回该任务详情，再重新验证项目访问；不能仅凭 Task 不存在断定项目撤权。项目重验确认撤权后按捕获生命周期清理，旧 E1 响应不能清除 E2。当前历史的可信 `410 task_deleted` 只退休对应任务与阅读资源；新 opening 可重新实时 GET。状态、许可、暂停解除、平台、负责人和删除的旧历史结果均受操作所有者和历史准入约束，不能修改恢复后的详情或释放新写锁。

已提交写响应触发的项目访问重验与确认撤权处理归仍存活的身份 scope，即使发起它的详情会话或页面已经释放也必须继续；UI 释放不能跳过可信 not_found，身份 scope 结束仍使旧响应失效。在仍存活的身份 scope 中撤权立即生效，持久清理失败也不能使 Retry 从磁盘恢复私有正文、摘要、人员资料或 Session 目录；当前身份 scope 内切换项目、卸载重挂、轮询或普通广播均不能恢复本地摘要预览，必须成功在线同步该项目后才可恢复。按 generation 清理保留了较新的完整持久集合，也不构成重新显示的授权。人员内容的持久记录受 userFence 约束；普通任务 epoch 更替可保留内容供新的在线人员清单按 version 验证复用，但项目撤权、注销或身份失效清除所属人员内容，旧响应不得跨当前项目 generation 发布。撤权负向提示只使匹配用户 fence/generation 的其他标签页拒绝旧内容，不授予访问，账户准入暂停期间也可立即处理；存储清理和正向读取仍等待身份 gate。清理只操作 ticket 匹配的持久 generation，不扩展为删除其他历史或新 generation 的承诺。

Session 记录目录按已认证用户、项目和任务隔离，受 userFence 与 cacheGeneration 约束。成功首页与确认空结果可持久复用，打开或重新激活时仍后台重读，不能用 Task version 判定历史新鲜。确认空目录在后台刷新期间保持隐藏；已有内容在普通失败时保留并提供重试。缓存仍可读但刷新或分页所需事务写入失败时，保留已有有效内容并显示可恢复错误，不发布无法排序的新成功响应。未知、失败、完整空与仍有 nextCursor 的未完成目录必须区分；首页为空且有 nextCursor 本身不证明完整空，后续页全部耗尽可独立确认并缓存空目录，同时保留原首页及 cursor。重新激活已确认空目录时，如刷新首页仍为空且有 nextCursor，后台继续读取后续页直至发现记录或真正耗尽。缓存不得成为实时 Session 控制或归档正文的授权来源。正常存储路径中，身份切换、撤权、删除和 generation 变化阻止旧内容及迟到响应重新发布。IndexedDB 完全不可读写时，迟到的旧撤权提示可以保守隐藏另一标签较新的成功结果，并提供重试；若撤权时所有持久媒介均不可写且全部相关标签关闭，下次启动可能在网络撤权响应前短暂显示旧目录。其他生命周期机制见[缓存架构](../design/daynight-task-sync.md#5-indexeddb-与去重)。

## R9：交互与详情

保留筛选、展开、选择、视口、全屏、滚动，以及独立详情页和附件工作区的阅读/操作状态。摘要来源的磁盘正文显示同时要求本挂载成功同步 receipt 和 scope 当前仍授权的项目 generation；撤权后旧 revision 不能恢复准入。每次打开记录本次 opening 的 live GET 要求，pending/unknown/核对期间也保留；磁盘、写结果或重开前核对不能替代它。任务写入绑定审阅时的来源资格与历史，操作接受时同步捕获该历史及所有者；每次异步准备完成和发送前重新检查，不能以新 `beginSync` ticket、相同 task ID 或业务版本延续旧历史确认。失效准备零写入，只 GET 当前历史，fresh GET 后重新确认；旧准备不能改写较新 owner 或释放其写锁。仅关闭详情不取消仍有效的已接受意图。账户变化暂停时取消尚未派发的准备，保留本地结果与展示；普通结果不得越过 gate 发布，真实刷新前不自动恢复或重放。未发送的失效准备以本地冲突或拒绝结束并只读刷新，已发送的旧历史结果进入 unknown 与 GET 核对；身份结束使旧操作失效，不能因受阻 getter 的异常留下永久 pending。可信已提交 404 的任务撤回继续优先于普通等待，项目访问通过独立重验判定。摘要来源的项目 generation 改变立即清除旧正文、PR 与已加载权限；direct 来源按身份、访问与 epoch 历史退休。相同任务 ID、版本或时间不能证明属于同一历史。

direct 来源不要求项目 manifest、图或 SyncTicket；当前身份、项目、Task、history 与 opening 内的完整实时 GET 必须验证响应主体和 `Daynight-Task-Epoch` 才能授予详情及写入资格。图缺席不证明删除。成功写保留确认事实和已提交版本下界，带 epoch 的后续 GET 达到下界后才重新允许写；失败保留确认和错误，不重放。Steps 用该观察的父版本，集合推进时有界补读父 Task 和集合。图与 Task GET 共同观察 epoch：换代立即退休旧图、详情、Steps 与阅读树，旧响应不能恢复它；新历史下至多自动补读一次。关系独立读取，失败只影响关系区域；局部任务链不声称包含全部外部后续任务。direct 内容和 Session 目录只在当前 opening 内存准入。

重复摘要不触发没有变化的详情 GET。服务端依赖状态变化更新本地派生字段，原始服务端差异继续保留陈旧提示与禁写。暂存版本高于摘要时等待，相等时受保护准入，已被摘要越过则丢弃并通过现有读队列重新 GET。普通读取恢复保持普通读取的用途：失败显示读取错误与 Retry，成功 GET 清除其读取阻塞状态，不改变原操作阶段；操作结果核对继续保持核对用途、意图和 outcome，失败时检查状态可用，成功只清除相应核对阻塞。两者不得相互留下不可见的永久禁写标记，也不重发写操作。

详情每项目最多 32 条、总 8 MiB、单条 2 MiB，按自身内容的精确 UTF-8 JSON 字节与 lastUsedAt 淘汰；超大成功正文可在会话显示而不持久化。真实缓存错误可见、可 Retry；同资源、同 generation 且仍获授权的成功内容才可在恢复性错误中保留。附件继续独立按需读取。

## R10：验证与效率

在数据稳定的夹具中读取完整公开任务事实，对照本地物化的完整项目图；完整 task-sync snapshot 或任务列表/详情均可提供这些事实，不能把局部任务链图当作全项目对照。验证同时间戳不同任务/版本、边界包含、重复去重、迟到响应、多标签页、完整初始化、离开超过窗口后的追赶、详情不能推进水位，以及恢复/账号失效。验证网络响应挂起时缓存已可见、后台更新、失败保留、有效空缓存、无缓存加载和撤权清除；两标签页中较新 generation 被保留时，拒绝响应后的 Retry、轮询和同 scope 导航/重挂仍不能先发布，成功在线恢复后才重新显示。本地摘要不得启用详情或伪造同步时钟。

响应 ID 集合等于对应快照内窗口条件选中的任务，重复是合法数据；移除“无变化必为零任务”和“只改一个任务必只返回一个任务”的要求。记录实际窗口命中数、重复率、正文与传输字节、IDB 读写及投影耗时。自身字段和依赖状态均未变化的重复数据不得导致重复 IDB 写入、详情失效、图布局或广播。验证 schema 12 重建、持久读回、同版本自身冲突、依赖状态变化的持久化与发布、隐藏终态及未结束前置、Goal 存在但不入图，以及 epoch 和迟到响应隔离。

完整属性随摘要传输和持久化，不截断、不静默丢键。写入入口拥有属性结构、字段、规范化和现有容量规则；同步读取直接装载规范值，不再次校验存储数据，不设置图规模或响应字节预算。完整响应含 `sessions`，自然查询、解码、编码或持久化错误不发布部分结果。详情的 8 MiB 缓存预算不覆盖摘要。测量实际样本、接近写请求上限的 PR 值和较大属性的多任务样本的响应字节、解析与 IDB 提交时间；不承诺所有合法属性总量都能满足浏览器配额。网络或配额失败保留旧有效缓存和水位。

Session 集合验证覆盖空 delta、无贡献 `{}`、窗口外活动 Task、所有既有状态判断、身份不匹配、缺失 live 和 fence 不匹配、同快照批量读取和自然错误传播。轻量读取不能取得完整 Session 内容、目录或操作。Web 验证同时覆盖 body receipt 的真实顺序、同事务请求基线、snapshot/delta 观察、旧值与旧缺席、30 秒期限、失败与恢复、全部角标/入口及 memory-only 边界。列表/Overview 在多个同步周期内没有完整 current；Session-only 变化不增加 Task 缓存写入、正文失效、普通通知或图计算。

本合同不新增分页、流式 staging、项目属性字节预算或遥测上传。

保留四种容量图各五次的既有门槛：打开图不超过 3,000ms，选择、详情、缩放和平移反馈不超过 300ms。新增缓存耗时先实测，不设无依据的绝对门槛。

## 范围边界

[任务 Thread](daynight-task-thread.md)采用独立消息 Id 分页；发言不改变 Task version、updatedAt、properties、依赖或 epoch，不进入摘要及图投影。消息连续读取位置不能使用 task-sync 水位替代。

保留在线写入与服务端权限、版本、依赖检查。当前不包含绕过身份核验的离线冷启动、离线写入或即时推送。时间窗口重复传输是主动接受的取舍；不增加变更日志、同步递增序号或独立的事后 updatedAt 写入。
