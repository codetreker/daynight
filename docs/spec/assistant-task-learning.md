# 助手任务的结果记录与经验沉淀

助手在[助手任务](assistant-task.md)中反复处理同类事项时，应当越做越好。Session 历史可能被压缩、淘汰，或因接手而更换负责助手，因此经验必须保存在助手任务的持久材料中，不能依赖 Session 上下文。本文拥有结果记录、复盘、附录验证、相关经验查询和能力指标的必需行为。[设计](../design/assistant-task-learning.md)说明存储与机制。手册、附录、修订提案、事项、记录和事件的通用规则沿用助手任务规格。本规格的要求随对应实现逐项生效，未交付的部分不得作为现行能力对外声明。

经验沉淀分为三层：工作记录保存每次发生了什么，附录保存从记录中提炼的经验，手册规则保存经用户批准后可以直接执行的做法。

## 结果记录

负责 Bot 可以追加 `outcome` 类型的工作记录，结果取值为 `effective`、`ineffective` 或 `inconclusive`。结果记录必须引用同一任务的一条 `action` 记录，可以通过既有引用字段引用作为证据的事件或其他记录。写入权限与负责 Bot 的其他工作记录相同，需要当前认领。

其他类型的记录不得携带结果取值或动作引用。引用的记录不存在、属于其他任务或类型不是 `action` 时，请求被拒绝。记录保持只追加：结果在动作之后单独记录，原动作记录不被修改。同一动作可以有多条结果记录，后来的观察不覆盖先前的观察。

## 复盘

复盘事件提示负责 Bot 回顾工作记录并提炼经验。它不点亮关注。

- **事项复盘**：事项从打开变为关闭时，服务端在同一事务中向负责 Bot 生成一个 `retrospective` 事件，负载引用该事项。
- **周期复盘**：距上次复盘至少 7 天，且其间存在新的结果记录时，服务端在下一次事件拉取中生成一个周期 `retrospective` 事件。服务端不新增调度循环；没有事件拉取时不生成。

任务暂停时不生成复盘事件。复盘事件按普通助手任务事件投递和确认。

## 附录的适用范围与验证

附录可以声明适用范围：项目 ID、事件类型和事项类别，均为可选集合，省略表示不限定。负责 Bot 可以引用一条结果记录，为附录登记一次验证；`effective` 计为成功，`ineffective` 计为失败，`inconclusive` 不能用于验证。同一结果记录对同一附录只能登记一次。附录读取返回适用范围、成功与失败次数和最近验证时间。

附录仍只是经验参考，不参与可执行规则，不能扩大直接动作。用户可以修改或删除附录；删除后其验证登记一并失效。

## 相关经验

Bot 可以按项目、事件类型和事项类别查询相关附录。查询只返回未删除的附录，按范围匹配程度、最近验证时间和 ID 排序，最多返回 5 项。Worker 投递助手任务事件通知时，按通知涉及的项目、事件类型和事项类别附上相关经验的有界摘要，并给出读取完整附录的命令。

## 规则提升

经验成为可执行规则只能通过现有修订提案，并由用户决定。提案可以引用结果记录和附录验证作为证据。已被拒绝的相同规则在没有新证据时不得重复提出，这一点沿用现有规则。

## 能力指标

任务提供最近 30 天的能力指标，供 CLI 与网站读取：

- 动作记录数量，以及结果记录中 `effective`、`ineffective` 与 `inconclusive` 的数量。
- 升级（`escalation`）与结果未知（`result_unknown`）事件的数量。
- 该时间窗内关闭的事项数量和平均解决时长（从首次打开到关闭）。
- 复发数量，即 episode 大于 1 的事项数量。

指标在一次数据库快照中计算，并返回计算时间与时间窗边界。

## 验收

- 结果记录只能引用同一任务的 `action` 记录，其他类型带结果字段被拒绝，重放请求返回原结果。
- 事项关闭时恰好生成一个复盘事件；满足条件的事件拉取生成周期复盘，不满足时不生成，暂停任务不生成。
- 附录可以声明范围并登记验证，同一结果记录重复登记被拒绝，`inconclusive` 不能登记。
- 相关经验查询按范围与验证时间排序并受数量上限约束；事件通知附带相关经验摘要。
- 能力指标与基础记录、事项和事件一致。
