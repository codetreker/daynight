# 个人 Worker Prompt 编辑区的容器布局

本文规定用户级、项目个人级和 Worker 级 Prompt 编辑器的可用宽度、布局切换与回归验收要求。三个入口的资源、保存及权限语义由 [Web 规格](daynight-web.md#个人-worker-prompt)定义，布局机制由 [Web 设计](../design/daynight-web.md#个人-worker-prompt-编辑)定义。

## 问题与目标

项目设置的内容宽度同时受到站点侧栏与设置导航占用。在视口宽度 768px 时，Prompt 内容区可能只剩 314px。按视口 760px 判断单列的布局仍选择编辑区和说明区双列，固定最小宽度的说明区将编辑面板压缩到约 34px，textarea 仅约 26px。标题与提示近乎逐字纵排，保存操作被推到很远的页面下方，输入框聚焦后也不会恢复可用宽度。中英文均受影响。

该问题并非手机视口专属：较小视口可能已经切成单列，而带有多层导航的中等视口仍然错误地选择双列。用户级、项目个人级和 Worker 级入口的外围导航不同，因此相同视口不代表相同编辑空间。

目标是按编辑器实际可用宽度选择布局，使内容受限的入口保持可读、可编辑，并在空间充分时保留编辑区与说明区并排阅读。

## 布局要求

三个入口必须共享同一宽度规则。判断对象是 Prompt 组件外层容器扣除外围导航后得到的实际内容宽度，而不是浏览器视口宽度。

| 实际内容容器宽度 | 必须呈现的布局 |
| --- | --- |
| ≤620px | 编辑区在前、说明区在后，按原有 DOM 顺序单列排列 |
| >620px | 保留编辑区与说明区的双列布局 |

620px 本身属于单列。用户调整窗口或展开、折叠站点侧栏后，布局必须跟随新的实际空间变化；不得要求刷新页面或重新打开编辑器。设置导航的既有窄屏排列规则继续有效，不能以调整宿主导航断点代替组件宽度判断。

标题、正文、textarea 与保存操作不得因说明栏挤占而退化为近乎逐字符宽度。中文、英文、长单词、长行与多行内容均须保持可操作；长内容可增加必要的纵向滚动，但不能造成整页横向溢出。说明、追加顺序和组合示例必须保留，可通过页面或示例区域的正常滚动阅读至末尾。内容足够宽时不得无条件放弃双列。

## 编辑与权限边界

宽度变化只影响排版，不能重建正在编辑的 textarea、覆盖草稿、移动键盘焦点或重置选区。跨越 620px 边界、切换站点侧栏及改变视口时，当前层草稿与组合示例继续对应，示例场景选择保持。

输入、保存、清空、放弃、离开确认沿用原有行为。文字、空格和换行必须原样保存；保存空正文仍表示清空当前层。取消离开确认必须保留草稿并恢复相应编辑焦点。放弃修改不能撤销已经发送的写入，布局变化不能产生额外请求或重放保存。

布局规则不得改变账号、项目成员或 Worker 的资源绑定与权限准入。项目个人 Prompt 仍由各成员维护自己的内容，不因共享设置需要管理员而限制普通成员。读取失败、写入待定、版本冲突、结果未知和确认失权时的状态处理、按钮限制与草稿保护沿用现有编辑器语义，不能为使布局可测而绕过这些状态。

## 验收标准

### 真实几何与邻近宽度

在中英文界面，对三个入口分别覆盖 320、375、390、768、1360px，以及宿主导航和旧视口断点附近的 739、740、741、759、760、761px。每组覆盖站点侧栏展开与折叠；在窄屏固有侧栏形态下也应确认其既有行为未回归。

记录实际容器、编辑面板、textarea 与说明区的几何及文档滚动宽度，确认单列或双列取决于实际容器。项目设置 768px、侧栏展开的复现场景必须从窄字符栏恢复成可用输入区；仅证明页面没有横向滚动，或者断言某条 CSS 字符串存在，均不足以验收。

额外构造实际内容容器 619、620、621px 的连续变化，确认 619px 与 620px 单列、621px 双列，并确认返回原宽度后仍满足规则。该检查必须使用浏览器排版结果，不能用不执行 CSS 布局的 DOM 环境替代。

### 交互与长内容

在三个入口中输入中英文混合长行、多行、空格及长单词，验证输入与组合示例可读，说明与长示例可滚动至末尾。保持输入框聚焦和非空选区，连续跨越单列、双列边界，验证同一编辑节点、草稿、焦点和选区保持。

通过真实页面验证保存及空正文保存，并以对应资源读回确认原文和清空结果。验证放弃修改、带草稿离开、取消离开后的草稿与焦点恢复。共享保存机制可在隔离资源上完成真实写入验证；报告须区分实际写入覆盖的入口与只验证草稿交互的入口，不能把模拟回执描述为真实保存。

保留与当前层无关的资源和运行配置；验证不能修改其他成员的 Prompt 或使用生产任务作为测试载体。对已有失败与权限状态的回归，应确认编辑器保护仍有效，不因尺寸变化而发送写入、清除错误或恢复未经授权的操作。

### 证据与完成条件

浏览器证据必须标明受测前端版本、实际服务版本、语言、视口、侧栏状态以及几何和交互结果。截图应与同一稳定状态的几何配对；视口模拟不能据此宣称覆盖真实手机软键盘、触摸设备或屏幕阅读器。

可执行回归应能在原布局上暴露受限容器缺陷，并在修复后通过上述目标行为与边界检查。实现验收以实际产品复测为准；原型、规格、通过的辅助脚本或合并文档本身不建立修复完成结论。
