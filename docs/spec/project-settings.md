# 项目设置工作空间

项目设置按用途提供五个分组，所有有权访问项目的成员均可进入；操作权限和个人资源归属仍由各功能的现有规则决定。项目页只有一个“项目设置”入口，设置页提供返回当前项目的入口。侧栏在所有分组中保持所属项目的选中状态。

| 顺序 | 中文 | English | 内容 |
| --- | --- | --- | --- |
| 1 | 执行与提醒 | Execution & alerts | 执行提醒阈值、输入校验、保存与取消、冲突和结果 |
| 2 | Worker 提示词 | Worker prompts | 当前用户的项目个人提示词、预览与作用层次 |
| 3 | GitHub 集成 | GitHub integration | 仓库连接、安装、同步状态与管理 |
| 4 | 成员与邀请 | Members & invitations | 成员身份、有效角色、Team 继承、独立项目授权与邀请 |
| 5 | 项目管理 | Project management | 项目归属、转移和删除 |

## 地址与导航

`/projects/{projectId}/settings` 默认进入执行与提醒；`?tab=execution|prompts|github|members|management` 指定分组。`/projects/{projectId}/members` 直接显示同一项目的成员与邀请分组，不重定向。空、重复或非法 `tab` 显示导航错误和默认分组入口，保留项目上下文。其他查询参数及已有授权错误处理沿用现有规则。

分组链接支持直接访问、刷新、修饰键和新标签页；实际切换记录浏览器历史，重复选择当前组不新增条目。历史恢复相应分组，包括旧成员地址；URL 与历史不保存草稿、秘密或操作结果。刷新按身份和权限读取已保存资源，不保证恢复未保存内容或一次性链接。

桌面导航纵向排列，手机导航横向滚动，选中项保持可见；320px 页面不产生横向溢出，宽成员表格可在自身区域滚动。方向键按导航方向切换，Home/End 选择首尾，选中项和正文具有可访问关联。隐藏组及其浮层不可交互；打开模态时保留焦点约束，历史切换离开所属组时暂停浮层，返回后恢复。

## 状态与操作

同一用户和项目的组间切换保留草稿、原始输入、校验、预览、展开内容、操作结果及各组阅读位置，不自动保存、取消或重发操作。首次进入从组顶部开始，返回时恢复有效位置及编辑上下文；内容变短时可限制到可用范围。非当前组以“未保存”“处理中”“需处理”表达各自实际状态，普通后台检查不标记为业务处理中。某一资源读取失败时显示其错误和重试，不阻止其他可访问资源。

进行中、确认、拒绝、冲突和未知结果属于原用户、项目及操作。隐藏不表示取消或回滚，旧结果不得覆盖较新编辑、关闭新的确认或抢走导航。设置、GitHub、转移和删除沿用共同写入保护；成员和邀请保持独立操作限制，个人提示词保持独立资源生命周期。未知写入通过只读核对处理，当前读取不证明原操作成功，也不自动重放。

同项目设置地址和旧成员地址之间切换不触发提示词放弃确认。离开整个工作空间时沿用提示词离开保护；取消离开后选择提示词组并恢复有效编辑焦点。普通后台身份检查保留界面；真实账号变化、项目删除或访问撤销撤回不可访问的私有内容和秘密，旧响应不得恢复它们。

成员组继续区分有效角色、Team 继承和独立授权。Project admin 可按现有规则管理独立授权及邀请；移除独立授权不改变 Team 关系，也不必然使成员失去访问权。普通成员不因此获得退出项目或管理 Team 角色的能力。邀请链接只在创建结果中展示，列表不含秘密；手动复制、复制失败恢复和关闭前的一次性提示仍可用。已展示的链接在暂离整个设置工作空间后返回时保留，直到明确关闭或真实主体、资源失效。邀请撤销的未知结果及重复操作限制按原邀请 ID 保留，不因列表读取、其他操作或切换分组清除。

确认本人授权变更后按可信回执处理实际权限；隐藏成员组不延迟真实失权对其他设置组的撤回。失权后仍显示合法的本人成功反馈或已确认等待说明及返回入口，但不显示旧项目标题、名册或秘密。后续 404 不证明未知写入成功，也不能使结果导航到另一个项目。

各功能的具体权限、版本、错误和恢复规则由[认证需求](daynight-auth.md)、[执行提醒](daynight-task-timing.md)、[个人提示词](worker-prompts.md)及 [Web 需求](daynight-web.md)拥有；[工作空间设计](../design/project-settings.md)说明状态与展示的组织方式。
