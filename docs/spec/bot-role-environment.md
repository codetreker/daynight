# 助手角色与 CLI 运行环境

## 角色职责

Daynight 助手使用真实 CLI 查询和操作系统，适用于无项目、单项目和跨项目请求。
角色通过 CLI help 发现实际命令和参数，不假定工作目录属于 Git 仓库，不定义任务
动作白名单。普通查询和已授权直接操作无需创建 Goal；存在交付目标时，按适用的
需求、方案、交付与验收阶段推进，保留阶段确认和执行授权。

规划应核对已有工作，明确需求、范围、资料拥有者、输入、产物消费者、必要交换
约定、执行条件及成功和失败验收。独立任务围绕可交付结果划分，明确并行条件和
共享资源约束，区分链内普通依赖与同项目跨链外部前置，排除循环、遗漏与冗余边。
实际登记后读回正文、附件内容与依赖图；创建、允许自动选择和实际认领分别报告。
整体完成需要确认需求对应的组合交付证据，不能从一个任务 done 推导。

进展回答读取当前事实并按需引用，避免默认读取全部 Session 历史。任务状态、
暂停、依赖就绪、权限、Worker 在线和空闲容量具有不同含义；未知或过期信息不能
表述为可用。写入使用决策时读取的精确版本；冲突重读并重新判断，未知结果先核对
原对象或请求身份，不盲目重复写入或发送。解除阻塞不能以删除真实前置或伪造完成
代替验收。

## 冻结和恢复

唯一模板由 Worker 的 `bots/instructions.ts` 拥有，文本变化必须更新 revision。
仅在首次启动准备、服务器角色和本地准备均已确认不存在时生成角色。生成结果
包含完整 `instructions`、`revision` 与文本 UTF-8 的 SHA-256 小写十六进制 digest。
模板不接收配置、凭据或用户请求作为插值输入。

已有服务器角色必须原文复用；本地资料丢失可用服务器值重建。本地已准备而登记
结果未知时，保留本地原值用于原 registration 核对；双方同时存在但任何字段不一致
时拒绝继续，不能覆盖或渲染替代值。缺失必须是权威读取确认的 `null`，读取失败
不能当作缺失。模板升级不改变既有角色或恢复代际。

角色必须符合[共享角色契约](controller-role-instructions.md)的 Unicode、非空白与
64 KiB UTF-8 限制；revision 非空且 Unicode 良构，digest 必须匹配。不裁剪、
规范化或改写持久值。角色属于原生启动配置，不能以用户消息或隐藏 turn 发送。

## CLI 环境与认证

启动和恢复前，从目标 Worker 的配置路径设置 `DN_CONFIG_DIR`，包括没有 alias 的
情况。真实 `HOME`、`CODEX_HOME` 等原生目录保持原值；PATH 继续使用已有 alias
准备规则与 Provider 的 native PATH 合并规则，不为 Bot 创建替代原生账户目录。

CLI 使用该配置根中的正常认证。检查当前 server 与 Bot 绑定服务一致，并通过
当前凭据查询身份，确认与 owner 一致；拒绝未登录、错误账户、服务不一致及未知
验证结果。Controller relay token 不作为 CLI PAT，也不写入角色、命令参数或
诊断内容。检查不授予额外项目或原生工具权限。

在 Bot 的真实 cwd 和准备环境中，以有界、可取消的只读帮助调用检查当前 CLI
所需入口。旧 CLI、缺少可执行文件、失败或超时明确拒绝准备，不能假报成功。
检查只确认当时的配置、账户和入口可用；不能原子阻止用户之后修改 CLI 全局配置，
也不能将帮助命令成功解释成业务操作权限或 Provider 可用。

## 消费者与验证边界

这些 helper 不建立新 skill 或业务 API，不启动 Bot。托管消费者负责先持久化首次
角色意图，再以原 registration 提交服务端冻结值；取得角色后写入 launch ticket，
使用 `initialInput: "none"` 与空 `initialPrompt`。消费者同时负责启动/恢复前调用
环境检查、保留执行所需 alias 并在后代停止后释放。

自动检查覆盖新角色与旧冻结值、未知登记保留、冲突及损坏拒绝、精确 UTF-8 边界，
以及配置根、身份、CLI 能力、alias、超时/取消和清理。模板内容需要针对查询、规划、
冲突和未知结果情景评审。源码与 helper 验证不证明真实模型遵循指令、三 Provider
端到端托管或完整助手体验；组合运行需另行验收。
