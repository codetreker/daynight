# 任务外部依赖与任务链边界需求

本文定义依赖边的外部标识、执行前置和任务链展示的目标行为。
[架构](../design/daynight-external-dependencies.md)拥有存储、接口与计算机制，
[交互原型](../design/mockups/external-dependencies/index.html)拥有目标视觉和交互。
依赖性质持久化、完整任务与图输出以及 CLI/Web 严格读取已实现。
Web 已按普通依赖弱连通分量归组，并按显式边性质绘制虚线和标注详情关系。
公开 API 已支持分类创建及部分 PATCH，CLI 使用普通/外部选项声明完整替换关系。

## 范围与设计边界

已确认的方向是在依赖边上区分普通依赖与明确的外部依赖。两者都是真实执行前置，
普通依赖还用于计算任务链，外部依赖不用于把两端的任务链合并。
当前范围不引入持久化 `groupId`、独立任务组资源或手工成员管理。
任务链采用普通弱连通分量及派生代表；无普通连线的任务保持独立。
普通依赖变化会使任务链合并或拆分，代表任务也可能变化。
不为呈现分组增加虚构前置。

## ED-R1：依赖分类与资源

每条 `(project_id, task_id, depends_on_task_id)` 关系保存一个外部标识。
普通依赖为 `false`，外部依赖为 `true`；默认新增关系为普通依赖。
同一关系只能存在一次，不能同时声明为普通和外部。

完整任务、列表、ready、写入结果及图任务均返回：

```json
{
  "dependsOn": ["A", "B"],
  "externalDependsOn": ["B"],
  "blockedBy": ["B"],
  "ready": false
}
```

示例中的字母代指合法 task ID。`dependsOn` 保留全部前置 ID，
`externalDependsOn` 是其中的外部子集。两个字段均为必填数组，
按正规化 UUID 排序且不重复；读取器拒绝缺失、`null`、非法 ID 或不属于完整依赖集的外部 ID。
依赖列表没有添加顺序，“第一个依赖”不建立任何优先级或组身份。

现有字段含义继续有效：`blockedBy` 包含全部未完成前置，
`ready` 仍是已批准 todo 且全部前置完成；任务列表 JSON 只省略 description，
其余资源字段包括外部依赖、精确版本和计时值均保留。

## ED-R2：创建、更新与一致性

HTTP 创建和 PATCH 接受 externalDependsOn，并校验其属于最终完整依赖集。
元数据及生命周期写入保留未修改的关系性质，新增未分类关系为普通。

创建请求可省略两个依赖字段，分别表示空依赖集和空外部子集。
显式提供外部子集时，必须同时满足它属于最终完整依赖集。
缺失的普通或外部前置都不能绕过同项目引用检查。

PATCH 继续使用观察到的精确任务版本。两个字段独立可选：

| 提供的字段 | 要求的结果 |
|---|---|
| 都省略 | 保留全部关系及其性质。 |
| 仅 `dependsOn` | 替换完整关系集合；保留仍存在关系的性质，新关系为普通。 |
| 仅 `externalDependsOn` | 保留完整关系集合，替换其外部子集。 |
| 两者都提供 | 使用新的完整关系集合及其精确外部子集。 |
| `dependsOn: []`、外部字段省略 | 移除全部依赖及对应性质。 |
| `externalDependsOn: []`、完整字段省略 | 保留全部依赖，将其全部设为普通。 |

无效外部子集、未知或重复字段、`null`、重复 ID、非法 ID、自引用、缺失任务、跨项目引用均明确拒绝。
拒绝不能留下部分修改。分类变化与任务字段、版本和时间在同一项目事务提交。
只改变关系性质也属于有效修改：任务版本增加一次，`updatedAt` 更新，
`startedAt`、`completedAt` 与状态保持不变。
正规化后的完整集合及外部子集都相同时为语义无变化，版本和更新时间不变；过期版本仍须先冲突。

修改标题、描述、PR 属性、allowAgents、requiredPlatform 及 set-status 都必须保留关系性质。
附件操作继续独立于任务版本，不影响依赖。

## ED-R3：执行、权限与容量

所有真实依赖都参与环检测、阻塞、就绪、领取和完成检查。
全外部或普通与外部混合形成的环，同样返回 `dependency_cycle`。
外部前置未完成时，任务仍不能进入 in_progress 或 done。
外部标识不能跨越项目边界或扩大读写权限。

沿用当前项目授权、项目写锁、版本冲突和错误语义。
未授权请求不能修改分类；锁等待后的成员移除或权限变化仍按现有规则复核。
取消和数据库失败保留原错误链，响应丢失按现有不确定写入规则读取核对，不能盲目重发。

完整图上限仍为 1,000 个任务、5,000 条真实依赖，外部边计入同一上限。
外部子集不构成第二份依赖或额外边数。CLI 的超时、解码字节和累计响应预算保持明确且可验证。

## ED-R4：任务链计算

Web 以普通依赖计算唯一成员归属，执行一致性、阻塞和上游上下文继续使用全部依赖。

删除外部边后，以普通边的无向连通分量作为任务链成员集合。
方向仍用于执行和布局；忽略方向仅用于判断属于同一条链。
例如普通边 `A → C ← B` 只产生一条含三个任务的链，不能重复计入 C。
外部边 `X ⇢ C` 保留前置关系，但不把 X 所在普通分量并入该链。

每个任务只属于一个普通分量。分量有多个普通起点时仍显示一个入口。
代表任务取分量中普通入度为零、且在服务端精确 `(created_at, id)` 顺序中最早的任务，
标题取其标题；任务链按代表任务的精确创建顺序倒序显示。
分量、代表任务和入口身份均为派生值，不提供持久组 ID。

保留项目“任务列表”内的“任务链”和“独立任务”页签；项目概览和任务列表共用同一完整快照。
多成员分量进入任务链；普通入度与出度均为零的单成员分量进入独立任务，
即使它有外部前置或外部后续。“独立”不表示已经就绪。
独立任务行须在存在未完成前置时显示“被阻塞” / “Blocked” 徽标，
复用现有图卡片的阻塞表达；外部前置造成的阻塞不能只靠未出现 ready 标签暗示。

链进度、聚合状态、未完成数和完成筛选只统计其成员。
所有成员完成才算整链完成；外部上下文不参与链进度。
项目统计仍对完整项目任务去重计算。
普通边的增删或性质切换可以使链合并或拆分，也可以改变标题与排序。

## ED-R5：完整上下文与视觉

打开链的图浮层时，数据投影包含全部成员及沿两类边追溯的完整前置闭包，
保留闭包内的真实边；链外前置的无关后续不进入投影。
同一任务可作为多个画布的前置上下文出现，但实际成员归属不重复。

虚线箭头只表示显式标记的外部依赖，实线箭头表示普通依赖。
即使外部边两端通过其他普通路径属于同一分量，该边仍画为虚线。
虚线卡片及“外部前置”标签表示当前链之外的前置上下文；
上下文中本来是普通的边仍为实线。图例明确区分边性质与卡片角色。

详情中的前置、阻塞者、后续关系分别以“普通依赖”或“外部依赖”显示关系自己的性质，
“外部依赖”标签不属于任务本身。后续关系从该后续任务拥有的边取得标识。
阻塞状态与外部标识分别呈现。关系导航继续只切换当前详情资源。
Web 本范围提供读取与展示，不新增依赖编辑器。

保留 50 个任务、100 条真实诱导边的初始概览及每次 20 个直接邻居展开。
普通分量和前置闭包保持连通，无需额外组成员展开机制。
选择只改变检查高亮，Details 独立；保留现有路线、视口、焦点、全屏、附件、双语及任务计时契约。

## ED-R6：刷新与浏览偏好

图内容等价比较必须包含外部子集，分类变化可以更新任务链、关系标签和边样式。
仅图时钟样本变化仍不重建任务索引。普通状态刷新保留当前可见集合、视口与检查状态。

图浮层的打开状态仅属于本次项目访问，默认关闭；原展开存储不再读写。
当前打开任务是临时的分量定位依据，合并或拆分后解析到它现在所属的可见多成员分量，
即使它不再是代表任务；只因代表变化而计算新的展示入口时，不覆盖仍有效的原定位任务。
任务不存在、成为独立任务或分量被筛掉时关闭浮层并清除选择，不自动打开其他链。
离开任务链类别或任务列表分区也关闭浮层，返回后等待显式打开。
代表不变而成员集合变化时，重算概览、清除局部检查及旧展开动作，并重新进行初始视口定位；
画布和图浮层所有者保持挂载，保留全屏、已打开详情及其 inert/滚动锁。
代表变化初始化对应图，图浮层继续保持打开。
详情仍绑定 task ID；原触发控件消失时，关闭详情优先回到存活图浮层的关闭按钮，再使用可见列表或页面回退点。
浮层尺寸、关闭、焦点及持久化边界由[Web 要求 W5](daynight-web.md#必须交付的行为)拥有。

## ED-R7：CLI 与 skill

当前 CLI 已在完整资源、列表、ready、操作结果及图中保留和输出外部子集，
人类输出使用 `External dependencies (N): ...`。创建、更新及 skill 指引明确区分两类依赖。

`--depends-on` 声明普通前置，`--external-depends-on` 声明外部前置，均可重复。
只要提供任一种依赖选项，就替换完整关系集合：并集编译为 `dependsOn`，
外部选项的精确集合编译为 `externalDependsOn`。
只提供外部选项表示替换为全外部关系，不表示追加或仅修改分类。
两类选项重复引用同一 ID 是冲突输入。
两类选项都省略时保留关系；`--clear-dependencies` 与任一种依赖选项互斥，提交两个空数组。

CLI 的读取、JSON、人类输出、help、completion、安装产物与 `using-daynight` 同步表达外部性质。
Goal 内部阶段和交付前置使用普通边，只有明确属于其他任务链的真实前置才标记为外部。
不能根据任务已完成、标题相似或当前图入口猜测关系性质。
顶层任务可以有外部前置；其含义是不具有普通前置。
精确版本、完整字段替换、部分注册恢复及批准、执行、合并权限边界继续有效。

## ED-R8：历史数据与交付验收

`012_external_dependencies.sql` 已为依赖行增加非空 `external`，全部旧边取得普通性质，
保留任务、依赖端点、版本、状态、时间、PR 属性和附件。
不按旧根、时间、标题或历史 groupId 草案推断外部性质。
普通连通分量会将以前重叠的多根投影合为一链，这是计算规则变化，不是数据恢复。

历史 worker 串组实例作为隔离回归数据。后续调查发现，原处理角色任务指向 AU-T5、ST-T2 的两条边已被其他操作移除；
设计和验收不能将旧快照当成当前写入清单，也不能自动恢复这些前置。
既有边的分类审计须使用新的完整读取，交付依据与待执行清单；线上重分类需要另外的明确写入授权和当时观察到的版本。

公开外部分类写入必须以所有受支持的依赖读取端已正确消费标识为前提，
避免保存了外部性质却仍将其用于普通任务链归属。每个可部署状态均须可构建、可验证。

验收覆盖迁移、字段保持、部分 PATCH、精确版本、权限与取消、混合环、外部阻塞、重启、
多普通起点、内部路径上的外部边、完整上下文、合并拆分、原型状态及真实 PostgreSQL、安装 CLI、生产浏览器。
存储、服务、CLI 与 Web 分别验证本层约束，独立整体验收验证相同数据跨层的一致行为。
这些验证共同遵守[架构中的固定验收基线](../design/daynight-external-dependencies.md#固定验收基线)，
其中列出 native/container/capacity 场景、容量、样本、性能、拓扑、覆盖率、预算及证据身份的固定源码与具体数值。
架构审阅通过不代表运行时交付或线上问题已修正。
