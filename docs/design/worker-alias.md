# Worker 展示别名

## 目标与边界

当前账号可以在 `/workers` 的 Worker 详情中设置、修改和明确清除别名。
列表和详情优先显示别名，未设置时使用 `machine.name`。详情始终显示原机器名
和完整 Worker ID；列表保留完整 Worker ID 区分同名机器和重复别名。
别名不是身份、操作系统主机名、调度标签或执行配置，不改变 Worker ID、
Session、claim、任务负责人和历史 claim 内的机器名。任务列表不传播别名。

## 持久化与所有权

服务端在持久化 Worker 记录上保存独立的可空别名与递增版本。
初始别名为 null，版本为十进制字符串 `"1"`；版本上限为有符号 64 位整数。
上报只更新 telemetry 和任务观测，不覆盖手动别名，也不推进别名版本。
别名更新不改变最后上报时间、在线判定、执行配置版本或活动 Worker 配额。
重启与刷新从持久化存储读回。旧数据通过迁移获得默认值，旧 Worker 不需要升级。

所有读取和写入均使用认证 principal 的账号 ID 与 Worker ID 定位同一记录。
无法访问的 Worker 返回 `not_found`，不泄露其他账号的别名和版本。
服务端按既有 HTTP、service、core 和 DAO 分层承担协议、事务、规则和 SQL 职责。
实际权限检查不能由 UI 隐藏按钮代替。

## HTTP 合同与兼容

`GET /api/v1/me/workers/{workerId}/alias` 返回
`{workerId, alias: {value, version}}`。`value` 是规范化字符串或 null。
`PUT` 同一路径只接受 `{value, expectedVersion}`，成功返回相同结构，
其中 `expectedVersion` 必须是实际观察的正整数十进制字符串。
null 是唯一清除操作，空串或纯空白不是清除。

事务内确认所有权及版本后更新别名。过期版本即使提交相同值也返回
`version_conflict`，防止把失败误判成幂等成功；版本匹配的相同值不必推进版本。
实际修改原子推进版本，溢出拒绝，不能回绕。读取和写入错误保持既有认证、
输入校验、事务完成与请求错误规则；客户端不自动重放写入。

Worker 列表和详情请求通过 `Daynight-Worker-Alias: 1` 显式协商，
支持的服务端回显该头，并在每个 Worker 中提供必需的 `alias: {value, version}`。
未协商的响应保持原有精确字段集合；report、claim 和 CLI 协议保持不变。
支持协商时缺少字段或字段非法必须拒绝，不从机器名推测别名版本。
旧服务端没有回显时，新 Web 继续读取旧响应，但不提供编辑入口。
未知响应头版本拒绝。列表不为每个 Worker 另发别名请求。

## 名称校验

接受中文、普通 Unicode、组合字符和包含 ZWJ 的 emoji；不做 NFC 转换、
大小写折叠或账号内唯一性限制。去除首尾 Unicode `White_Space` 后必须有
1–80 个 Unicode scalar values，而不是 UTF-16 code units。
拒绝非法 Unicode、全部 `Cc`、`Zl`、`Zp`、U+FEFF 以及双向控制字符
U+061C、U+200E、U+200F、U+202A–U+202E、U+2066–U+2069。
输入中的这些非法字符不能靠 trim 消除后偷偷接受。
前后端使用同一规则；服务端是最终准入所有者。
内容以 React 文本和 `bdi` 渲染，不使用 HTML 注入。

## 交互与连续性

详情标题附近显示“设置别名”或“修改别名”。内联表单有可见 label、
名称输入、长度和字符规则、当前已保存别名、保存、清除及取消。
输入无效时不能保存；清除是独立按钮，不依赖输入框为空。
进入编辑聚焦输入，取消或成功保存恢复入口焦点。Escape 取消；
IME 输入的 Enter 和 Escape 不触发提交或关闭。
提交中阻止重复写入与取消。取消不修改服务端。

保存成功只增量更新目标 Worker 标题及资源，不重置详情页签或其他配置草稿。
背景观测不重建表单、不覆盖输入，也不自动改变编辑开始时冻结的版本。
较早的 polling 响应不能回退已确认的别名版本。
切换账号或 Worker、权限撤回时，旧请求不得发布到新目标。
认证检查期间保留编辑状态，但新的写入必须通过当前账号准入。

失败保留输入并显示可本地化错误。版本冲突必须先显式查看当前已保存别名，
保留原输入，并以观察到的新版本在用户核对后重新提交。
网络或协议故障造成未知写入结果时，同样先读取原 Worker 的别名；
读取成功只表明当前状态，不证明之前哪个请求提交，不自动重试。
检查失败仍阻止重复写入；关闭再打开不能绕过这一限制。

表单遵守 [UI 原则](../ui-design.md)，在中英文、桌面和 320px 宽度下保留
文本换行、键盘焦点与至少 44px 的窄屏触控目标。原型仅属于任务附件，
不进入产品源码、测试目录或 PR。

## 验证职责

Web 测试验证协商精确 parser、输入校验、正文与版本绑定、主次展示、
设置/修改/清除、取消、失败保留、冲突及未知结果读回、账号与目标隔离。
前端浏览器验证实际键盘、焦点、长名称和 320px 无横向溢出。
core 测试验证所有权规则、规范化与版本拒绝，HTTP 测试验证真实协议边界。
DAO 使用隔离 PostgreSQL 验证迁移、持久化、并发 CAS、上报不覆盖与账号隔离。
正常 API 集成顺序验证设置、后续读取及上报、修改和清除，不用 mock 或 skipped
替代真实持久化证明。各模块执行命令以模块 README 为准。
