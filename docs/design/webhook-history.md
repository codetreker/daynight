# Webhook 投递历史与重投

## 历史读取

管理路由通过同一认证模块和 `RegisterRoutes` 提供投递、尝试和载荷查询。每次读取在 Repeatable Read 快照中检查当前凭据、owner 关系和资源资料权限。配置摘要从同一快照读取保留历史中最新的 Attempt，按准入时间及 ID 排序；尚未结束的最新 Attempt 不被旧结果替代。

投递保留事件和原匹配证明、目标快照与固定载荷。资料不可读时只返回允许的关联标识、时间及结果；类型和资源过滤在披露判断后应用。游标绑定主体、owner、资源、过滤条件和资料披露状态，不替代授权。记录进入回收或逻辑保留期结束后，查询不把分批清理误判为原证明损坏。载荷接口单独检查当前资料权限及原保留期限，并返回原字节的 Base64、长度和 SHA-256；不会从当前任务重建内容。

分页的资料状态绑定主体当前可读取的 Project 和既有 Task 删除状态，并加密游标。历史记录和订阅的到期或回收不改变该绑定。绑定使用签发时间作为新 Project 和 Task 的水位；在签发前开始但随后提交的事务可能使游标失效。该检查保守地覆盖主体可读范围，范围内无关任务删除或 Project 权限变化也可能使游标失效。移除签发游标所用的旧 master 后，该游标也不能解密；调用方须从第一页重新读取。

## 重投与执行

客户端提供 operation ID、原时间、主体、配置版本和投递代次。操作围栏先检查原回执；新意图在来源、endpoint、原证明和 Delivery 锁下重新核验权限、目标及期限。同一事务推进代次和手动计数、取得新 FIFO 票据并保存回执。响应中的回执描述原效果，当前投影视图在提交释放连接后用新快照授权。未知提交必须通过原操作核对。

登记只创建一次手动机会；运行器在另一个事务中保存 Attempt，并在明确准入提交后发送。原事件、目标和字节不变。手动失败只恢复仍开放且未到期的原自动计划，成功关闭剩余计划；历史确认和晚到观测独立保留。维护处理沿 Delivery 与 Attempt 的既定锁方向判断活动责任和保留期限。
