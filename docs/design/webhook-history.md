# Webhook 投递历史与重投

## 历史读取

管理路由通过同一认证模块和 `RegisterRoutes` 提供投递、尝试和载荷查询。每次读取在只读 Repeatable Read 快照中检查当前凭据、owner 关系和资源资料权限。配置摘要从同一快照读取保留历史中最新的 Attempt，按准入时间及 ID 排序；尚未结束的最新 Attempt 不被旧结果替代。

投递保留事件和全部原匹配证明、目标快照与固定载荷。资料不可读时只返回允许的关联标识、时间及结果；类型和资源过滤在披露判断后应用。资料披露与当前投递资格分别判断：有权查看完整资料不代表 owner、原匹配或目标 revision 仍满足投递资格。原匹配中任意一个当前连续有效即可满足连续性，但完整性校验始终覆盖全部原匹配。pending／leased 失去资格时投影为 suppressed，再应用状态筛选；Endpoint.enabled 不额外改变历史资格。

历史列表按 `(occurred_at,id)` 的 keyset 顺序读取候选，每批最多 100 条。每个非空批次顺序执行三条集合查询：主查询关联 Delivery 的 Event、Task、项目归属、Team、当前 Endpoint 和必要权限事实；随后按相同 Delivery IDs 分别读取 Matches 及当前 subscription／binding，以及 Attempts。主记录顺序决定页面顺序，两组子集合各自按 Delivery ID 归组，避免关联后行数相乘。SQL 返回事实，Go 执行共享资格规则、协议及原证明校验、哈希和视图构造，逐项处理时不再访问 DAO。

请求预检先验证同一 owner／endpoint 的完整配置；该校验与候选读取共享快照，因此批量结果只需当前 Endpoint 的存在、删除及 revision 事实。真实缺失配置的保留历史入口与已删 Endpoint 墓碑保持各自行为，配置损坏继续报错。主查询通过 LEFT JOIN 保留缺失 Event、Task、项目归属和 Team 的可识别事实；缺失或损坏不能让 Delivery 静默消失。领域校验只消费当前页面及其 lookahead 实际需要的候选，未消费的后续候选不提前触发校验；数据库解码、部分读取、取消和事务完成错误仍完整传播。

列表每批使用主查询返回的数据库 `statement_timestamp()` 作为 fact／payload 完整性及载荷可用性的统一观察点。同批记录在处理期间跨过期限时仍按该观察点判断；下一批取得新的数据库观察点。候选保留期 SQL 中 `now()` 的事务时间，以及游标签发水位的独立观测，各自保持现有语义。详情和载荷点查询继续在各自读取流程中取得数据库时间。

Attempt 按 Delivery ID、generation、sequence、ID 稳定排序。每个 Delivery 最后一条 Attempt 决定 lastAttemptAt 和 lastResult；最新 Attempt 尚未完成时结果为空，不回退旧成功。lastAcknowledgedAt 单独取正常与晚到 acknowledged 观察时间的最大值。

三个集合查询绑定同一只读快照，每个结果读完并关闭后才发下一条。空候选批只执行主查询；筛选后不足时继续下一批。每批三条不等于整个请求固定三条：请求级权限、Disclosure 摘要、保留策略及后续批次单独核算。候选扫描、证明排序／编码、正文哈希和批量保留数据仍有各自成本，批量化不改变这些工作量的定义。

游标绑定主体、owner、资源、过滤条件和资料披露状态，不替代授权。记录进入回收或逻辑保留期结束后，查询不把分批清理误判为原证明损坏。载荷接口单独检查当前资料权限及原保留期限，并返回原字节的 Base64、长度和 SHA-256；不会从当前任务重建内容。

## 分页与资料状态

配置列表、投递和尝试分页使用 Base64 URL 编码的 JSON 游标。游标是调用方可修改的输入；服务严格拒绝未知或重复字段，并核对主体、owner、endpoint、Delivery、过滤条件、资料披露状态和有效位置。每次请求独立检查当前权限，位置只选择当前授权查询中的记录。投递 cursor 指向最后实际返回的匹配项，lookahead 与未消费候选不能造成跳项。游标不包含 URL、签名秘密、载荷或原始 Project/Task 身份集合。

投递分页的资料状态绑定主体当前可读取的 Project 和既有 Task 删除状态，保存资料状态摘要。历史记录和订阅的到期或回收不改变该绑定。绑定使用签发时间作为新 Project 和 Task 的水位；在签发前开始但随后提交的事务可能使游标失效。该检查保守地覆盖主体可读范围，范围内无关任务删除或 Project 权限变化也可能使游标失效。资料状态变化导致游标拒绝时，调用方须从第一页重新读取；服务重启本身不使游标失效。

## 重投与执行

客户端提供 operation ID、原时间、主体、配置版本和投递代次。操作围栏先检查原回执；新意图在来源、endpoint、原证明和 Delivery 锁下重新核验权限、目标及期限。同一事务推进代次和手动计数、取得新 FIFO 票据并保存回执。响应中的回执描述原效果，当前投影视图在提交释放连接后用新快照授权并复查回执有效期。仍保留的过期匹配回执返回 `410 operation_expired`，不推进代次、手动计数或 FIFO 票据；GET 的逻辑过期与首次准入时间规则由[管理模块](webhook-management.md#写入与回执)统一定义。未知提交必须通过原操作核对。

登记只创建一次手动机会；运行器在另一个事务中保存 Attempt，并在明确准入提交后发送。原事件、目标和字节不变。手动失败只恢复仍开放且未到期的原自动计划，成功关闭剩余计划；历史确认和晚到观测独立保留。维护处理沿 Delivery 与 Attempt 的既定锁方向判断活动责任和保留期限。
