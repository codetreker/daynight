# GitHub App 的 Team 使用授权

App 管理员按已知 Team UUID 预览最小 Team 引用，确认原 App 版本和 Team 版本后创建使用授权。普通 Team 和 Personal Team 使用相同授权规则；Personal Team 的名称为空，不查询其所有者的资料。Team admin 只能读取所属 Team 的安全 App 使用投影，不能由此取得 App 管理权或其他 Team 的信息。

授权身份是不可变 UUID，撤销保留墓碑；重新授权使用新 UUID，不恢复旧项目连接。授权和撤权事务按 Team 共享锁、App 根锁、授权、连接及提示的顺序取得锁。Team 根锁冻结与 Team 删除有关的授权集合，App 根锁保护管理员、授权与影响集合；单行版本不能冻结这些集合，因此需要短事务锁。事务不持锁等待网络请求或正文。

撤权重新检查当前管理员、原 App 版本、影响版本和精确授权，在同一事务中解除该授权的连接、关闭同步、清除领取和提示并推进 fence。稳定仓库身份和历史 PR 保留。影响版本随授权或连接集合的实际变化推进；[项目连接](github-app-project-connection.md)与[资源清退](github-app-resource-retirement.md)复用这些停止和影响维护能力。

影响预览只向 App 管理员返回授权 Team 的最小引用和连接数量。项目详情按当前 Project 读取权限在数据库分页前过滤，未获权限的项目仅计入隐藏数量。游标绑定操作者、App、授权、配置版本和影响版本；版本变化拒绝继续分页，每页重新检查当前读取权限。

生产路由公开授权管理和 Team 使用投影。App 管理工作区的 Team 使用授权分区接受精确 Team UUID，核对返回的最小 Team 引用后再提交；修改输入使旧预览失效。授予创建新授权 UUID，撤权确认使用精确授权、配置版本和影响版本。项目连接与 Project/Team 清退组件使用各自专用事务能力，保持权限、锁顺序及影响版本合同。

授权弹窗的 Team ID 标签位于输入行上方，通过原有 label 关联输入框。字段内的专属 flex 行按输入框、核对按钮的 DOM 和键盘顺序排列并垂直居中；输入框占剩余空间且允许收缩，核对按钮保留自然宽度和完整标签。在桌面及 320px 窄屏、中英文和核对中状态下都保持同行，UUID 在输入框内横向滚动，弹窗和页面不产生水平溢出。校验反馈、目标 Team 预览与授权说明位于输入行下方。布局复用现有字段、按钮和焦点样式，仅作用于本功能，保留初始输入焦点、真实 disabled 与 aria-disabled 以及核对和提交的准入判断。

App 删除和 Team 撤权共用项目影响呈现与有限并发的 Project 权限核验；每页发布前逐项重新核验，并检查隐藏数与影响版本。各次读取不是原子权限快照，已观察到的权限丧失或影响范围变化会清除旧项目详情。账户与 App 失权清理受保护内容；同一账户的后台核对保留仍有效的页面、草稿和焦点。提交结果区分 committed、not_committed 和 unknown，未知结果不自动重放，后续读取不能证明原操作结果；工作区保留跨分区的确认回执与未知结果核对入口。
