# 单 Project GitHub 同步执行器

`service/github.Executor` 提供单 Project 的直接执行入口。调用方提供 Project 写事务和只读 snapshot、GitHub 远端读取组件、当前 App ID 与日志器，并以 context 管理执行生命周期。[连接与运行时](github-connection-runtime.md)负责调度扫描、HTTP 管理入口和服务启停。

## 领取与发布

领取在 live Project 写事务中读取连接、同步开关、数据库时间和到期提示，按访问重查、完整轮询、PR 提示的优先级选择工作。连接与同步均开启才可领取。领取使用独立 token 和运行 generation，有效期为五分钟。每次实际 HTTP 请求（包括认证、重试和重定向）前及每个最多 25 条的发布批次后，在短事务中验证并续持同一领取。单次数据库操作和 HTTP 请求分别以 15 秒为上限，完整轮次没有固定总期限。续持失败或结果未知立即停止；首次领取结果未知仅在只读 snapshot 确认同步仍开启且同一 token 和 generation 有效后继续。发布及完成结果未知不会重放，也不会声称完整成功。

完整轮询先验证安装对稳定仓库身份和 PR 的访问，再逐页读取所有 open PR。每批发布标记当前轮次；遍历结束后，对本地未见的 active 编号逐项读取当前事实。未出现本身不改变状态。只有全部页面与缺席项确认成功后才更新完整成功时间，并使用完成时的当前轮询间隔安排下一轮。GitHub 的分页不是原子快照，后续轮询和事件继续收敛。

提示工作每次最多处理 100 项；长轮询每页最多处理一项。执行器读取当前 PR，发布和按原 request ID 确认在同一事务内完成；读取期间新提示不会被旧确认删除。未曾保存且已关闭的历史 PR 不新建。Webhook 与轮询各自记录尝试、成功及错误，只有提示集合排空后才清除 webhook 错误。

## 失败与恢复

临时失败保留数据并在 30 秒后重试；限流等待取该时间与 GitHub 恢复时间中的较晚者。单项 404 不代表关闭或撤权，执行器复核仓库和安装访问。确认暂停或仓库权限不可用后按配置间隔重查；确认安装删除或 App 身份改变需要重新连接。重新获得原绑定访问后立即安排完整核对。所有发布仍由同步开关、原 token、generation、有效期限及 live Project 约束，关闭同步、断开、撤权信号和接管阻止迟到响应。关闭提交后旧代次不能续租或发布；已发送或已越过检查点的远端请求可能完成，关闭回执不表示所有实例的请求已经退出。重新开启产生新代次并完整核对。

远端和数据库调用不跨事务，错误保留原因链；日志携带 Project、领取、代次、安装与仓库身份以及处理阶段和提示来源，不记录凭据或 PR 正文。数据库协调及保留模型见[存储设计](github-pr-storage.md)，远端认证和协议见 [GitHub App 远端读取](github-app-remote.md)。
