# 单 Project GitHub 同步执行器

`service/github.AppExecutor` 通过 App-aware 工作事务执行单个 Project 的同步。[连接与运行时](github-connection-runtime.md)负责调度扫描、HTTP 管理入口和服务启停；授权与生命周期见[独立 App 执行](github-app-execution.md)。

## 领取与发布

领取在 live Project 写事务中读取连接、同步开关、数据库时间和到期提示，按访问重查、完整轮询、PR 提示的优先级选择工作。连接与同步均开启才可领取。领取使用独立 token 和运行 generation，有效期为五分钟。每次实际 HTTP 请求（包括认证、重试和重定向）前及每个最多 25 条的发布批次后，在短事务中验证并续持同一领取。单次数据库操作和 HTTP 请求分别以 15 秒为上限，完整轮次没有固定总期限。

续持失败或结果未知立即停止。首次领取结果未知时停止该轮并等待领取到期。发布及完成结果未知不会重放，也不会声称完整成功。

完整轮询先验证安装对稳定仓库身份和 PR 的访问。每轮从全状态列表头按创建时间倒序发现，每页 20 条、最多 10 页；自然结束和第 10 页主动截断均可继续。每轮按仓库身份与编号聚合重复摘要，未知的适用候选按编号读取详情，明确在所有覆盖期间之外结束的未知记录无需读取详情。列表不保存发现位置，下一轮重新从头读取；未返回或超出范围的未知编号不构成补录保证。随后继续完整遍历 open PR，并对本地未见的 active 编号逐项读取当前事实。未知 open 和已保存终态的重开先读取详情确认，未出现本身不改变状态。只有发现、open 遍历与缺席项确认全部成功后才更新完整成功时间，并使用完成时的当前轮询间隔安排下一轮。GitHub 的分页不是原子快照，后续轮询和事件继续收敛。

提示工作每次最多处理 100 项；长轮询在全状态发现页、open 页和详情观测发布后的有界位置最多处理一项到期提示，再继续轮询。详情读取和对应发布之间不插入提示。轮询期间的提示若发布 open 观测，标记为本轮已见，避免新增提示不断扩展缺席项集合；独立提示不使用轮询标记。执行器读取当前 PR，发布和按原 request ID 确认在同一事务内完成；读取期间新提示不会被旧确认删除。首次发布未知终态时，当前终态时间必须属于该 Project 与仓库的覆盖期间；已有记录继续按当前观测更新。详情与摘要有实质矛盾时复核，不能确认则本轮失败。同秒的可逆状态冲突须读取并复核当前详情，发布时检查读取期间已保存事实未变；已确认合并不可回退。Webhook 与轮询各自记录尝试、成功及错误，只有提示集合排空后才清除 webhook 错误。普通提示读取失败逐项重排，不阻止轮询继续；限流使轮询失败并按原规则退避，领取失效及事务失败或结果未知立即停止。

## 失败与恢复

临时失败保留数据并在 30 秒后重试；限流等待取该时间与 GitHub 恢复时间中的较晚者。单项 404 不代表关闭或撤权，执行器复核仓库和安装访问。确认暂停或仓库权限不可用后按配置间隔重查；确认安装删除需要重新连接。重新获得原绑定访问后立即安排完整核对。

所有发布由同步开关、原 token、generation、有效期限、live Project 和捕获的 App、凭据、grant、owner Team 与 ownership version 约束。关闭同步、断开、撤权信号和接管阻止迟到响应。关闭提交后旧代次不能续租或发布；已发送或已越过检查点的远端请求可能完成，关闭回执不表示所有实例的请求已经退出。重新开启产生新代次并完整核对。

远端和数据库调用不跨事务，错误保留原因链。日志携带 Project、领取、代次、安装与仓库身份、处理阶段和提示来源；独立 App 工作另带授权身份，不记录凭据或 PR 正文。数据库协调及保留模型见[存储设计](github-pr-storage.md)，远端认证和协议见[GitHub App 远端读取](github-app-remote.md)。
