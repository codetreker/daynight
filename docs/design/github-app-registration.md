# 独立 GitHub App 登记

独立 App 使用客户端生成的本地 UUID 标识，外部 GitHub App ID 在活资源中全局唯一。登记先用提交的私钥向固定 GitHub origin 证明 App 身份，再以单个事务插入 App 和首位管理员；证明期间不持有数据库锁。重复外部 ID 不授予已有 App 的管理权，本地 UUID 永久占用。

App 公开元数据与凭据分离。当前管理员才能读取元数据；列表在分页前按当前管理员过滤，并按创建时间和 UUID 排序。管理员、有效 Team 授权和连接项目数量从实际存储计数。读取不返回私钥、Webhook secret 或其摘要；Webhook URL 使用可信公开 origin 构造，不表示 Webhook 已验证。

迁移 `076_github_apps.sql` 建立管理员关系和独立 membership sequence、邀请及授权墓碑，并为项目连接准备授权字段。删除后的 App 和授权身份不能复用；活外部 ID 或 App/Team 授权的唯一性由部分索引保证。[管理员与邀请](github-app-administration.md) 拥有管理员读取、精确移除和邀请生命周期的机制；[Team 授权与影响预览](github-app-team-grants.md) 拥有使用授权和撤权组件；[配置与删除](github-app-configuration.md) 拥有凭据替换和资源删除机制；[项目连接](github-app-project-connection.md) 拥有 Team 权限、远端证明及专用项目事务。服务公开独立 App 登记、配置、管理员、邀请和授权接口。

登记的 45 秒预算覆盖输入、GitHub 请求和提交；本地读取使用 15 秒预算。事务返回 committed、not_committed 或 unknown，未知结果不得自动重放。客户端可使用原 UUID 查询当前可见元数据，但同值读取不能证明未知秘密写入已提交。

## 管理工作区

全局 GitHub Apps 工作区列出当前账号管理的资源，按本地 UUID 打开接入设置。登记时预生成 UUID，并要求完整凭据。配置页分别展示服务内名称、已验证的 GitHub 身份和稳定 Webhook URL。名称、私钥和 Webhook secret 各有独立的修改入口和弹窗；每次提交只携带当前字段、App 配置版本和当前账号身份。私钥使用多行输入，Webhook secret 使用密码输入；既有秘密不回显，空凭据不能提交。Webhook secret 弹窗展示稳定 URL 并提醒管理员配置 GitHub；私钥证明不代表 Webhook 已验证。服务端凭据证明及版本规则由[配置与删除](github-app-configuration.md)拥有。

编辑弹窗共享 App 的操作保护和身份准入生命周期。取消、Escape 或确认成功清理敏感草稿，提交期间不允许取消或重复提交；明确拒绝保留输入以供修正。版本冲突保留草稿，要求管理员核对当前状态后明确决定，后台读取不会自动使用新版本重发旧草稿。结果未知时保留原 App 和操作上下文并提供核对入口，即使关闭弹窗仍可见提示；核对并重新决定之前，其他配置入口不能绕过该保护。当前元数据相等不能证明秘密写入成功。

临时身份准入阻塞或恢复核对期间保留仍获授权的弹窗、草稿、焦点和选择范围，同时禁止新请求；账号替换、明确管理员失权或资源不可用时清理敏感输入和旧权限视图。后台读取、导航和迟到响应受原 App 与身份隔离。弹窗将焦点带入当前输入、限制在弹窗内，并在取消或成功关闭后返回原入口。

删除前显示获授权 Team 的连接汇总，以及按当前 Project 读取权限过滤的项目详情；未授权项目只计入隐藏数量。项目详情逐页替换，发布前以有限并发重新核对每项的 Project 读取权限，并检查隐藏数量；读取相互独立，不构成权限的原子快照。确认使用预览版本与影响版本。明确拒绝保留草稿，冲突要求重新核对并决定；结果未知不自动重放。
