# 助手任务经验沉淀设计

[规格](../spec/assistant-task-learning.md)拥有结果记录、复盘、附录验证、相关经验和能力指标的必需行为。本文说明存储与机制。助手任务的通用存储、事务与分层见[助手任务服务端](assistant-task.md)，Worker 的事件通知见 [Worker Bot 执行层](worker-bot-runtime.md#通知与定时事件)。

## 存储

新增迁移遵循助手任务表的约定：每行带 `owner_user_id`，DAO 查询带 owner 条件，不新增外键或 CHECK，并同步 `schema/current.sql`。

| 表或列 | 持久职责 |
| --- | --- |
| `assistant_task_records` 新增列 | 结果取值与被评价的 `action` 记录 ID；既有行为空 |
| `assistant_tasks` 新增列 | 上次复盘时间 |
| `assistant_task_appendix` 新增列 | 适用范围（项目 ID、事件类型、事项类别）、成功与失败验证计数、最近验证时间 |
| `assistant_task_appendix_validations` | `(appendix_id, outcome_record_id)` 唯一的验证登记 |
| `assistant_task_items` 新增列 | 本次打开时间与最近关闭时间；既有行为空 |
| `assistant_task_item_closures` | 只追加的关闭登记：事项、episode、本次打开时间（可空）与关闭时间，服务能力指标的时长计算 |

## 结果记录

`outcome` 加入 Bot 工作记录类型的显式枚举。core 在任务锁内读取被引用的记录，校验其属于同一任务且类型为 `action`。结果取值与动作引用只在 `outcome` 记录中进入请求指纹，因此既有记录的重放指纹不变。DAO 的插入、读取与分页映射新列。

## 复盘事件

`retrospective` 加入系统事件类型的显式枚举，不点亮关注，Bot 不能通过 `AddEvent` 创建。事项复盘在事项更新事务中生成：当更新把状态从 `open` 改为 `closed` 时，同一事务写入复盘事件，目标为当前负责 Bot。

周期复盘复用问答超时的无调度器模式：事件拉取在所属任务锁内读取上次复盘时间与其后最新结果记录的时间；满足“距上次复盘至少 7 天且其后有结果记录”且任务 active 时，写入复盘事件并更新上次复盘时间。上次复盘时间为空时，以任务创建时间为起点。

## 附录验证与相关经验

附录范围由 core 校验：项目 ID 为规范 UUID，事件类型属于已知类型，类别为非空的有界文本，每个集合有数量上限。验证操作由负责 Bot 引用一条 `outcome` 记录提交；core 校验记录属于同一任务、结果不是 `inconclusive`。DAO 以验证登记表的唯一约束防止重复计数，并在同一事务中更新计数与最近验证时间。

相关经验查询在数据库中计算匹配程度：每个声明的维度与查询条件相符计一分，未声明的维度不计分也不排除，声明但不相符的附录被排除。结果按分数、最近验证时间和 ID 降序，最多 5 项。Worker 在渲染事件通知时按通知涉及的维度调用该查询，每项摘要限定为 1 KiB 的 UTF-8 安全预览。

## 能力指标

事项写入在任务锁内比较新旧状态：以 `open` 创建或从 `closed` 变为 `open` 时，以数据库时间写入本次打开时间；从 `open` 变为 `closed` 时，写入最近关闭时间，并在同一事务中追加一条关闭登记，复制本次打开时间。其他更新保留两个时间。迁移不回填既有事项，因为现有数据只有创建时间和最后更新时间，无法证明真实的打开时刻；这些事项此后的关闭登记打开时间为空。

指标查询在单个只读快照中聚合最近 30 天的记录、事件与关闭登记，不新增物化表。平均解决时长只使用打开时间非空的关闭登记，另行返回打开时间为空的关闭次数。时间窗以数据库时间计算，响应返回 `observedAt` 与窗口起止时间。

## 验证责任

- **core 单测**：结果记录、复盘条件、附录范围与验证规则的判定矩阵。
- **PostgreSQL 测试**：使用隔离实例，验证新列往返与旧行兼容、迁移、状态转换时间与关闭登记、事项关闭与复盘事件的原子性、周期复盘的并发拉取只生成一个事件、验证登记的唯一性与计数、相关经验排序和指标聚合。
- **HTTP 与 CLI 测试**：新字段的解析与错误映射。
- **Worker 测试**：使用受控响应验证相关经验摘要的渲染与字节上限。
