# API 输入与资源计量设计

## 职责

[候选限额规范](../spec/daynight-api-input-limits.md)定义单位和数值。各 core 领域拥有自己的常量和纯候选检查；`internal/core/model/taskproperty` 保留结构 `NormalizeValue`，独立准入检查每个规范化值。读取既有数据不因候选额度改变。Task 和 Step 共用文字策略，原有集合 codec 继续拥有 Steps 与 Thread 的编码额度。

`internal/core/inputpolicy` 以版本和稳定标识列出候选领域限额，供存量检查识别规则。类型化容量失败携带字段、实际值、上限和单位，不保存输入。预算编码在首个超额字节停止时，报告已观察下界并明确标识，不能将它当作完整编码长度。结构错误及原有权限判断仍由各自所有者处理。

协议投影与编码需要由准入计量和实际输出共享，避免 JSON 转义、外壳、版本表示或换行产生偏差。预算写入必须在超限时明确失败；属性只计规范化 JSON 值。协议层不依赖 HTTP handler 或数据库。上游规范化 Profile 包含 identity ID 和落库字段；`/me` 响应使用本地 User ID 和 personalTeam，采用独立投影和含换行的计量，不能混用两者的外壳。

## 启用边界

纯策略本身不接入在线读写、文件 I/O 或数据库事务。存量检查必须在受控快照中使用相同策略，对无法在检查预算内判定的值报告不确定，不能报告合规。在线接线前处理存量超限并确保所有有效写入口使用同一准入。完整目录未新增分页，其物化和历史增长风险保留；最终输出额度不构成全服务峰值内存保证。

离线检查以字段长度和有界投影驱动逐项 visitor，仅对可完整读取的候选调用领域规范化及生产编码；文件通过对应命名空间的只读 stat 检查。JSONL 逐条输出并预留终止摘要，超过工具预算时保留不完整结论。报告以源码、策略和规范摘要、数据库关系身份、存储根和快照时间绑定观察范围。启用复核独立读取当前身份并比较报告和静止窗口；该比较依赖可信报告保管及操作方确认 writer 持续停止，不能认证报告内容或自行建立隔离。
