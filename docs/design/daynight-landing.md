# 公开产品入口设计

[产品介绍要求](../spec/daynight-landing.md)拥有 LP1–LP9 的可观察结果。
本设计拥有公开页面、产品入口与本地演示的组合方式；
[鉴权设计](daynight-auth.md)继续拥有身份、私有请求与业务连续性，
[语言设计](daynight-web-i18n.md)拥有语言运行时。

## 路由与生命周期

生产入口在常驻 `LocaleProvider` 下挂载响应地址变化的 `Application`。
应用按当前 pathname 选择公开首页、公开指南或 `AuthenticatedApp`：

```text
LocaleProvider
└── Application
    ├── /          → LandingPage
    ├── /setup     → SetupGuideShell
    └── 其他页面   → AuthenticatedApp
        ├── /login
        ├── /projects
        └── 既有业务路径
```

地址读取与历史操作由 `app/` 的路由所有者提供，直接进入、应用内跳转和浏览器历史遵循
同一规则。`main.tsx` 只负责初始语言和 React 入口，不以一次性的 pathname 判断决定
整个文档生命周期。原生链接继续支持修饰键、新标签和文档导航。

`AuthenticatedApp` 保留请求代际、取消、任务缓存作用域、前台身份复核与屏障；这些状态
不迁移到公开页。公开页进入工作台后，私有应用重新执行权威身份读取。公开页的身份
提示不能准入私有数据，公开指南也不为显示导航而建立身份生命周期。

## 公开导航与页面

`features/landing/LandingPage.tsx` 拥有完整页面，`LandingDemo.tsx` 拥有本地演示，
`demo.ts` 拥有稳定示例身份与依赖，`useNavigationIdentity.ts` 拥有公开导航提示。
`styles/landing.css` 的选择器限制在
`.landing-page` 下，避免全局 `h1`、`.button` 或 `.brand` 规则改变工作台与登录页。
页面复现产品品牌、首屏价值说明、具体困扰、演示、个人与团队价值、上手和 FAQ。

公开导航使用一个可取消的只读身份请求更新登录/工作台入口。正文立即渲染，不等待该
请求。导航状态区分 unknown、anonymous、authenticated 与 error；unknown/error 提供
中性的登录/工作台入口，错误另有本地化状态说明与工作台链接，不被当作匿名身份。该读取不创建缓存
作用域、不列出项目、不启动任务同步，离开页面时取消自己的请求。

首屏及末尾主行动定位 `#demo`，演示后的上手动作使用 `/setup`。登录与已有用户的工作台
导航分别进入 `/login` 与 `/projects`。全部身份变更和登录由真实认证组件及服务承担，
生产组件没有原型工具条或模拟认证分支。

## 本地演示模型

示例数据只包含展示所需的稳定任务身份、执行状态、前置条件和材料身份。它不复用服务端
任务 DTO，因此不需要伪造项目版本、时间、水位或授权字段。任务就绪与阻塞由状态及前置
关系推导，文案目录只翻译展示内容。

演示组件保存当前场景、任务、文档和记录身份；语言不作为组件 key 或状态初值依赖。
场景切换维护标签与面板关系，方向键操作同步焦点与选中状态。依赖按钮选中前置任务，
让“邀请邮件等待邀请接口”可被直接检查。文档和交付内容使用 JSX 渲染，避免把产品文案
作为任意 HTML 注入。

“完成依据”是明确标记的后续完成示例，和当前执行中的任务快照分离。全部操作为本地
阅读和选择，不请求业务 API，不写入真实任务。常见问题采用具有原生键盘语义的展开控件。

## 登录目标与公开切换

`/login` 延续 `returnPath` 参数。客户端解析实际支持的站内目标；未提供目标时选择
`/projects`，非法目标显示错误和可恢复入口。认证应用将普通匿名业务地址替换为独立登录
地址，并在成功或已有会话时替换到目标，避免历史中的登录循环。

服务端 `StartLogin` 保存已验证目标，无目标默认 `/projects`，拒绝 `/login` 和实际
callback 的循环目标。已绑定并消费的 callback 失败后清除绑定 Cookie，303 到
`/login?authError=login_failed`，并为已知事务保留有效 `returnPath`。即使身份领取成功后
建立本地 session 失败，也保留该已知目标。错误和原始凭据不进入公开 URL。

邀请生命周期依据有效业务目标识别，因此 `/login?returnPath=/invitations` 仍属于原
邀请。fragment 在身份请求前捕获并从地址移除，凭据只留在既有 tab 内临时状态，不放入
回跳参数或提供方 URL。主动离开邀请到首页或指南时，应用入口负责清理，不能依赖已经
卸载的认证组件观察新路由；清理失败保持可见。邀请结束和账号切换沿用原有授权要求。

设备授权保留 `user_code` 和原始目标，普通退出与邀请/设备的切换账号使用不同的导航
意图。退出失败不卸载错误与重试入口。私有内容在身份变化时同步撤回，旧请求不能在
公开/私有切换后发布。这些连续性是入口调整的必要保证，细节见[鉴权设计](daynight-auth.md)。

## 语言与分享信息

`messages.landing` 的类型契约与 `en`、`zh-CN` 目录拥有全部固定推广文案、示例材料和
可访问标签。复用 `LanguageSelector` 和已有偏好保存/失败机制；数据身份与语言无关，
换语言不会重置演示选择或启动业务操作。

原始 `index.html` 提供默认英文标题、description、Open Graph 标题、说明、类型和站点名。
公开页按当前目录更新文档语言、标题与对应 meta 内容。沿用 Vite 构建、资产发布校验和
Go embed；元数据不引入 `src`/`href` 资产引用，也不改变这些引用的严格路径检查。
这里提供默认分享信息和客户端本地化，不提供服务器端本地化正文或搜索收录保证。

## 服务与发布

`internal/server/ui.go` 为 `/`、`/login`、`/projects` 和既有页面注册相同 HTML handler，
保持 GET/HEAD、`no-store`、方法拒绝和请求日志。资源 API 继续独立鉴权。callback 配置
保留 `/login` 与 `/setup` 的根及后代命名空间，在路由注册前拒绝冲突。

官网、工作台、API、附件与 CLI 共用既有 origin，不改变 host-only Cookie、来源检查、
回调登记或 CLI 默认服务地址。是否采用独立官网部署或子域需要独立的连续性设计，不能
仅通过修改导航链接完成。

## 验证与边界

组件验证覆盖公开内容在身份等待/失败下可读、身份提示、全部演示选择、键盘、双语状态
保持和元数据。认证回归覆盖登录默认/指定/非法目标、任务文件与 query、失败回跳、邀请、
设备账号切换、退出失败、直接访问及历史。公开指南保留零 API 请求断言。

生产浏览器使用实际 Vite 产物和 Go 嵌入服务，检查四种宽度、长英文、可见焦点及完整
入口旅程。`pnpm web:typecheck`、`pnpm web:test`、`pnpm web:build` 和独立 PostgreSQL
下的 Go gate 保持既有覆盖与清理门槛。源绑定回执拥有实际运行结果，文档不把组件或
原型检查当作真实提供方、完整生产集成或访客转化证据。

服务器渲染、CMS、转化分析、计费和常驻 Worker 不属于公开介绍的必要机制。页面、演示
与认证各有独立职责，保持以后增加这些能力时可重新设计的边界。决策及实际替代方案见
[公开产品入口决策](../../.agents/notes/implemented/architecture/2026-10-26-public-product-entry.md)。
