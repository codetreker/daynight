# 项目设置工作空间设计

[需求](../spec/project-settings.md)定义五组、入口、路由和状态保留；各资源的业务规则仍由原 controller 和对应需求拥有。工作空间以用户和项目为稳定身份，组合执行与提醒、Worker 提示词、GitHub 集成、成员与邀请及项目管理，不复制它们的读写状态机。

## 路由与活动范围

`app/project-settings-route.ts` 定义分组选择和链接，`router.ts` 将旧 `/projects/{id}/members` 直接解析为同项目的 settings + members，不改写历史。URL 是阅读选择的权威来源；无效选择保留项目身份并显示恢复入口。原有 `authError` 处理继续适用。实际切换通过 `BrowserNavigation` 和已有离开屏障，同一选择不新增历史；链接保留原生新标签行为。

`ProjectSettingsPanel` 与 `ProjectAccessBoundary` 按用户和项目维持稳定 owner。工作空间区分同项目 `inWorkspace`、实际展示的 `workspaceActive` 和所选组的 `sectionActive`：切组不结束 `onRoute`，隐藏组停止交互并使用 `hidden` 和 `inert`。共享 Project GET 在活动工作空间读取权威名称、仓库和设置；失败不阻止提示词或成员等独立资源读取。名称不可用时使用项目 ID，不借用其他项目的名称。

成员组由同一工作空间内的 `MembersPanel` 拥有，接收 `onRoute`、活动状态及状态和保留回调。工作空间以 H1 展示项目名称及页面身份，成员组以 H2 展示分区标题和有权限时的邀请按钮，名册以 H3 标识自身区域。分区标题和按钮根据可用宽度换行；名称只在工作空间中展示。成员、邀请使用原 controller、权限与提交语义；成员变化和资源不可用时刷新项目目录。没有独立成员页面 host 或重复名称读取。设置、GitHub、仓库改址、转移和删除共用 `ProjectManagementGuard`；成员、邀请及个人提示词不加入该 guard。

## 导航可见性

`ProjectSettingsTabs` 在分组选择、重复选择、语言或活动项状态提示文本变化后调用同一定位函数，并用 `ResizeObserver` 观察导航容器及各链接的实际边框尺寸。前置链接变宽也会移动活动链接，因此观察范围包括非活动项。定位按容器与活动链接的实际边界计算，只在横向溢出的行布局中修正 `scrollLeft`，保留 4px 内边距和 1px 取整容差；超宽链接优先对齐起点。不使用平滑动画，不修改正文滚动或焦点。

观察器在卸载时断开。状态提示以文本值触发定位，控制器返回新对象但内容不变时不重新定位；手动滚动本身不触发尺寸观察。成员搜索浮层低于手机吸顶导航；向上展开时按重叠的导航和顶栏底边限制可用高度，使分组入口和搜索结果均可操作，并保留全局顶栏与抽屉的层级。导航 DOM 与原有链接处理保持稳定，避免后台读取或状态更新重置用户阅读与编辑上下文。[可见性决策](../../.agents/notes/implemented/bug-fix/2026-11-19-project-settings-navigation-visibility.md)记录观察范围与触发方式的取舍。

## 仓库改址

`management/project-repository` 拥有改址表单、确认展示和 controller，`api/project-repository.ts` 拥有预览与保存的协议验证。预览和回执校验请求项目、地址、分类、解绑事实和版本关系；两个版本及目标 GitHub ID 保持正十进制 int64 字符串，避免浮点精度损失。请求和响应沿用项目身份检查与 no-store。

controller 复用 `useOperation` 的主体准入、在途和结果发布保护。预览只读，保存前重新核对有效 Project admin、归属与当前编辑身份。仓库操作使用共同 guard 的 `repository` owner，同步阻止同一渲染周期中的重复提交。409 清除预览及未知身份的确认选项；未知写入保留原操作结果，读取 Project GET 仅显示当前事实。取消保留草稿，真实失权撤回私有地址和预览。

`projects/repository-changes.ts` 发布按账号和 Project ID 绑定的仓库变化通知。设置 controller 持有仓库刷新期间的草稿保留意图，使失败、取消及恢复读取沿用原草稿和并发版本；权威读取成功后按现有规则合并设置、暴露版本冲突，再结束该保留意图。真实失权仍撤回私有草稿。项目目录和项目页重读元数据；GitHub 组撤下原安装证明及状态，活动时重读，隐藏时在再次进入后读取。已挂载的 Worker 配置、项目选择与观察沿用各自读取及草稿合并路径刷新。通知不伪造焦点或权限变化，不改写 PR 阅读选择。可信回执和未知操作的只读核对均可刷新当前事实，后者始终保留未知结果。

## 项目归属布局

`ProjectOwnership` 在归属卡片正文内以可折行 Flex 行组合团队信息和原生转移按钮。信息按内容取宽并允许收缩和断行，按钮不收缩；无权限提示保持在该行下方。样式仅作用于归属正文，不改变权限门槛或对话框。

## 状态与结果所有权

各 controller 分别报告保留事实；工作空间派生 dirty、pending 和 needsAttention 摘要，摘要不决定权限或释放写锁。成员保留包含在途操作、待发布 grant 和 invitation、已展示的 secret、未完成核对的问题及按原 invitation ID 保存的撤销防重复事实。因此暂离工作空间不会卸载仍持有秘密或结果的成员 owner。真实主体或资源失效撤回私有内容和秘密，不把临时隐藏当作失效。

对话框沿用 suspended 机制：隐藏组释放焦点约束但保留原确认，返回时恢复。接受操作时捕获分组展示代际；可信回执、真实自我失权和其他业务安全后果仍按原用户、项目与操作身份处理，不因分组隐藏而等待。关闭确认、重置输入、焦点和自动导航还须匹配原确认、展示代际和位置，旧回执不能改变较新的交互。

工作空间在私有不可用区域之外提供稳定的成员结果 host。成员 controller 将既有无秘密的 grant 等待说明及可信结果发布到该 host，复用原回执和返回动作；结果绑定原用户及工作空间，显示不依赖当前选中成员组。真实失权后仅保留本人可信变更或已确认等待说明及返回入口，撤回标题、名册和秘密。结果发布不以随后 404 推断写入成功，亦不改变另一个项目的导航。

个人提示词导航保护将同项目设置分组、无效分组地址及旧成员地址视为同一工作空间；取消离开时先选择提示词组，再恢复有效焦点。各组阅读位置和编辑选区在工作空间内存中保存；历史恢复先应用可见组再恢复位置。活动工作空间临时使用 manual scroll restoration，离开后恢复浏览器设置。手机导航仅调整自身横向滚动，不覆盖正文位置。
