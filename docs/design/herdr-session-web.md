# Herdr Session 页面与只读回放

## 页面与身份

Task Session 使用共同任务入口，当前 web 执行保留 native timeline、composer 与原连接策略，herdr 执行由独立终端客户端承接。历史选择和附件中的 Session 记录读取同一任务历史 API；条目保存原 sessionId、claimId、executionGeneration、内容类型与 ready hash。历史读取不经过 current，不创建实时连接，也不持有输入接口。Session 选择保存在当前浏览器页签的用户/项目/任务范围内，刷新和重新领取任务不会把已选择记录改投新执行；每次读取仍由服务端核验权限。

普通附件继续使用原文件树、上传和删除流程。受管 Session 记录在同一侧栏中独立于文件树展示。记录目录与确认空结果按用户、项目和任务持久缓存，打开或重新激活时复用合格缓存并后台重读首页；历史 API 没有目录版本合同，任务业务版本不决定目录是否新鲜。确认空目录在后台刷新期间继续隐藏，有记录时保留可读内容，内容变化后更新。首次未知状态提供加载提示；空 items 仍有 nextCursor 时不是完整空目录。读取失败不作为空结果保存，已有内容保持可读并提供重试，首次失败也有可恢复入口。缓存和响应必须通过共享身份及项目生命周期准入，旧 scope、撤权或过期请求不能重新发布内容。缓存只用于目录展示，不能授权实时连接、控制或归档正文。具体取舍见[记录目录缓存决策](../../.agents/notes/implemented/architecture/2026-11-05-session-records-cache.md)。

历史存在与归档 ready 是不同条件，pending、failed、unavailable 记录也保留入口。选中记录后使用原阅读区打开只读记录，不能借普通附件操作覆盖、删除或重命名权威归档。两类内容共用阅读区的可用高度，避免短窗口中的正文被额外记录区域挤空。普通附件预览在回放时保持挂载并隐藏、禁用交互，上传草稿与 iframe 状态保留；选择普通文件、上传成功或导航到附件时退出受管记录选择。

## 实时连接与人工输入

终端客户端的订阅由页签可见性、文档可见性、当前任务和访问权限共同决定。隐藏页签和离开页面关闭该浏览器的 channel；服务端撤销相同 browserClientId 的租约或尚未完成的取得控制请求。录制由 Worker 独立负责，不依赖浏览器是否订阅。

页面默认只读。取得控制、续约、释放、处置初始提交和恢复自动执行均通过严格 v2 请求，只有 Worker 确认状态才改变可用动作。文字粘贴与有限逻辑键使用原 Session、运行代次、connection/control epoch、段与终端绑定，不发送任意终端寻址或 resize。输入结果未知时保留原 operationId，只查询原操作，不重发原正文。浏览器写前保存不含输入正文的操作身份，刷新后恢复未知提示；用户明确核对后才允许新的人工操作，原回执仍保持未知。这项本地确认既不修改 Worker 的原结果，也不恢复自动执行。传输完成不代表 Agent 已受理。

运行隔离身份由 Session、claim、运行代次、connection epoch 和实际终端地址共同组成。`nativeSessionId` 是独立的单向补齐字段：相同运行身份内允许 `null` 补齐为已知值；已知值之后返回 `null` 的旧状态整条丢弃，另一非空身份则使客户端失效。首次状态读取、刷新和重新连接共用状态准入规则；重新连接仍等待 channel 确认后才允许控制。

同一运行身份内，control epoch 与 segment/frame 序号分别保持单调，身份补齐不能绕过任一检查。旧初始状态缺少 control 时，不能清除已经确认的控制状态。保留较新帧时同步合法补齐的原生身份元数据，避免画面与后续输入使用不同绑定。正常身份补齐保留未决操作、原截止时间和回执读取；真实运行、连接、终端地址或输入控制代次变化仍使原未决输入保持 unknown，并隔离迟到结果。

输入的 `leaseSeq` 在相同 leaseId/controlEpoch 下严格递增。原生身份补齐不会创建新租约，不能重置输入序号；只有租约身份变化才开启新的序号空间。

提交与后续回执查询共用从提交开始计算的 10 秒截止时间，pending 时主动检查也不延长它。超时中止请求并保留 unknown；即使底层传输没有响应取消，页面也会结束等待。unknown 后的显式回执检查使用新的 10 秒只读窗口，不重启原操作或自动重发。

回执查询的 404 可能表示操作尚未写入，不能单独证明 Session 已失效。客户端在同一读取窗口内核对原 sessionId 的状态；原 Session 可访问时保留 unknown 和人工核对入口，不经 current 重定向。原 Session 的实际访问拒绝仍关闭查看与控制能力。迟到结果必须同时匹配查询代次、原操作和当前执行绑定，不能覆盖新操作。

未知初始提交使用 `resolve_initial_assignment` 记录人工处置，仍保持 suspended。`resume_automation` 是另一项显式确认，要求用户已处理终端草稿；它不能夹带未知初始提交处置。确认绑定打开时的运行身份与 control epoch，未知结果确认还绑定原 operationId；提交时重新核对当前客户端状态。控制身份或原操作改变后必须重新确认，正常画面更新和原生身份补齐不取消同一上下文的确认。旧环境未公布相应动作时，页面不尝试替代控制。

## 归档验证与播放

v2 reader 对固定归档状态、finalizationId、原始文件字节的 hash/size 和严格 schema 进行验证，再核对项目、任务、原 claim、Session、最终运行代次、服务源和完整性。共享 decoder 校验每帧、索引、段、gap 和停止归属。任一不一致拒绝展示，不跳过坏帧。

v1 历史沿用原格式及服务端文件 hash 校验；浏览器核对固定状态的 hash/size、正文身份和内嵌资源完整性。v1 的 HTTP JSON 包装会重新编码正文，因此不将重建 JSON 的 hash 冒充上传原始字节的 hash。

实时与回放共用受限文本 renderer，内容只进入文本节点，样式来自经过校验的有限字段。时间轴按段序号累计单调时长，使用 bigint 避免序号或时长取整。每帧独立，可直接定位；段内 gap 和段间边界都是播放节点，自动播放停在缺口，只有明确继续才读取下一段。partial 始终显示。缩放和终端内横向滚动支持窄屏与长行，不把长内容扩展到整个页面。

## 验证边界

接口和客户端测试覆盖身份拒绝、权限、延迟响应、Worker 确认、未知输入以及不可变文件验证。播放器测试覆盖随机定位、段间与段内缺口、隐藏暂停和文本安全；现有 web Session 与附件回归继续执行。浏览器和跨层验证的具体 revision、环境及结果属于交付证据，模拟接口不代表原生 Provider 验收。
