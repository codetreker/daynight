# Webhook 私有管理模块

## 职责与组装

服务端 Webhook 管理模块处理 Personal User 和 shared Team 的 endpoint 配置、签名秘密和操作回执。`internal/server/webhook` 将认证后的请求映射到 `internal/service/webhook`，并可独立挂载；应用的公开路由不在此处注册。业务校验位于 `internal/core/webhook`，中立事务合同位于 `internal/core/store`，PostgreSQL 实现负责锁、配额和持久化。

创建时订阅必须为空；显式订阅和事件投递不由此模块提供。Personal owner 从主体派生；Team 的当前成员只能读取脱敏配置，本人原回执可读，当前管理员才能管理和读取秘密。每次读取均在同一数据库快照内重新检查凭据与成员关系。

## 写入与回执

操作身份由 owner 和客户端提供的 operation ID 确定。写事务先取得操作围栏，查询现有回执；新操作检查权限和时间，在来源锁、endpoint 锁及桶与 owner 账目锁下重新核验，再把效果和回执共同提交。回执保存规范化意图指纹、实际请求正文摘要、原时间及结果版本，不保存 URL 或秘密。匹配重放不重复效果；事务释放连接后，以新的授权快照读取回执和当前视图。提交结果未知时调用者必须使用原操作身份核对。

配置版本仅在真实变化时递增，目的地版本仅在目的地变化时递增。操作和配置使用持久配额，超限在效果提交前拒绝。删除清除配置密文和签名密钥，保留最小墓碑与有界回执。

## 可恢复秘密

密钥环指定不可变的 active master 和可用于恢复的旧 master。AES-256-GCM 密文绑定 master 标识及 owner、endpoint、用途和目的地版本或签名 key ID。真实配置变化以当前 master 重新封装存活密文；无变化不改写密文。签名秘密只通过独立授权接口读取；轮换最多保留一份当前 key 和一份有效重叠 key。
