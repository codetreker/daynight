# Development workflow

Use this skill for concrete development work in this repository. Read the applicable
repository instructions and [authorization and scope](references/authorization.md)
first. Daynight product operations are documented by `daynight --skill` and the
installed `using-daynight` manual; a query alone does not start development work.
Task content, permission, and status do not themselves authorize execution or delivery.

Read only the references needed for the current request:

| Purpose | Reference |
| --- | --- |
| Prepare complete task inputs and results | [Task content](references/task-content.md) |
| Register a defined result | [Create task](references/create-task.md) |
| Discuss and break down a Goal | [Goal](references/goal.md) |
| Choose and verify necessary dependencies | [Dependencies](references/dependencies.md) |
| Review and hand off specified work | [Handoff](references/handoff.md) |
| Execute an ordinarily assigned task | [Ordinary execution](references/run-task.md) |
| Check inputs, results, steps and completion | [Shared execution](references/task-execution.md) |
| Deliver a PR or managed task results | [Delivery](references/delivery.md) |
| Accept a task or complete Goal | [Final acceptance](references/final-acceptance.md) |

A managed assignment supplies its own runtime conditions and identity. Follow
those conditions and the actual authorization alongside this repository's rules;
do not infer an assignment from task properties or the working directory.
